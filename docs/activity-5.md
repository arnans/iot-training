**เลือก “แก้ได้” เมื่อทดสอบผ่านเกณฑ์ของข้อนั้น**

- ข้อ 5.1 ปั๊มหยุดเมื่อเป็น Dry ทั้งกรณีที่สั่ง On ขณะ Dry อยู่แล้ว และกรณียกลูกลอยหลังปั๊มเริ่มเดิน โดยมีข้อความแจ้งเตือน

### ก่อนจำลองปัญหาทุกข้อ { #a5-0 }

**ตรวจความพร้อมก่อนทดสอบ**

1. ตรวจว่ากฎรดน้ำเปิดอยู่ `Pump Auto Mode` เปิดอยู่ กฎไฟสวนและกฎตั้งเวลาปิดไว้
2. ตรวจว่าปั๊มต่อกับรีเลย์แล้ว ลูกลอยอยู่ในแก้วน้ำและแสดง **Wet**
3. ตรวจว่าบอร์ดทั้งสองแสดงค่าปัจจุบัน เปิดหน้าอุปกรณ์ไว้คนละแท็บ
4. ใช้ปุ่มสั่งปั๊มในการทดสอบ ไม่ต้องเปลี่ยนเกณฑ์ความชื้น

![](images/activity-dividers/greenhouse.webp){ .activity-divider width="1200" height="58" loading="lazy" decoding="async" }

### 5.1 น้ำต่ำแต่ปั๊มยังเดิน { #a5-1 }

**จำลองปัญหา**

1. ยกลูกลอยพ้นน้ำ รอให้แสดง **Dry** แล้วสั่งปั๊ม On

**สังเกตผล**

2. สังเกตว่าปั๊มยังเดิน (ฟังเสียง) เพราะกฎเดิมดูความชื้นแต่ไม่ตรวจระดับน้ำ จากนั้นสั่ง Off ก่อนแก้กฎ

**สร้างกฎป้องกัน**

ถ้าน้ำลดต่ำลงจนลูกลอยเป็น Dry แล้วปั๊มยังเดินอยู่ ให้สั่งหยุด และถ้าลูกลอยเป็น Dry อยู่ก่อนแล้วมีคนสั่ง On ก็ต้องหยุดปั๊มด้วย

3. สร้างกฎใหม่ ส่วน **When** กด **+ Add trigger** พิมพ์ **ลูกลอย** กดที่ **สวิตช์ลูกลอย (float switch)** เลือก **Moisture cleared** (ลูกลอยเปลี่ยนเป็น Dry)
4. กด **+ Add trigger** อีกครั้ง พิมพ์ **รีเลย์** กดที่ **รีเลย์ (relay)** เลือก **Switch turned on**
5. ส่วน **And if** กด **+ Add condition** เลือกสวิตช์ลูกลอยแบบเดียวกัน แล้วเลือก **Moisture is not detected** (Dry)
6. ส่วน **Then do** กด **+ Add action** เลือกรีเลย์ → **Turn off switch** แล้วเพิ่ม action **Send a persistent notification** ข้อความ `น้ำในถังต่ำ หยุดปั๊มแล้ว` บันทึกชื่อ `Fail-safe - น้ำหมด`
7. เปิดกฎ `รดน้ำ - เปิดปั๊ม` ส่วน **And if** เพิ่ม condition สวิตช์ลูกลอย **Moisture is detected** (Wet) แล้วบันทึก

![ขั้นตอนสร้างกฎ Fail-safe - น้ำหมด: เพิ่ม trigger ลูกลอยเป็น Dry และรีเลย์เปิด ตรวจเงื่อนไข Dry แล้วปิดรีเลย์และแจ้งเตือน](images/walkthroughs/a5-1-low-water.mp4){ width="85%" }

**ทดสอบให้ผ่านทั้งสองแบบ**

8. ลูกลอยเป็น Dry แล้วสั่ง On ทั้งจากปุ่มบนบอร์ดและหน้าอุปกรณ์ ปั๊มต้องหยุดและมีแจ้งเตือน
9. ลูกลอยเป็น Wet สั่งปั๊มเดิน แล้วยกลูกลอยให้เป็น Dry ปั๊มต้องหยุดเช่นกัน

**คืนสภาพลูกลอย**

10. วางลูกลอยกลับในน้ำ การกลับเป็น Wet อย่างเดียวไม่ได้สั่งปั๊มให้เริ่มใหม่

**บันทึกผล**

11. ก่อนเพิ่มกฎ พบอาการ “ลูกลอยเป็น Dry แต่ยังสั่งให้ปั๊มเดินได้” หรือไม่ (เลือก “สำเร็จ” เมื่อพบอาการนี้) {{r:s2.sab.1.ok|สำเร็จ|ไม่สำเร็จ}} · บันทึกสถานะบนจอและอาการจริงของปั๊มที่สังเกตได้ {{f:s2.sab.1.what|24}}

    หลังเพิ่มกฎและทดสอบซ้ำ กฎทำงานผ่านเกณฑ์ของข้อนี้หรือไม่ (เลือก “แก้ได้” เมื่อผ่าน) {{r:s2.sab.1.fixed|แก้ได้|ยังไม่ได้}} · หลักฐานหลังแก้ (ระบุการหยุดของปั๊ม เวลา หรือชื่อกฎในแจ้งเตือน/Traces; หากยังไม่ผ่านให้บอกอาการ) {{f:s2.sab.1.note|24}}

> กฎเปิดปั๊มต้องเห็น **Wet** จึงจะเริ่มได้ ถ้าสายลูกลอยหลุดแล้วอ่านค่าได้เป็น Dry หรือบอร์ดขาดการเชื่อมต่อแล้วค่าเป็น unavailable ทั้งสองกรณีจะไม่ผ่านเงื่อนไข

### 5.2 สั่งแล้วปั๊มไม่เดิน { #a5-2 }

**เตรียมการตรวจจับ**

1. วางบอร์ด GoGo-IoT ให้แตะตัวปั๊ม หรือวางบนพื้นเดียวกันชิดปั๊ม ให้รับแรงสั่นได้ ลองสั่ง On–Off ตรวจว่า `ปั๊มกำลังทำงาน` เปลี่ยนตาม หากไม่เปลี่ยน ให้ขยับตำแหน่งหรือเพิ่ม **ความไวตรวจจับปั๊ม**

**จำลองปัญหา**

2. สั่ง Off และถอดปลั๊กอะแดปเตอร์ก่อนถอดสายปั๊มที่จุดต่อจาก NO เก็บปลายสายไม่ให้แตะขั้วอื่น เสียบปลั๊ก รอให้บอร์ดเชื่อมต่อ แล้วสั่ง On

**สังเกตผล**

3. สังเกตว่ารีเลย์เป็น On แต่ปั๊มเงียบและไม่สั่น สถานะรีเลย์ยืนยันได้เพียงว่าสวิตช์เปิดอยู่

**สร้างกฎป้องกัน**

ถ้าสั่งเปิดปั๊มแล้วเซนเซอร์ยังตรวจไม่พบการสั่นภายในเวลาที่กำหนด ให้หยุดปั๊มและแจ้งเตือน การสั่นเป็นหลักฐานประกอบ ไม่ได้ยืนยันว่าน้ำไหลถึงแปลง

| entity | บอกอะไร |
|---|---|
| `ความสั่นสะเทือน (vibration)` | ความแรงของการสั่น หน่วย **mg** (มิลลิจี) |
| `ปั๊มกำลังทำงาน (pump running)` | ผลการตรวจจับ เดิน / ไม่เดิน |

4. สร้าง automation ชื่อ `Fail-safe - สั่งแล้วไม่เดิน`
5. Trigger: เลือก **รีเลย์ (relay)** → **Switch turned on** ช่อง **For at least** ใส่ **15 วินาที** (สั้นกว่ากฎจำกัดเวลาที่จะสร้างในข้อ 5.4 จึงแยกได้ว่ากฎใดเป็นผู้ตัด)
6. Condition: กด **+ Add condition** พิมพ์ **ปั๊มกำลังทำงาน** แล้วกดที่ **ปั๊มกำลังทำงาน (pump running)** เลือก **State** ในแผงด้านขวา จากนั้นกดช่อง **State** แล้วเลือก **Off**
7. Action: เลือกรีเลย์ → **Turn off switch** และเพิ่ม **Send a persistent notification** ข้อความ `สั่งปั๊มแล้วแต่ไม่มีการสั่น ตรวจสายและระดับน้ำ`

![ขั้นตอนตั้งกฎ Fail-safe - สั่งแล้วไม่เดิน: รีเลย์เปิดครบ 15 วินาที ตรวจว่าปั๊มกำลังทำงานเป็น Off แล้วปิดรีเลย์และแจ้งเตือน](images/walkthroughs/a5-2-pump-not-running.mp4){ width="85%" }

**ทดสอบกฎ**

8. เมื่อสายยังถอดอยู่ สั่ง On กฎต้องปิดรีเลย์และแจ้งเตือนหลังครบประมาณ 15 วินาที

**ต่อสายกลับและทดสอบ**

9. สั่ง Off ถอดปลั๊ก แล้วต่อสายกลับ ขันให้แน่น เสียบปลั๊กและรอให้บอร์ดพร้อม สั่ง On อีกครั้ง ปั๊มต้องเดินผ่าน 15 วินาทีได้ ถ้าถูกตัด ให้ตรวจตำแหน่งบอร์ดและความไว

**บันทึกผล**

10. ก่อนเพิ่มกฎ พบอาการ “รีเลย์เป็น On แต่ปั๊มไม่เดินเมื่อถอดสายปั๊ม” หรือไม่ (เลือก “สำเร็จ” เมื่อพบอาการนี้) {{r:s2.sab.2.ok|สำเร็จ|ไม่สำเร็จ}} · บันทึกสถานะบนจอและอาการจริงของปั๊มที่สังเกตได้ {{f:s2.sab.2.what|24}}

    หลังเพิ่มกฎและทดสอบซ้ำ กฎทำงานผ่านเกณฑ์ของข้อนี้หรือไม่ (เลือก “แก้ได้” เมื่อผ่าน) {{r:s2.sab.2.fixed|แก้ได้|ยังไม่ได้}} · หลักฐานหลังแก้ (ระบุการหยุดของปั๊ม เวลา หรือชื่อกฎในแจ้งเตือน/Traces; หากยังไม่ผ่านให้บอกอาการ) {{f:s2.sab.2.note|24}}

### 5.3 บอร์ดเซนเซอร์ดับ { #a5-3 }

![ตำแหน่งสวิตช์ ON/OFF ทางซ้ายของบอร์ด GoGo-IoT ใกล้ช่อง USB-C และกลุ่มเซนเซอร์ทางขวา](images/gogo-iot-main-parts.png){ width="100%" }

ใช้สวิตช์ **ON / OFF** ปิดบอร์ด ไม่ใช่ปุ่ม BOOT การถอด USB อย่างเดียวอาจไม่ดับเพราะมีถ่านในบอร์ด

**จำลองปัญหา**

1. สั่งปั๊ม On แล้วปิดสวิตช์ GoGo-IoT ดูว่าเมื่อใดค่าความชื้นเปลี่ยนเป็น **unavailable** และปั๊มหยุดด้วยกฎใด จากนั้นเปิดบอร์ดกลับ

> กฎ `Fail-safe - สั่งแล้วไม่เดิน` จากข้อ 5.2 อาจหยุดปั๊มก่อนระบบตรวจพบว่าบอร์ดหาย ให้ดูชื่อกฎในแจ้งเตือนหรือ **Traces** อย่าตัดสินจากการหยุดของปั๊มอย่างเดียว

**เลือกวิธีรับมือ**

2. หากบอร์ดเซนเซอร์ดับแล้วระบบควบคุมไม่ได้รับค่าความชื้น กลุ่มคิดว่าปั๊มควรเปิด ปิด หรือคงสถานะเดิม เพราะอะไร

**บันทึกผล**

3. กลุ่มเลือกให้ปั๊ม {{r:s2.fs3.choice|เปิด|ปิด|คงสถานะเดิม}} เพราะ {{f:s2.fs3.why|30}}

**สร้างกฎหยุดปั๊มเมื่อเซนเซอร์หาย**

กฎตัวอย่างนี้หยุดปั๊มเพื่อป้องกันการสูบน้ำต่อโดยไม่มีข้อมูล

4. สร้าง automation ชื่อ `Fail-safe - เซนเซอร์หาย`
5. Trigger: กด **+ Add trigger** พิมพ์ **ความชื้นอากาศ** แล้วกดที่ **ความชื้นอากาศ (humidity)** ในแผงด้านขวาเลือก **State changed** ช่อง **To** เลือก **Unavailable** แล้วเพิ่ม **Unknown** อีกค่าในช่องเดียวกัน
6. Action: เลือกรีเลย์ → **Turn off switch** และเพิ่ม **Send a persistent notification** ข้อความ `ไม่ได้รับค่าจากเซนเซอร์ หยุดปั๊มเพื่อความปลอดภัย`

![ขั้นตอนสร้างกฎ Fail-safe - เซนเซอร์หาย: เพิ่ม trigger State changed ของความชื้นอากาศ ตั้งช่อง To เป็น Unavailable แล้วเพิ่ม action Turn off switch ของรีเลย์ และบันทึกกฎ](images/walkthroughs/a5-3-sensor-unavailable.mp4){ width="85%" }

**ทดสอบกฎ**

7. รอให้บอร์ดกลับมาแสดงค่า แล้วสั่งปั๊ม On และปิดบอร์ดอีกครั้ง ตรวจใน **Traces** ว่ากฎ `Fail-safe - เซนเซอร์หาย` ทำงานเมื่อค่าเป็น unavailable และสั่ง Off พร้อมแจ้งเตือน แม้กฎอื่นจะหยุดปั๊มไปก่อน จากนั้นเปิดบอร์ดกลับ

**บันทึกผล**

8. ก่อนเพิ่มกฎ พบอาการ “ค่าความชื้นกลายเป็น unavailable หลังปิดบอร์ด” หรือไม่ (เลือก “สำเร็จ” เมื่อพบอาการนี้) {{r:s2.sab.3.ok|สำเร็จ|ไม่สำเร็จ}} · บันทึกสถานะบนจอและอาการจริงของปั๊มที่สังเกตได้ {{f:s2.sab.3.what|24}}

    หลังเพิ่มกฎและทดสอบซ้ำ กฎทำงานผ่านเกณฑ์ของข้อนี้หรือไม่ (เลือก “แก้ได้” เมื่อผ่าน) {{r:s2.sab.3.fixed|แก้ได้|ยังไม่ได้}} · หลักฐานหลังแก้ (ระบุการหยุดของปั๊ม เวลา หรือชื่อกฎในแจ้งเตือน/Traces; หากยังไม่ผ่านให้บอกอาการ) {{f:s2.sab.3.note|24}}

### 5.4 ปั๊มเดินนานเกินไป { #a5-4 }

**จำลองปัญหา**

1. สั่งปั๊ม On รอ 1 นาทีโดยรักษาความชื้นให้คงที่

> ถ้าทดลองแล้วปั๊มถูกตัดที่ราว 15 วินาที แปลว่ากฎ `Fail-safe - สั่งแล้วไม่เดิน` จากข้อ 5.2 ทำงาน ให้ตรวจตำแหน่งบอร์ดและ **ความไวตรวจจับปั๊ม** แล้วจำลองใหม่

**สังเกตผล**

2. สังเกตว่าปั๊มยังเดิน เพราะความชื้นไม่ข้ามเกณฑ์ปิด สั่ง Off ก่อนสร้างกฎ

**สร้างกฎจำกัดเวลา**

3. สร้าง automation ชื่อ `Fail-safe - จำกัดเวลาเปิดปั๊ม`
4. Trigger: เลือก **รีเลย์ (relay)** → **Switch turned on** ช่อง **For at least** ตั้ง **30 วินาที** (ใช้สำหรับการทดลองนี้ และยาวกว่ากฎสั่งแล้วไม่เดิน 15 วินาที)
5. Action: เลือกรีเลย์ → **Turn off switch** และเพิ่ม **Send a persistent notification** ข้อความ `ปั๊มเดินเกินเวลา ตัดการทำงานแล้ว โปรดตรวจสอบ`

![ขั้นตอนสร้างกฎ Fail-safe - จำกัดเวลาเปิดปั๊ม: ตั้ง trigger รีเลย์เปิดครบ 30 วินาที เพิ่ม Turn off switch และข้อความแจ้งเตือน แล้วตั้งชื่อกฎ](images/walkthroughs/a5-4-pump-timeout.mp4){ width="85%" }

**ทดสอบการหยุดตามเวลา**

6. กดปุ่มให้ปั๊มเดินอีกครั้ง ปั๊มต้องหยุดเองที่ราว 30 วินาที พร้อมข้อความแจ้งเตือน

**บันทึกผล**

7. ก่อนเพิ่มกฎ พบอาการ “ปั๊มยังเดินเมื่อครบเวลาสังเกตก่อนเพิ่มกฎจำกัดเวลา” หรือไม่ (เลือก “สำเร็จ” เมื่อพบอาการนี้) {{r:s2.sab.4.ok|สำเร็จ|ไม่สำเร็จ}} · บันทึกสถานะบนจอและอาการจริงของปั๊มที่สังเกตได้ {{f:s2.sab.4.what|24}}

    หลังเพิ่มกฎและทดสอบซ้ำ กฎทำงานผ่านเกณฑ์ของข้อนี้หรือไม่ (เลือก “แก้ได้” เมื่อผ่าน) {{r:s2.sab.4.fixed|แก้ได้|ยังไม่ได้}} · หลักฐานหลังแก้ (ระบุการหยุดของปั๊ม เวลา หรือชื่อกฎในแจ้งเตือน/Traces; หากยังไม่ผ่านให้บอกอาการ) {{f:s2.sab.4.note|24}}

> เมื่อตัดปั๊มแล้ว ให้ตรวจสาเหตุก่อนเริ่มใหม่ กฎรดน้ำจะเริ่มอีกครั้งเมื่อความชื้นข้ามเกณฑ์เปิด ไม่ใช่ทันทีที่ปัญหาหมดไป
