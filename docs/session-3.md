# ช่วงที่ 3 — โครงสร้างระบบ IoT: การสื่อสาร คลาวด์ แดชบอร์ด และการออกแบบระบบ

**เปิดกล่องที่ยังไม่ได้เปิด แล้วใช้เวลาครึ่งหลังออกแบบระบบสำหรับฟาร์มของเรา**

สองช่วงที่ผ่านมาเราใช้งานบอร์ดร่วมกับ Home Assistant ได้แล้ว ครึ่งแรกของช่วงนี้จะเปิดดูว่าข้อมูลส่งถึงกันได้อย่างไร อุปกรณ์ในแปลงที่ไม่มีไฟฟ้าใช้พลังงานจากที่ใด อ่านข้อมูลที่ระบบของเราบันทึกไว้ตั้งแต่ช่วงที่ 2 แล้วสร้างแดชบอร์ดสำหรับผู้ใช้จริง ครึ่งหลังทั้งหมดเป็นเวลาออกแบบระบบสำหรับฟาร์ม โดยพิจารณาทั้งอุปกรณ์ การสื่อสาร พลังงาน และงบประมาณ แล้วแลกเปลี่ยนกับทีมที่จับคู่กัน

> **เมื่อจบช่วงนี้** ทีมจะอ่านกราฟข้อมูลของตัวเองและบอกได้ว่าแต่ละช่วงเกิดจากอะไร มีแดชบอร์ดที่ผู้อื่นใช้งานได้ อธิบายได้ว่าจะดูข้อมูลฟาร์มจากนอกพื้นที่อย่างไร และมีแบบร่างระบบสำหรับฟาร์มหนึ่งชุดที่ผ่านการแลกเปลี่ยนกับอีกทีมแล้ว

## บอร์ดกับ Home Assistant ติดต่อกันอย่างไร

**20 นาที บรรยายและสาธิต**

**อุปกรณ์ที่ใช้** ไฟล์ตั้งค่า ESPHome ที่แจก (ดูส่วนบนของไฟล์)

![ไฟล์ YAML ของ ESPHome ส่วน esphome, wifi และ api เน้น name_add_mac_suffix, ssid และบล็อก api ที่ไม่มีบรรทัดเข้ารหัส](images/placeholder.png){ width="55%" }

เปิดไฟล์ตั้งค่าแล้วหาสามรายการ ได้แก่ **ssid** ซึ่งระบุชื่อ WiFi ที่บอร์ดใช้, **name_add_mac_suffix** ซึ่งทำให้ชื่อบอร์ดไม่ซ้ำกัน และ **api** ซึ่งกำหนดการเชื่อมต่อกับ Home Assistant รวมถึงการเข้ารหัส ทั้งบอร์ด GoGo-IoT และบอร์ดรีเลย์มีการตั้งค่าส่วนนี้

> ในไฟล์นี้ **ไม่ได้กำหนดหมายเลข IP ไว้** เพราะบอร์ดขอหมายเลขจากเราเตอร์เมื่อเชื่อมต่อ แล้วประกาศชื่อของตนเองบนเครือข่าย Home Assistant จึงค้นพบบอร์ดและแสดงรายการให้เลือกได้ โดยเราไม่ต้องกรอก IP เอง

จากนั้นไปที่ **Settings → Devices & services → ESPHome** กดที่อุปกรณ์ จะเห็น entity ชื่อ **หมายเลข IP** บอกว่าเราเตอร์ให้ IP อะไรกับบอร์ดตัวนี้ ลองเทียบกับของทีมข้าง ๆ เปิดแท็บใหม่ พิมพ์ `http://` ตามด้วย IP นั้น จะเจอหน้าเว็บของบอร์ดเอง เหมือนที่เราใช้ในช่วงที่ 1 ก่อนเพิ่มบอร์ดเข้า Home Assistant **บอร์ดตัวนี้เป็นเว็บเซิร์ฟเวอร์** อยู่ในเครือข่ายเดียวกับเรา และ Home Assistant ก็คุยกับบอร์ดผ่านเครือข่ายเดียวกันนี้เอง

> ในช่วงที่ 2 เมื่อทีมที่จับคู่กันปิด WiFi บนแล็ปท็อป บอร์ดทั้งสองและ Home Assistant ยังทำงานอยู่ แต่ติดต่อกันไม่ได้ เพราะการเชื่อมต่อเครือข่ายถูกตัด

### เลือกวิธีสื่อสารให้เหมาะกับฟาร์ม

ก่อนเลือกวิธีสื่อสาร ให้พิจารณา **ระยะทาง · การใช้พลังงาน · ปริมาณข้อมูล · ค่าใช้จ่าย** วิธีที่เหมาะกับฟาร์มหนึ่งอาจไม่เหมาะกับอีกฟาร์ม ตารางนี้เป็นข้อมูลอ้างอิงสำหรับใช้ในกิจกรรมที่ 8 ไม่ต้องจดตาม

| เทคโนโลยี | ระยะทาง | ใช้พลังงาน | ปริมาณข้อมูล | ค่าใช้จ่าย | ข้อจำกัดที่ต้องรู้ |
|--|---------|------------|--------------|------------|------------------|
| **WiFi** (ที่เราใช้) | ใกล้ ราว 30–50 เมตรจากเราเตอร์ในที่โล่ง | สูง | มาก | ต่ำ ถ้ามีเราเตอร์อยู่แล้ว | ต้องมีเราเตอร์และไฟฟ้าถึงจุดติดตั้ง ไม่เหมาะกับอุปกรณ์ที่ใช้ถ่านอย่างเดียว |
| **ESP-NOW** | ราว 100–200 เมตรในที่โล่ง บอร์ดถึงบอร์ด | ปานกลาง | น้อย | ต่ำมาก ไม่ต้องมีเราเตอร์ | คุยกันได้เฉพาะบอร์ดตระกูล ESP32 ต้องมีบอร์ดหนึ่งตัวต่อ WiFi ไปหา Home Assistant |
| **Zigbee** | ราว 10–30 เมตรต่อช่วง แต่ส่งต่อกันเป็นทอด ๆ (mesh) ผ่านอุปกรณ์ที่เสียบไฟ | ต่ำ เซนเซอร์ใช้ถ่านได้เป็นปี | น้อย | ปานกลาง ต้องมีตัวรับ (coordinator) | อุปกรณ์สำเร็จรูปมีมาก แต่แบบกลางแจ้งมีน้อย ข้ามแปลงโล่งไกล ๆ ไม่ได้ ชุดสาธิตในห้องแสดงผลงานใช้เทคโนโลยีนี้ |
| **LoRa / LoRaWAN** | ไกล 1–10 กิโลเมตร | ต่ำมาก | น้อยมาก ส่งค่าเป็นครั้ง ๆ | ปานกลาง โมดูลและเกตเวย์ | ส่งข้อมูลได้น้อยและไม่ถี่ ไม่เหมาะกับการสั่งงานที่ต้องตอบทันที ต้องมีเกตเวย์ของเราเองหรือของผู้ให้บริการ |
| **Cellular / NB-IoT** | ทุกที่ที่มีสัญญาณมือถือ | ปานกลางถึงสูง | ปานกลาง | ปานกลาง และค่าซิมรายเดือน | ขึ้นกับสัญญาณ ณ จุดติดตั้ง มีค่าใช้จ่ายต่อเนื่อง |
| **RS-485** (สาย) | ไกลตามสาย ถึงราว 1 กิโลเมตร | ต่ำ | ปานกลาง | สายราคาถูก แต่มีค่าเดินสาย | ต้องเดินสาย ใช้กับเซนเซอร์อุตสาหกรรมที่มีพอร์ตนี้ เช่น ความชื้นดินหรือ EC แบบมืออาชีพ |

> ตัวเลขในตารางเป็นแนวโน้มทั่วไป ระยะจริงขึ้นกับสิ่งกีดขวาง เสาอากาศ และรุ่นอุปกรณ์ ให้ใช้เป็นจุดเริ่มต้นแล้วทดสอบในพื้นที่จริงก่อนซื้อจำนวนมาก

ผู้สอนยกตัวอย่างการเลือกหนึ่งกรณี คือ **บัตร A โรงเรือนผักใกล้บ้าน** ที่มีไฟบ้านและ WiFi ถึง จากนั้นทีมลองเลือกเองหนึ่งกรณี

> **บันทึกผล** สวนผลไม้ 10 ไร่ (บัตร B ในกิจกรรมที่ 8) จุดวัดความชื้นดินอยู่ห่างบ้าน 400 เมตร มีไฟที่หัวแปลง เซนเซอร์ → ระบบควบคุม เราจะเลือก {{f:s3.comm.choice.tech|12}} เพราะ {{f:s3.comm.choice.why|36}}

### วิธีรับส่งข้อมูล (โปรโตคอล)

อ่านประกอบ ไม่ต้องจด

| โปรโตคอล | หลักการ |
|----------|---------|
| **ESPHome native API** (ที่เราใช้) | บอร์ดรับส่งข้อมูลกับ Home Assistant โดยตรงในเครือข่ายเดียวกัน ไม่ผ่านตัวกลาง และรองรับ Home Assistant ได้มากกว่าหนึ่งเครื่องพร้อมกัน เครื่องที่สองจึงอ่านบอร์ดตัวเดียวกันได้โดยไม่รบกวนเครื่องแรก |
| **MQTT** | อุปกรณ์ส่งข้อความ (publish) ไปยังตัวกลางที่เรียกว่า broker ส่วนผู้รับเลือกรับข้อความ (subscribe) ตามหัวข้อที่ต้องการ ใช้เชื่อมอุปกรณ์หลายยี่ห้อเข้าด้วยกัน |
| **HTTP** | อุปกรณ์ส่งข้อมูลไปยังที่อยู่ URL ปลายทางเป็นครั้ง ๆ |

### ดูข้อมูลฟาร์มจากนอกพื้นที่ด้วย Home Assistant Cloud (สาธิต)

ระบบของเราขาดอย่างเดียวคือการเข้าถึงจากนอกฟาร์ม ผู้สอนสาธิตวิธีเติมส่วนนี้จากชุดของผู้สอน **ทีมไม่ต้องทำตาม** เพราะบริการนี้ต้องสมัครบัญชีและรอเปิดใช้งาน

หลักการคือ Home Assistant ของฟาร์มยังเป็นเครื่องเดิม ยังทำ automation บันทึกข้อมูล และแสดงแดชบอร์ดอยู่ในฟาร์ม บริการ **Home Assistant Cloud** (ของบริษัท Nabu Casa ผู้ดูแลโครงการ Home Assistant) เพียงเปิดทางให้เข้าถึงเครื่องนั้นจากอินเทอร์เน็ตอย่างปลอดภัย ไม่ได้ย้ายข้อมูลหรือกฎขึ้นไปทำงานบนคลาวด์

สิ่งที่ผู้สอนแสดงบนจอ

1. **Settings → Home Assistant Cloud** บัญชีที่ลงชื่อเข้าใช้แล้ว สวิตช์ **Remote access** ที่เปิดอยู่ และที่อยู่สำหรับเข้าจากภายนอกที่ระบบสร้างให้
2. ปิด WiFi บนโทรศัพท์ของผู้สอน ให้ใช้อินเทอร์เน็ตมือถือเท่านั้น
3. เปิดที่อยู่นั้นบนโทรศัพท์ ลงชื่อเข้าใช้ แล้วเห็นแดชบอร์ดเดียวกับที่ฉายอยู่
4. เป่าลมใส่บอร์ด GoGo-IoT ของผู้สอน ดูค่าความชื้นบนโทรศัพท์เปลี่ยนตาม แล้วสั่งปั๊มจากโทรศัพท์หนึ่งครั้ง

> บริการนี้เป็นแบบสมัครสมาชิกมีค่าใช้จ่ายรายเดือนหรือรายปี ไม่ได้ติดมากับ Home Assistant ที่เป็นโอเพนซอร์ส ค่าบริการส่วนหนึ่งใช้สนับสนุนการพัฒนา Home Assistant ทางเลือกที่ไม่มีค่าใช้จ่ายมีอยู่ แต่ต้องตั้งค่าเครือข่ายเอง ดูในหัวข้อศึกษาเพิ่มเติมท้ายหน้านี้

> **บันทึกผล** โทรศัพท์ของผู้สอนดูแดชบอร์ดผ่าน {{r:s3.remote.conn|อินเทอร์เน็ตมือถือ|WiFi ของโซน}} · ส่วนที่ตัดสินใจและบันทึกข้อมูลอยู่ที่ {{r:s3.remote.where|ในฟาร์ม (แล็ปท็อป)|บนคลาวด์}}

**คำถามท้ายหัวข้อ** ถ้าอินเทอร์เน็ตของฟาร์มดับ แต่ WiFi ในฟาร์มและ Home Assistant ยังทำงาน อะไรยังใช้ได้และอะไรใช้ไม่ได้ และถ้าเป็นเครื่องที่รัน Home Assistant ดับ ผลต่างจากกรณีแรกอย่างไร

## จ่ายไฟให้อุปกรณ์ในแปลงอย่างไร

**10 นาที ผู้สอนนำ ทีมดูที่กล่องของตัวเอง**

**อุปกรณ์ที่ใช้** กล่องจ่ายไฟที่ต่ออยู่แล้วตั้งแต่ช่วงที่ 1, แผงโซลาร์เซลล์ 12V 15W (หยิบดูประกอบ ไม่ต้องต่อ)

อุปกรณ์ที่ติดตั้งกลางแปลงอาจอยู่ไกลจากจุดจ่ายไฟ จึงต้องวางแผนแหล่งพลังงานด้วย ระบบโซลาร์เซลล์ขนาดเล็กมีส่วนสำคัญสามส่วน ได้แก่ **แผงโซลาร์เซลล์** ผลิตไฟ **แบตเตอรี่** เก็บพลังงานไว้ใช้ และ **charge controller** ควบคุมการชาร์จและการจ่ายไฟให้โหลด เพื่อไม่ให้แบตเตอรี่ชาร์จเกินหรือคายประจุมากเกินไป

อุปกรณ์ที่เราเรียกว่า “กล่องจ่ายไฟ” ตั้งแต่ช่วงที่ 1 คือ charge controller โดยชุดทดลองใช้ **อะแดปเตอร์ 12V ต่อแทนแบตเตอรี่** เพื่อจ่ายไฟให้ปั๊มและบอร์ด ชุดทดลองจึงมีสองในสามส่วน ส่วนที่ขาดคือแบตเตอรี่จริง เราจึงไม่ต่อแผงเข้ากล่องในห้องอบรม เพราะแผงมีไว้ชาร์จแบตเตอรี่ ไม่ได้มีไว้เลี้ยงระบบโดยตรง

![charge controller PWM ด้านหน้า: จอ LCD สามปุ่ม ช่อง USB สองช่อง และขั้วต่อหกขั้วด้านล่าง แบ่งเป็นสามคู่ พร้อมป้าย แผง แบตเตอรี่ โหลด สองคู่หลังมีสายต่ออยู่แล้ว](images/placeholder.png){ width="55%" }

### รู้จักขั้วต่อและอ่านค่าบนหน้าจอ

ขั้วต่อด้านล่างมีสามคู่ จากซ้ายไปขวา คือ **แผงโซลาร์เซลล์** (สัญลักษณ์แผง) **แบตเตอรี่** (สัญลักษณ์แบตเตอรี่) และ **โหลด DC** (สัญลักษณ์หลอดไฟ) ไล่สายที่ต่ออยู่แล้วให้ครบ

- คู่ซ้าย: ว่าง ในฟาร์มจริงต่อแผงโซลาร์เซลล์ที่นี่ หลังต่อแบตเตอรี่แล้วเท่านั้น
- คู่กลาง: ต่ออะแดปเตอร์แทนแบตเตอรี่เพื่อจ่ายไฟให้ชุดทดลอง
- คู่ขวา: ไปแผงต่อสาย แล้วผ่านรีเลย์ไปปั๊ม นี่คือโหลด 12V ของระบบ
- ช่อง USB สองช่อง: โหลด 5V อีกทางหนึ่ง บอร์ดรีเลย์ใช้ตั้งแต่ช่วงที่ 1 และบอร์ด GoGo-IoT ใช้ตั้งแต่จบช่วงที่ 1

สังเกตว่าอุปกรณ์ทุกชิ้นของทีมเรา ยกเว้นแล็ปท็อป ใช้ไฟจากกล่องนี้กล่องเดียวมาตั้งแต่จบช่วงที่ 1

จอแสดงแรงดันของ "แบตเตอรี่" และไอคอนต่าง ๆ อ่านค่าแรงดันและดูไอคอนแบตเตอรี่ว่าบอกเต็มหรือไม่

> จอจะแสดงแรงดันประมาณ 12 V แต่ไอคอนแบตเตอรี่จะดู **ไม่เต็ม** แม้อะแดปเตอร์ยังจ่ายไฟอยู่ เพราะแบตเตอรี่ตะกั่วกรดที่ชาร์จเต็มมีแรงดันประมาณ 12.7–13.0 V charge controller ประเมินจากแรงดันที่วัดได้ จึงไม่รู้ว่าแหล่งจ่ายเป็นอะแดปเตอร์ ตัวอย่างนี้ช่วยให้เห็นว่าอุปกรณ์ตัดสินใจได้จากข้อมูลที่วัดได้เท่านั้น ไอคอนแบตเตอรี่เป็นค่าประมาณ ไม่ใช่ปริมาณพลังงานที่เหลืออยู่จริง

### ใครต้องมีไฟตอนกลางคืน

แผงผลิตไฟเฉพาะตอนมีแสง แบตเตอรี่คือส่วนที่ทำให้ระบบอยู่ได้ทั้งคืนและวันฟ้าครึ้ม ส่วน charge controller ตัดโหลดเมื่อแบตเตอรี่ต่ำเพื่อรักษาแบตเตอรี่ไว้ การเลือกชนิดและขนาดแบตเตอรี่ให้ตรงกับ charge controller ต้องดูจากคู่มือของอุปกรณ์ทั้งสอง ไม่ใช่เรื่องที่เดาได้จากชื่อชนิดถ่าน

ลองไล่ดูอุปกรณ์ของทีม ถ้าต้องการให้ระบบ **บันทึกข้อมูลได้ทั้งคืนที่ฟาร์ม** อุปกรณ์ชิ้นใดต้องมีไฟเลี้ยงบ้าง บอร์ด GoGo-IoT มีถ่าน 18650 ในตัวจึงอยู่ได้เอง แต่บอร์ดรีเลย์ เราเตอร์ และเครื่องที่รัน Home Assistant ไม่มี

> ถ้าผู้สอนมีชุดสาธิตที่มีแบตเตอรี่จริง จะแสดงกระแสชาร์จบนจอเมื่อแผงโดนแสงและเมื่อบังแผง โดยแบตเตอรี่ต่ออยู่ตลอด ทีมดูจากจอฉาย

> **บันทึกผล** จอแสดง {{n:s3.pwr.volt|5}} V · ไอคอนแบตเตอรี่แสดงว่า {{r:s3.pwr.icon|เต็ม|ไม่เต็ม}}
>
> อุปกรณ์ที่ต้องมีไฟเลี้ยง ถ้าจะบันทึกข้อมูลทั้งคืนที่ฟาร์ม {{f:s3.pwr.night|36}}

**ความปลอดภัย** แผงที่โดนแสงจ่ายกระแสตลอดเวลาแม้ไม่ได้ต่ออะไร ห้ามให้สายบวกและลบของแผงแตะกัน และในฟาร์มจริงห้ามต่อแผงเข้า charge controller ที่ยังไม่มีแบตเตอรี่ ลำดับที่ถูกต้องคือ แบตเตอรี่ → แผง → โหลด และถอดย้อนลำดับ

**คำถามท้ายกิจกรรม** ชุดอุปกรณ์ในสถานการณ์ D (แปลงห่างไกล) ใช้ระบบแบบนี้ ถ้าฟ้าครึ้มติดกันสามวัน อุปกรณ์จะทำงานต่อได้อีกนานเท่าไร ต้องรู้ตัวเลขอะไรบ้าง (สามอย่าง) จึงจะตอบได้ แผง 15W ในชุดของเราเลี้ยงเซนเซอร์และการสื่อสารได้ แต่ปั๊มโซลาร์ในสถานการณ์ D ต้องคำนวณแยกต่างหาก

## อ่านข้อมูลที่บันทึกไว้ตั้งแต่ช่วงที่ 2

**20 นาที**

**อุปกรณ์ที่ใช้** แล็ปท็อป

> **สลับคนใช้แล็ปท็อปก่อนเริ่ม**

Home Assistant บันทึกข้อมูลมาตั้งแต่ต้นช่วงที่ 2 เราจะย้อนดูข้อมูลเหล่านี้ เชื่อมโยงการเปลี่ยนแปลงบนกราฟกับสิ่งที่ทีมทดลองทำ แล้วคิดต่อว่าถ้าเห็นลักษณะเดียวกันในฟาร์มจริง ควรทำอะไร

1. เมนูซ้าย **History**
2. กด **+ Choose entity** เพิ่มความชื้นอากาศ แสง และ **สวิตช์ของบอร์ดรีเลย์**
3. กดที่ช่วงเวลาด้านบน ตั้งให้ครอบตั้งแต่ต้นช่วงที่ 2 ถึงตอนนี้ กราฟแสดงได้เฉพาะช่วงที่มีการบันทึก ตั้งช่วงกว้างกว่านั้นก็ไม่มีข้อมูลก่อนที่ Home Assistant เปิด ในฟาร์มจริงเราจะตั้งเป็นวันหรือสัปดาห์เพื่อดูแนวโน้ม

![หน้า History แสดงกราฟความชื้นอากาศ กราฟแสง และแถบสถานะเปิดปิดของสวิตช์รีเลย์ตั้งแต่ช่วงที่ 2 เห็นช่วงที่ค่าความสว่างลดลงตอนครอบบอร์ด แถบรีเลย์สลับถี่ช่วงก่อนใส่ hysteresis และช่วงที่เส้นขาดหายตอนรอบจำลองปัญหา](images/placeholder.png){ width="60%" }

> ทีมที่ VM ถูกปิดหรือรีสตาร์ตระหว่างพัก จะไม่มีข้อมูลช่วงที่ 2 ให้อ่านกราฟตัวอย่างที่ผู้สอนฉาย หรือขอดูของทีมข้าง ๆ แล้วทำข้อต่อไปได้ตามปกติ

หาสี่อย่างนี้บนกราฟ แล้วบอกให้ได้ว่าตอนนั้นเราทำอะไร ถ้าหาไม่พบให้เขียนว่า **ไม่พบ** ได้ เพราะบางทีมอาจไม่เกิดอาการนั้น หรือช่วงขาดหายสั้นจนมองไม่เห็น

- **ช่วงที่ค่าความสว่างลดลง** ตอนเอามือครอบบอร์ดในกิจกรรมที่ 5
- **ช่วงที่แถบรีเลย์สลับถี่** ตอนที่เกณฑ์เปิดกับเกณฑ์ปิดยังเท่ากัน ก่อนใส่ hysteresis
- **ช่วงที่เส้นขาดหายไป** ตอนรอบจำลองปัญหาในกิจกรรมที่ 6 ที่บอร์ดโดนปิดสวิตช์หรือหลุดจากเครือข่าย
- **ช่วงที่รีเลย์ถูกสั่ง On หลังต่อปั๊มกลับ** ตอนที่ระบบรดน้ำเริ่มทำงานเอง

> แถบรีเลย์ On **ไม่ได้แปลว่าปั๊มเดิน** ช่วงแรกของกิจกรรมที่ 5 รีเลย์ต่ออยู่กับหลอดไฟ ให้นับเฉพาะหลังเวลาที่จดไว้ตอนต่อปั๊มกลับ {{f:s2.pump_back_t|5}} น. และแม้หลังจากนั้น แถบก็บอกได้เพียงว่า Home Assistant **สั่ง** On ปั๊มเดินจริงหรือไม่ต้องดูจากค่าความสั่นสะเทือน เหมือนปัญหาที่ 4 ของช่วงที่ 2

> **บันทึกผล** ความชื้นอากาศตั้งแต่ช่วงที่ 2 ต่ำสุด {{n:s3.hist.hum_min|4}} % ตอน {{f:s3.hist.hum_min_t|5}} น. สูงสุด {{n:s3.hist.hum_max|4}} % ตอน {{f:s3.hist.hum_max_t|5}} น.
>

3. **Gauge** ของความชื้นอากาศ ถ้ามีเวลา ตั้ง **Severity** ให้สีเปลี่ยนตามเกณฑ์เปิดและเกณฑ์ปิดปั๊มของทีม เพื่อให้คนที่ไม่รู้ตัวเลขเกณฑ์ก็อ่านออก
4. **History graph** ตั้ง Hours to show เป็น 24 จะเห็นข้อมูลที่เพิ่งอ่านไปอยู่ในนั้น
5. **Tile** ของสวิตช์ลูกลอย ตั้งชื่อให้คนอ่านเข้าใจ เช่น `น้ำในถัง` (เปลี่ยนไอคอนถ้ามีเวลา)
6. เพิ่ม **Tile** สำหรับสวิตช์ปั๊ม และ **Entities** สำหรับกฎ automation ทุกข้อ กดที่ชื่อ automation ดูว่ามี **Last triggered** หรือไม่
7. ย้ายการ์ดให้สิ่งสำคัญที่สุดอยู่บนสุด กด **Done**

## กิจกรรมที่ 8 — ออกแบบระบบสำหรับฟาร์ม (Design)

**55 นาที** ออกแบบ 40 · แลกเปลี่ยนกับทีมที่จับคู่กัน 10 · ปรับแก้และบันทึก 5

**อุปกรณ์ที่ใช้** แบบร่างระบบท้าย[ใบบันทึกของทีม](record-sheet.md) ใบราคาอุปกรณ์ที่แจก (ราคาเป็นตัวอย่าง ณ วันที่ระบุในใบ) โทรศัพท์สำหรับค้นราคาเพิ่มถ้าต้องการ

> **ตกลงกันก่อนว่าใครเป็นคนเขียนลงแบบร่าง** และให้ทุกคนมีส่วนในแต่ละส่วนของแบบร่าง

เป้าหมายคือแบบร่างสำหรับ **ทดลองรอบแรก** ที่จุดเดียว แก้ปัญหาเดียวที่ชัดเจน ไม่ใช่แบบติดตั้งทั้งฟาร์ม สิ่งที่ยังไม่รู้ให้เขียนว่ายังไม่รู้ และระบุว่าต้องถามใครหรือวัดอะไรก่อนซื้อ การรู้ว่าตัวเองยังขาดข้อมูลอะไรเป็นข้อดีของแบบร่าง ไม่ใช่ข้อบกพร่อง

> ค่าเกณฑ์ความชื้นอากาศที่ใช้ในห้องอบรมเป็นการจำลองเพื่อฝึกเขียนกฎ ในฟาร์มจริงต้องเลือกค่าที่วัดแล้วตอบการตัดสินใจนั้นได้จริง เช่น ความชื้นดินสำหรับการรดน้ำ และต้องวัดค่าปกติในแปลงก่อนตั้งเกณฑ์

เลือกสถานการณ์จากบัตรหนึ่งใบ หรือใช้ฟาร์มของสมาชิกในทีม แล้วจัดทำแบบร่างระบบหนึ่งหน้า

| บัตร | สถานการณ์ |
|------|-----------|
| **A โรงเรือนผัก** | โรงเรือน 6 × 20 เมตร ใกล้บ้าน มีไฟบ้านและ WiFi ถึง ปลูกผักสลัด ปัญหาคือร้อนจัดช่วงบ่ายและรดน้ำไม่สม่ำเสมอเมื่อเจ้าของไม่อยู่ |
| **B สวนผลไม้ 10 ไร่** | ลำไยหรือมะม่วง แปลงยาว 400 เมตรจากบ้าน มีไฟที่หัวแปลง ต้องการรู้ความชื้นดิน 3–4 จุดกระจายทั่วสวน และสั่งวาล์วน้ำหยดเป็นโซน |
| **C ไฮโดรโปนิกส์** (ขั้นสูง) | โต๊ะปลูก 8 โต๊ะในโรงเรือน ต้องเฝ้าระดับน้ำ อุณหภูมิน้ำ และค่า EC/pH ปั๊มหมุนเวียนจะหยุดนานเกิน 30 นาทีไม่ได้ |
| **D แปลงห่างไกล ไม่มีไฟ** (ขั้นสูง) | ข้าวโพดหรือมันสำปะหลัง 20 ไร่ ห่างบ้าน 3 กิโลเมตร ไม่มีไฟบ้าน สัญญาณมือถืออ่อน ต้องการรู้ความชื้นดินและระดับน้ำในบ่อ และสั่งปั๊มโซลาร์ |
| **E ฟาร์มของเราเอง** | หากมีสมาชิกทำฟาร์มและมีข้อมูลพื้นที่ชัดเจน ให้ใช้ฟาร์มนั้นเป็นโจทย์แทนบัตรได้ เริ่มจากปัญหาที่เขียนไว้ตอนเริ่มช่วงที่ 1 ต้องบอกได้ว่า ขนาดพื้นที่ ระยะจากบ้าน มีไฟบ้านหรือไม่ สัญญาณมือถือเป็นอย่างไร และตอนนี้แก้ปัญหานั้นอย่างไร |

> บัตร C และ D ต้องใช้อุปกรณ์เฉพาะทาง (หัววัด EC/pH ที่ต้องปรับเทียบ ปั๊มโซลาร์ที่ต้องคำนวณขนาดแผงและแบตเตอรี่) เลือกได้ถ้าทีมมีคนคุ้นเคยกับอุปกรณ์เหล่านั้น หรือเขียนส่วนนั้นไว้ในช่อง "สิ่งที่ยังไม่แน่ใจ" แล้วออกแบบส่วนที่เหลือให้ครบ แนะนำให้เริ่มจากบัตร E ถ้ามีฟาร์มจริง

### แลกเปลี่ยนกับทีมที่จับคู่กัน

ทีมเดียวกับรอบจำลองปัญหาในช่วงที่ 2

1. ทีมแรกเล่าแบบร่าง 1 นาที ทีมที่ฟังใช้ 3 นาทีตอบสองข้อ: **การตัดสินใจไหนมีเหตุผลชัดที่สุด** และ **ชิ้นไหนที่ยังตอบไม่ได้ว่าถ้าเสียแล้วจะเกิดอะไรขึ้นต่อ**
2. สลับกัน
3. แต่ละทีมกลับมาปรับแบบร่างของตัวเองหนึ่งจุดจากสิ่งที่ได้ฟัง

> **บันทึกผล** สิ่งที่ปรับหลังฟังทีมที่จับคู่กัน {{f:d.revise|40}}

ไม่มีการนำเสนอหน้าห้อง ผู้สอนอาจยกแนวคิดที่เห็นระหว่างเดินดูโต๊ะมาเล่าในช่วงสรุป

### เกณฑ์ประเมินแบบร่าง

- เลือกเซนเซอร์และอุปกรณ์ที่รับคำสั่งไปทำงาน (actuator) โดยอ้างอิงสเปก และมี **ราคาจริง** ระบุว่าแอนะล็อกหรือดิจิทัล
- วิธีสื่อสารและแหล่งพลังงานเลือกโดยพิจารณาปัจจัยทั้งสี่ ไม่ใช่ "ใช้ WiFi เพราะในห้องอบรมใช้ WiFi"
- มี **fail-safe อย่างน้อยหนึ่งข้อ** และมี manual override ระบุว่าอยู่ที่ซอฟต์แวร์ บอร์ด หรือสายไฟตรง
- ระบุคนดูแลและความถี่
- งบประมาณรวมเหมาะสมกับขนาดและกำลังลงทุนของฟาร์ม
- ระบุสิ่งที่ยังไม่แน่ใจ และจะตรวจสอบอย่างไรก่อนลงมือ

แบบร่างอยู่ท้าย[ใบบันทึกของทีม](record-sheet.md) กรอกในหน้านั้นได้เลย

## สรุปทั้งหลักสูตร

ทบทวนหน้าที่ของ **ส่วนรับข้อมูล (Input) ส่วนตัดสินใจ (Logic) และส่วนที่ทำงานตามคำสั่ง (Output)** โดยเชื่อมโยงกับกิจกรรมทั้งสามช่วง

1. **เลือกการสื่อสารและพลังงานให้เหมาะกับพื้นที่** จากระยะทาง พลังงาน ปริมาณข้อมูล และค่าใช้จ่าย
2. **ระบบที่ควบคุมภายในฟาร์มยังทำงานได้เมื่ออินเทอร์เน็ตขัดข้อง** การเข้าถึงจากภายนอกเป็นเพียงทางเข้าไปดู Home Assistant เครื่องเดิมที่ฟาร์ม ระบบควบคุมหลักยังอยู่ที่ฟาร์ม
3. **charge controller ก็เป็นระบบ Input → Logic → Output** วัดแรงดัน ตัดสินใจ แล้วจ่ายหรือตัดไฟ และก็เห็นเฉพาะสิ่งที่วัดได้เช่นกัน
4. **ออกแบบแดชบอร์ดตามความต้องการของผู้ใช้** สิ่งสำคัญที่สุดอยู่บนสุด อ่านได้โดยไม่ต้องรู้ตัวเลข และให้คนที่ไม่ได้สร้างเป็นคนทดสอบ
5. **แบบร่างระบบต้องมีราคาและเหตุผล** ระบุเหตุผลที่เลือกอุปกรณ์แต่ละชิ้น ค่าใช้จ่าย ผลกระทบหากอุปกรณ์ขัดข้อง และสิ่งที่ยังต้องตรวจสอบก่อนลงมือ

### คืนอุปกรณ์

ทำตามลำดับนี้ เพื่อไม่ให้กฎใดสั่งปั๊มเดินระหว่างที่เรากำลังเทน้ำ

- [ ] **Settings → Automations & scenes** ปิดสวิตช์ automation ทุกข้อที่สั่งรีเลย์ได้ (กฎรดน้ำสองข้อ กฎน้ำหมด และ fail-safe ทุกข้อ)
- [ ] สั่งสวิตช์รีเลย์เป็น **Off** จากหน้าอุปกรณ์ แล้วดูว่าปั๊มหยุด
- [ ] ถอดสายตามลำดับ: สาย USB ของบอร์ดทั้งสองและสายโหลดออกจาก charge controller ก่อน แล้วจึงถอดอะแดปเตอร์ออกจากปลั๊กและจากคู่แบตเตอรี่ท้ายสุด ในฟาร์มจริงที่มีแผง ถอดแผงก่อนแบตเตอรี่
- [ ] เมื่อไม่มีไฟแล้ว เทน้ำออก เช็ดปั๊มและสายยางให้แห้ง ยกสวิตช์ลูกลอยออกจากใบ A เช็ดให้แห้ง
- [ ] ตรวจรายการอุปกรณ์ตาม [หน้าแรก](index.md) แล้วคืนทั้งชุดพร้อมบัตรประจำทีม
- [ ] **เก็บคำตอบของทีมไว้** กด **ดาวน์โหลดคำตอบ** ที่หัวหน้านี้แล้วส่งไฟล์ให้ผู้สอน จากนั้นเปิด[ใบบันทึกของทีม](record-sheet.md) แล้วกด **พิมพ์ / บันทึก PDF** แบบร่างคือแบบร่างแรกของระบบในฟาร์มของเราเอง

## นำไปใช้ที่ฟาร์มอย่างไร

ซอฟต์แวร์ที่เราใช้เป็นโอเพนซอร์สทั้งหมด และอุปกรณ์หาซื้อได้จากร้านค้าออนไลน์ในไทย Home Assistant ก็ติดตั้งไว้บนแล็ปท็อปของเราแล้ว

| สิ่งที่ต้องมี | ตัวเลือกที่แนะนำ |
|---------------|------------------|
| เครื่องสำหรับเปิด Home Assistant ตลอดเวลา | Raspberry Pi 4/5 หรือ Home Assistant Green หรือคอมพิวเตอร์เก่าหนึ่งเครื่องที่เปิดทิ้งไว้ได้ ควรเลือกเครื่องที่เปิดทำงานต่อเนื่องได้และไม่ถูกปิดหรือนำไปใช้งานที่อื่น |
| บอร์ดเซนเซอร์ | GoGo-IoT หรือ ESP32 ทั่วไป + เซนเซอร์อุณหภูมิความชื้น + เซนเซอร์ความชื้นดินแบบ capacitive + สวิตช์ลูกลอย |
| บอร์ดรีเลย์ | โมดูลรีเลย์ ESP32 สำเร็จรูป (ค้นคำว่า ESP32 relay board) |
| ปั๊มและไฟ | ปั๊มจุ่ม 12V + อะแดปเตอร์ 12V 2A |
| พลังงานสำหรับพื้นที่ไม่มีไฟฟ้า | แผงโซลาร์เซลล์ 12V + charge controller PWM + แบตเตอรี่ 12V ขนาดคิดจากจำนวนชั่วโมงที่ระบบต้องอยู่ได้โดยไม่มีแดด และชนิดต้องตรงกับที่ charge controller รองรับ |
| ดูจากนอกฟาร์ม | Home Assistant Cloud (สมัครสมาชิก ตั้งค่าง่ายที่สุด) หรือตั้งค่าเครือข่ายเอง เช่น VPN แบบ WireGuard หรือ Tailscale |

![QR code ไปยังคู่มือติดตั้ง Home Assistant ที่บ้าน](images/placeholder.png){ width="25%" }

*สแกนเพื่อดูคู่มือติดตั้ง Home Assistant บนเครื่องของเราเอง*

**แหล่งเรียนรู้** home-assistant.io · esphome.io ซึ่งมีตัวอย่างไฟล์ตั้งค่าสำหรับเซนเซอร์แทบทุกตัวที่ขายในท้องตลาด · ไฟล์ตั้งค่าของบอร์ดทั้งสองในหลักสูตรนี้ ผู้สอนจะแจกในกลุ่ม

**หัวข้อที่ศึกษาเพิ่มเติมได้หลังการอบรม**

- เขียนไฟล์ตั้งค่า ESPHome เองตั้งแต่ต้น และแฟลชบอร์ดผ่านเบราว์เซอร์
- fail-safe ในตัวบอร์ดที่ยังทำงานได้แม้ Home Assistant หยุดทำงาน (เชื่อมโยงกับคำถามท้ายกิจกรรมที่ 6)
- MQTT broker ของเราเอง สำหรับเชื่อมอุปกรณ์หลายยี่ห้อ
- ทดลองใช้ LoRa สำหรับแปลงที่ WiFi ไปไม่ถึง
- การเข้าถึงจากนอกฟาร์มโดยไม่ใช้บริการสมัครสมาชิก
- แบตเตอรี่จริงบน charge controller และการคำนวณขนาดแผงกับแบตเตอรี่
