# ช่วงที่ 3 — โครงสร้างระบบ IoT: การสื่อสาร คลาวด์ แดชบอร์ด และการออกแบบระบบ

**เข้าใจการเชื่อมต่อและพลังงาน ก่อนออกแบบระบบสำหรับฟาร์ม**

สองช่วงที่ผ่านมาเราใช้งานบอร์ดร่วมกับ Home Assistant ได้แล้ว ช่วงนี้จะมาดูว่าข้อมูลส่งถึงกันได้อย่างไร และอุปกรณ์ในแปลงที่ไม่มีไฟฟ้าจะใช้พลังงานจากที่ใด จากนั้นสร้างแดชบอร์ดสำหรับผู้ใช้จริง และออกแบบระบบสำหรับฟาร์มโดยพิจารณาทั้งอุปกรณ์ การสื่อสาร พลังงาน และงบประมาณ

> **เมื่อจบช่วงนี้** ทีมจะมีแดชบอร์ดที่ผู้อื่นใช้งานได้ ทดลองดูข้อมูลจากนอกฟาร์ม เข้าใจการจ่ายไฟให้อุปกรณ์ในแปลง และมีแบบร่างระบบสำหรับฟาร์มหนึ่งชุด


## ก่อนเริ่ม

- [ ] เปิด Home Assistant ของทีม ตรวจว่า entity ของบอร์ดทั้งสองแสดงค่า
- [ ] เปิดสวิตช์ automation `รดน้ำ - เปิดปั๊ม` กลับ (ปิดไว้ตอนจบช่วงที่ 2) ระบบรดน้ำจากช่วงที่ 2 ต้องครบ: automation รดน้ำสองข้อและ fail-safe เปิดอยู่ ปั๊มจมในใบ A น้ำวน ลูกลอยในใบ A

## บอร์ดกับ Home Assistant ติดต่อกันอย่างไร

**20 นาที บรรยาย**

**อุปกรณ์ที่ใช้** ไฟล์ตั้งค่า ESPHome ที่แจก (ดูส่วนบนของไฟล์)

![ไฟล์ YAML ของ ESPHome ส่วน esphome, wifi และ api เน้น name_add_mac_suffix, ssid และบล็อก api ที่ไม่มีบรรทัดเข้ารหัส](images/placeholder.png){ width="55%" }

เปิดไฟล์ตั้งค่าแล้วหาสามรายการ ได้แก่ **ssid** ซึ่งระบุชื่อ WiFi ที่บอร์ดใช้, **name_add_mac_suffix** ซึ่งทำให้ชื่อบอร์ดไม่ซ้ำกัน และ **api** ซึ่งกำหนดการเชื่อมต่อกับ Home Assistant รวมถึงการเข้ารหัส ทั้งบอร์ด GoGo-IoT และบอร์ดรีเลย์มีการตั้งค่าส่วนนี้

> ในไฟล์นี้ **ไม่ได้กำหนดหมายเลข IP ไว้** เพราะบอร์ดขอหมายเลขจากเราเตอร์เมื่อเชื่อมต่อ แล้วประกาศชื่อของตนเองบนเครือข่าย Home Assistant จึงค้นพบบอร์ดและแสดงรายการให้เลือกได้ โดยเราไม่ต้องกรอก IP เอง

จากนั้นไปที่ **Settings → Devices & services → ESPHome** กดที่อุปกรณ์ จะเห็น entity ชื่อ **หมายเลข IP** บอกว่าเราเตอร์ให้ IP อะไรกับบอร์ดตัวนี้ ลองเทียบกับของทีมข้าง ๆ เปิดแท็บใหม่ พิมพ์ `http://` ตามด้วย IP นั้น จะเจอหน้าเว็บของบอร์ดเอง เหมือนที่เราใช้ในช่วงที่ 1 ก่อนเพิ่มบอร์ดเข้า Home Assistant **บอร์ดตัวนี้เป็นเว็บเซิร์ฟเวอร์** อยู่ในเครือข่ายเดียวกับเรา และ Home Assistant ก็คุยกับบอร์ดผ่านเครือข่ายเดียวกันนี้เอง

> ในช่วงที่ 2 เมื่อทีมที่จับคู่กันปิด WiFi บนแล็ปท็อป บอร์ดทั้งสองและ Home Assistant ยังทำงานอยู่ แต่ติดต่อกันไม่ได้ เพราะการเชื่อมต่อเครือข่ายถูกตัด

### เลือกวิธีสื่อสารให้เหมาะกับฟาร์ม

ก่อนเลือกวิธีสื่อสาร ให้พิจารณา **ระยะทาง · การใช้พลังงาน · ปริมาณข้อมูล · ค่าใช้จ่าย** วิธีที่เหมาะกับฟาร์มหนึ่งอาจไม่เหมาะกับอีกฟาร์ม

> **จดลงใบบันทึก** ตารางเปรียบเทียบ WiFi · ESP-NOW · LoRa/LoRaWAN · Cellular/NB-IoT · RS-485 ตามปัจจัยทั้งสี่นี้ และเหมาะกับฟาร์มแบบไหน

### วิธีรับส่งข้อมูล (โปรโตคอล)

| โปรโตคอล | หลักการ |
|----------|---------|
| **ESPHome native API** (ที่เราใช้) | บอร์ดรับส่งข้อมูลกับ Home Assistant โดยตรงในเครือข่ายเดียวกัน ไม่ผ่านตัวกลาง และรองรับ Home Assistant ได้มากกว่าหนึ่งเครื่องพร้อมกัน เครื่องที่สองจึงอ่านบอร์ดตัวเดียวกันได้โดยไม่รบกวนเครื่องแรก |
| **MQTT** | อุปกรณ์ส่งข้อความ (publish) ไปยังตัวกลางที่เรียกว่า broker ส่วนผู้รับเลือกรับข้อความ (subscribe) ตามหัวข้อที่ต้องการ |
| **HTTP** | อุปกรณ์ส่งข้อมูลไปยังที่อยู่ URL ปลายทางเป็นครั้ง ๆ |

### ควบคุมในฟาร์ม (Local-first) หรือผ่านคลาวด์

ลองตอบคำถามเหล่านี้สำหรับระบบของเรา เทียบกับระบบที่ประมวลผลและสั่งงานบนคลาวด์ ในกรณีที่อินเทอร์เน็ตดับ

- automation รดน้ำยังทำงานหรือไม่
- ดูแดชบอร์ดจากในฟาร์มได้หรือไม่ · จากในเมืองได้หรือไม่
- ยังบันทึกข้อมูลไว้ดูย้อนหลังหรือไม่

> ระบบของเราขาดอย่างเดียวคือการเข้าถึงจากนอกฟาร์ม เราจะเติมส่วนนั้นในกิจกรรมที่ 7

## จ่ายไฟให้อุปกรณ์ในแปลงอย่างไร

**20 นาที**

**อุปกรณ์ที่ใช้** กล่องจ่ายไฟที่ต่ออยู่แล้วตั้งแต่ช่วงที่ 1, แผงโซลาร์เซลล์ 12V 15W, สายไฟ

> **สลับคนใช้แล็ปท็อปก่อนเริ่ม**

อุปกรณ์ที่ติดตั้งกลางแปลงอาจอยู่ไกลจากจุดจ่ายไฟ จึงต้องวางแผนแหล่งพลังงานด้วย ระบบโซลาร์เซลล์ขนาดเล็กมีส่วนสำคัญสามส่วน ได้แก่ **แผงโซลาร์เซลล์** ผลิตไฟ **แบตเตอรี่** เก็บพลังงานไว้ใช้ และ **ตัวควบคุมการชาร์จ** ควบคุมการชาร์จและการจ่ายไฟให้โหลด เพื่อไม่ให้แบตเตอรี่ชาร์จเกินหรือคายประจุมากเกินไป

อุปกรณ์ที่เราเรียกว่า “กล่องจ่ายไฟ” ตั้งแต่ช่วงที่ 1 คือตัวควบคุมการชาร์จ โดยชุดทดลองใช้ **อะแดปเตอร์ 12V ต่อแทนแบตเตอรี่** เพื่อจ่ายไฟให้ปั๊มและบอร์ด ในกิจกรรมนี้จะศึกษาหน้าที่ของขั้วต่อต่าง ๆ แล้วต่อแผงโซลาร์เซลล์เพิ่ม

![ตัวควบคุมการชาร์จ PWM ด้านหน้า: จอ LCD สามปุ่ม ช่อง USB สองช่อง และขั้วต่อหกขั้วด้านล่าง แบ่งเป็นสามคู่ พร้อมป้าย แผง แบตเตอรี่ โหลด สองคู่หลังมีสายต่ออยู่แล้ว](images/placeholder.png){ width="55%" }

### รู้จักขั้วต่อและอ่านค่าบนหน้าจอ

ขั้วต่อด้านล่างมีสามคู่ จากซ้ายไปขวา คือ **แผงโซลาร์เซลล์** (สัญลักษณ์แผง) **แบตเตอรี่** (สัญลักษณ์แบตเตอรี่) และ **โหลด DC** (สัญลักษณ์หลอดไฟ) ไล่สายที่ต่ออยู่แล้วให้ครบ

- คู่กลาง: ต่ออะแดปเตอร์แทนแบตเตอรี่เพื่อจ่ายไฟให้ชุดทดลอง
- คู่ขวา: ไปแผงต่อสาย แล้วผ่านรีเลย์ไปปั๊ม นี่คือโหลด 12V ของระบบ
- ช่อง USB สองช่อง: โหลด 5V อีกทางหนึ่ง บอร์ดรีเลย์ใช้ตั้งแต่ช่วงที่ 1 และบอร์ด GoGo-IoT ใช้ตั้งแต่จบช่วงที่ 1
- คู่ซ้าย: ยังว่างอยู่ เพราะยังไม่ได้ต่อแผงโซลาร์เซลล์

สังเกตว่าอุปกรณ์ทุกชิ้นของทีมเรา ยกเว้นแล็ปท็อป ใช้ไฟจากกล่องนี้กล่องเดียวมาตั้งแต่จบช่วงที่ 1

จอแสดงแรงดันของ "แบตเตอรี่" และไอคอนต่าง ๆ อ่านค่าแรงดันและดูไอคอนแบตเตอรี่ว่าบอกเต็มหรือไม่

> จอจะแสดงแรงดันประมาณ 12 V แต่ไอคอนแบตเตอรี่จะดู **ไม่เต็ม** แม้อะแดปเตอร์ยังจ่ายไฟอยู่ เพราะแบตเตอรี่ตะกั่วกรดที่ชาร์จเต็มมีแรงดันประมาณ 12.7–13.0 V ตัวควบคุมประเมินจากแรงดันที่วัดได้ จึงไม่รู้ว่าแหล่งจ่ายเป็นอะแดปเตอร์ ตัวอย่างนี้ช่วยให้เห็นว่าอุปกรณ์ตัดสินใจได้จากข้อมูลที่วัดได้เท่านั้น

### ตั้งชนิดแบตเตอรี่

กดปุ่มเมนู 5 ครั้ง แล้วกดค้าง 10 วินาที จอจะแสดง `b01` ใช้ปุ่ม + และ − ดูตัวเลือก: `b01` ตะกั่วกรด · `b02` ลิเธียมไอออน · `b03` ลิเธียมไอรอนฟอสเฟต (LiFePO4) แล้วกลับมาที่ `b01`

> ตัวควบคุมตัดโหลดเมื่อแบตเตอรี่ต่ำ และหยุดชาร์จเมื่อเต็ม แต่ "ต่ำ" กับ "เต็ม" ของแบตเตอรี่แต่ละชนิดเป็นแรงดันคนละค่า ถ้าตั้งผิดชนิด แบตเตอรี่จะเสื่อมเร็ว หรือโดนตัดไฟก่อนเวลา ถ้าใช้ถ่าน 18650 แบบเดียวกับที่อยู่ในบอร์ด GoGo-IoT ต่ออนุกรมเป็นแบตเตอรี่จริง ต้องเลือก `b02`

### ต่อแผง

ลำดับการต่อสำคัญมาก ตัวควบคุมต้องรู้แรงดันของระบบจากแบตเตอรี่ก่อน จึงจะรับไฟจากแผงได้ถูกต้อง ของเราต่อแบตเตอรี่ (อะแดปเตอร์) ไว้แล้ว จึงต่อแผงได้เลย

1. ต่อสายจากแผงเข้า **คู่ซ้าย** (สัญลักษณ์แผง) บวกเข้าบวก ลบเข้าลบ ห้ามให้ปลายสายสองเส้นแตะกัน
2. ดูไอคอนแผงและกระแสชาร์จบนจอ ในห้องจะได้เกือบศูนย์
3. ยกแผงไปใกล้หน้าต่างหรือโคมไฟ แล้วดูตัวเลขอีกครั้ง
4. **ดูผู้สอนสาธิตบนจอ ทีมไม่ต้องทำเอง** ผู้สอนถอดปลั๊กอะแดปเตอร์ของชุดผู้สอนออก 10 วินาทีขณะแผงยังต่ออยู่ ดูว่าจอดับ บอร์ดดับ หรือยังติด การสาธิตนี้ใช้เปรียบเทียบกับกรณีที่แผงผลิตไฟไม่ได้และระบบไม่มีแบตเตอรี่สำรอง แผงอย่างเดียวเลี้ยงระบบไม่ได้ ให้สังเกตจากชุดสาธิตของผู้สอนเท่านั้น เนื่องจากการถอดแบตเตอรี่ออกทั้งที่แผงยังต่ออยู่ผิดลำดับที่คู่มือตัวควบคุมกำหนด ผู้เข้าอบรมจึงไม่ต้องทดลองถอดตาม

![ระบบครบสามส่วน: แผงต่อคู่ซ้ายอะแดปเตอร์ต่อคู่กลาง แผงต่อสายและปั๊มต่อคู่ขวา บอร์ดรีเลย์และบอร์ด GoGo-IoT ต่อช่อง USB คนละช่อง](images/placeholder.png){ width="60%" }

**ถอดสายตามลำดับย้อนกลับจากตอนต่อ** เมื่อเลิกใช้ระบบตอนท้ายวัน ถอดโหลดก่อน แล้วจึงแผง ส่วนแบตเตอรี่ถอดท้ายสุด

> **จดลงใบบันทึก** แรงดันที่จอแสดง · ไอคอนแบตเตอรี่บอกว่าเต็มหรือไม่ · กระแสจากแผงในห้องและใกล้แสง · เกิดอะไรขึ้นตอนผู้สอนถอดอะแดปเตอร์ 10 วินาที

> **สังเกตบอร์ด GoGo-IoT ของผู้สอน** เมื่อจอตัวควบคุมและบอร์ดรีเลย์ดับ บอร์ด GoGo-IoT ยังส่งค่าได้เพราะมีถ่าน 18650 ในตัว ลองเชื่อมโยงกับสถานการณ์ D: อุปกรณ์ที่มีแบตเตอรี่สำรองยังทำงานต่อได้ แต่อุปกรณ์ที่พึ่งแหล่งจ่ายภายนอกเพียงอย่างเดียวจะหยุดเมื่อแหล่งจ่ายนั้นไม่มีไฟ

**ความปลอดภัย** ห้ามให้สายบวกและลบของแผงแตะกัน แผงที่โดนแดดจ่ายกระแสตลอดเวลาแม้ไม่ได้ต่ออะไร และห้ามต่อแผงเข้าตัวควบคุมที่ยังไม่มีแบตเตอรี่

**คำถามท้ายกิจกรรม** ชุดอุปกรณ์ในสถานการณ์ D (แปลงห่างไกล) ใช้ระบบแบบนี้ ถ้าฟ้าครึ้มติดกันสามวัน อุปกรณ์จะทำงานต่อได้อีกนานเท่าไร ต้องรู้ตัวเลขอะไรบ้าง (สามอย่าง) จึงจะตอบได้

## อ่านข้อมูลที่บันทึกไว้ตั้งแต่ช่วงที่ 2

**10 นาที**

**อุปกรณ์ที่ใช้** แล็ปท็อป

Home Assistant บันทึกข้อมูลมาตั้งแต่ต้นช่วงที่ 2 เราจะย้อนดูข้อมูลเหล่านี้ แล้วเชื่อมโยงการเปลี่ยนแปลงบนกราฟกับสิ่งที่ทีมทดลองทำ

1. เมนูซ้าย **History**
2. กด **+ Choose entity** เพิ่มความชื้นอากาศ แสง และ **สวิตช์ของบอร์ดรีเลย์**
3. ตั้งช่วงเวลาให้ครอบตั้งแต่ต้นช่วงที่ 2 ถึงตอนนี้

![หน้า History แสดงกราฟความชื้นอากาศ กราฟแสง และแถบสถานะเปิดปิดของสวิตช์รีเลย์ตั้งแต่ช่วงที่ 2 เห็นช่วงที่ค่าความสว่างลดลงตอนครอบบอร์ด แถบรีเลย์สลับถี่ช่วงก่อนใส่ hysteresis และช่วงที่เส้นขาดหายตอนรอบจำลองปัญหา](images/placeholder.png){ width="60%" }

- **ช่วงที่ค่าความสว่างลดลง** ตอนเอามือครอบบอร์ดในกิจกรรมที่ 5
- **ช่วงที่แถบรีเลย์สลับถี่** ตอนที่เกณฑ์เปิดกับเกณฑ์ปิดยังเท่ากัน ก่อนใส่ hysteresis
- **ช่วงที่เส้นขาดหายไป** ตอนรอบจำลองปัญหาในกิจกรรมที่ 6 ที่บอร์ดโดนปิดสวิตช์หรือหลุดจากเครือข่าย
- **ช่วงที่ปั๊มเดิน** หลังจากระบบรดน้ำเริ่มทำงานเอง

> **จดลงใบบันทึก** ปั๊มเดินกี่ครั้งตั้งแต่ช่วงที่ 2 · ข้อมูลขาดหายกี่ช่วง ช่วงที่ยาวที่สุดกี่นาที · ความชื้นอากาศต่ำสุดและสูงสุดตั้งแต่ช่วงที่ 2

**คำถามที่กราฟนี้ตอบไม่ได้** ช่วงพักหลังช่วงที่ 1 บอร์ดเซนเซอร์ยังเสียบไฟและยังอ่านค่าอยู่ในห้องนี้ แต่กราฟไม่มีข้อมูลของช่วงนั้นเลย เพราะอะไร

> เพราะช่วงนั้นแล็ปท็อปที่ใช้ **รับและบันทึกข้อมูล** ถูกปิดหรือนำออกจากห้องไป แม้บอร์ดยังอ่านค่าอยู่ ก็ไม่มี Home Assistant คอยบันทึกไว้ หากต้องการเก็บข้อมูลต่อเนื่องที่ฟาร์ม จึงต้องมีเครื่องที่เปิดทำงานได้ตลอด ดูตัวเลือกได้ในหัวข้อ **นำไปใช้ที่ฟาร์มอย่างไร** ท้ายหน้านี้

## กิจกรรมที่ 7 — สร้างหน้าจอติดตามและควบคุมฟาร์ม (Dashboard)

**45 นาที**

**อุปกรณ์ที่ใช้** ระบบทั้งหมด และโทรศัพท์ 1–2 เครื่อง

> **สลับคนใช้แล็ปท็อปก่อนเริ่ม**

ออกแบบแดชบอร์ดให้ผู้ที่ไม่ได้ร่วมทำกิจกรรมกับเราเปิดแล้วเข้าใจว่าในฟาร์มเกิดอะไรขึ้น และสามารถสั่งงานอะไรได้บ้าง

### ออกแบบก่อนสร้าง

เลือกผู้ใช้มาหนึ่งแบบ: **เจ้าของฟาร์มที่ดูจากโทรศัพท์ในเมือง** หรือ **คนงานหน้าแปลงที่ใช้แท็บเล็ต** หรือ **ผู้จัดการที่ดูหลายแปลงบนจอใหญ่**

> **จดลงใบบันทึก** ผู้ใช้ต้องรู้หรือทำอะไรบ้าง แต่ละอย่างใช้การ์ดแบบไหน entity รายการใด และอยู่ตำแหน่งไหนบนจอ

ควรมีอย่างน้อยห้าอย่าง: ค่าปัจจุบันที่สำคัญที่สุด (Gauge) · แนวโน้ม 24 ชั่วโมง (History graph) · สถานะน้ำในถังจากสวิตช์ลูกลอย · ปุ่มควบคุม (Tile) · สถานะ automation

### สร้าง

1. **Settings → Dashboards → + Add dashboard → New dashboard from scratch** ตั้งชื่อตามฟาร์ม เช่น `แปลง 1`
2. เปิดแดชบอร์ดใหม่จากเมนูด้านซ้าย กดไอคอนดินสอ แล้วเพิ่มการ์ดตามแผน
3. **Gauge** ของความชื้นอากาศ ตั้ง **Severity** ให้สีเปลี่ยนตามเกณฑ์เปิดและเกณฑ์ปิดปั๊มของทีม เพื่อให้คนที่ไม่รู้ตัวเลขเกณฑ์ก็อ่านออก
4. **History graph** ตั้ง Hours to show เป็น 24 จะเห็นข้อมูลที่เพิ่งอ่านไปอยู่ในนั้น
5. **Tile** ของสวิตช์ลูกลอย ตั้งชื่อให้คนอ่านเข้าใจ เช่น `น้ำในถัง` และเปลี่ยนไอคอน
6. เพิ่ม **Tile** สำหรับสวิตช์ปั๊ม และ **Entities** สำหรับกฎ automation ทุกข้อ กดที่ชื่อ automation ดูว่ามี **Last triggered** หรือไม่
7. ย้ายการ์ดให้สิ่งสำคัญที่สุดอยู่บนสุด กด **Done**

![แดชบอร์ดสำหรับเจ้าของฟาร์ม: เกจความชื้นอากาศสีเขียวบนสุด Tile น้ำในถัง กราฟ 24 ชั่วโมง ปุ่มปั๊ม และรายการ automation](images/placeholder.png){ width="60%" }

**ทดลองให้ผู้อื่นใช้งาน** ให้สมาชิกที่ไม่ได้นั่งหน้าแล็ปท็อปเปิดแดชบอร์ดใหม่บนโทรศัพท์ โดยคนอื่นไม่บอกอะไร เขาบอกได้ทันทีหรือไม่ว่าอากาศแห้งหรือชื้น น้ำในถังพอหรือไม่ และหาปุ่มปั๊มเจอในกี่วินาที

- [ ] **ให้ทีมข้าง ๆ ตรวจ** ส่งโทรศัพท์ให้คนจากทีมอื่นดูแดชบอร์ดของเรา คนนั้นบอกได้หรือไม่ว่าอากาศแห้งหรือชื้น น้ำพอหรือไม่ และปุ่มปั๊มอยู่ส่วนใด ถ้าบอกได้ครบสามอย่างถือว่าผ่าน

### ส่งข้อมูลขึ้นคลาวด์

ตอนนี้แดชบอร์ดดูได้เฉพาะจาก WiFi ของโซนเรา ผู้สอนจะพาทำขั้นตอนบนจอเพื่อส่งค่าของทีมไปยังบริการคลาวด์

> **จดลงใบบันทึก** เครื่องมือคลาวด์ที่ใช้ · ที่อยู่สำหรับดูข้อมูลของทีม · ส่งค่าอะไรขึ้นไปบ้าง ทุกกี่วินาที · ส่วนที่ส่งข้อมูลอยู่ที่บอร์ดหรือที่ Home Assistant

**ทดสอบจากระยะไกล** **ปิด WiFi บนโทรศัพท์** ใช้อินเทอร์เน็ตมือถือ แล้วเปิดที่อยู่คลาวด์ของทีม เห็นค่าหรือไม่ ค่าล่าสุดมาเมื่อกี่วินาทีก่อน และสั่งปั๊มจากที่นั่นได้หรือไม่

**คำถามท้ายกิจกรรม** ถ้าอินเทอร์เน็ตของสถานที่จัดอบรมดับตอนนี้ แดชบอร์ดบนคลาวด์กับแดชบอร์ดใน Home Assistant ของทีมจะเป็นอย่างไร และปั๊มยังรดน้ำเองหรือไม่

## กิจกรรมที่ 8 — ออกแบบระบบสำหรับฟาร์ม (Design)

**45 นาที**

**อุปกรณ์ที่ใช้** หน้าแบบร่างในใบบันทึก ใบราคาอุปกรณ์ที่แจก โทรศัพท์สำหรับค้นราคา

> **ตกลงกันก่อนว่าใครเป็นคนเขียนลงแบบร่าง**

เลือกสถานการณ์จากบัตรหนึ่งใบ หรือใช้ฟาร์มของสมาชิกในทีม แล้วจัดทำแบบร่างระบบหนึ่งหน้า แบ่งเวลาเป็น **ออกแบบ 30 นาที · แลกเปลี่ยนกับทีมที่จับคู่กัน 5 นาที · นำเสนอตัวอย่างหน้าห้อง 10 นาที**

| บัตร | สถานการณ์ |
|------|-----------|
| **A โรงเรือนผัก** | โรงเรือน 6 × 20 เมตร ใกล้บ้าน มีไฟบ้านและ WiFi ถึง ปลูกผักสลัด ปัญหาคือร้อนจัดช่วงบ่ายและรดน้ำไม่สม่ำเสมอเมื่อเจ้าของไม่อยู่ |
| **B สวนผลไม้ 10 ไร่** | ลำไยหรือมะม่วง แปลงยาว 400 เมตรจากบ้าน มีไฟที่หัวแปลง ต้องการรู้ความชื้นดิน 3–4 จุดกระจายทั่วสวน และสั่งวาล์วน้ำหยดเป็นโซน |
| **C ไฮโดรโปนิกส์** | โต๊ะปลูก 8 โต๊ะในโรงเรือน ต้องเฝ้าระดับน้ำ อุณหภูมิน้ำ และค่า EC/pH ปั๊มหมุนเวียนจะหยุดนานเกิน 30 นาทีไม่ได้ |
| **D แปลงห่างไกล ไม่มีไฟ** | ข้าวโพดหรือมันสำปะหลัง 20 ไร่ ห่างบ้าน 3 กิโลเมตร ไม่มีไฟบ้าน สัญญาณมือถืออ่อน ต้องการรู้ความชื้นดินและระดับน้ำในบ่อ และสั่งปั๊มโซลาร์ |
| **E ฟาร์มของเราเอง** | หากมีสมาชิกทำฟาร์มและมีข้อมูลพื้นที่ชัดเจน ให้ใช้ฟาร์มนั้นเป็นโจทย์แทนบัตรได้ เริ่มจากปัญหาที่เขียนไว้หน้าแรกของใบบันทึกตั้งแต่ช่วงที่ 1 ต้องบอกได้ว่า ขนาดพื้นที่ ระยะจากบ้าน มีไฟบ้านหรือไม่ สัญญาณมือถือเป็นอย่างไร และตอนนี้แก้ปัญหานั้นอย่างไร |

### นำเสนอ

1. **กับทีมที่จับคู่กัน** (ทีมเดียวกับรอบจำลองปัญหา) ทีมละ 1 นาที แล้วสลับ ทีมที่ฟังตอบสองข้อ: การตัดสินใจไหนมีเหตุผลชัดที่สุด และชิ้นใดที่ยังตอบไม่ได้ว่าถ้าเสียแล้วจะเกิดอะไรขึ้น
2. **หน้าห้อง** ผู้สอนเลือกสามถึงสี่ทีมที่ทีมที่จับคู่กันเสนอชื่อ ทีมละ 1 นาที ทุกทีมจะได้แลกเปลี่ยนกับทีมที่จับคู่กัน ส่วนการนำเสนอหน้าห้องใช้ยกตัวอย่างแนวคิดที่น่าสนใจร่วมกัน

### เกณฑ์ประเมินแบบร่าง

- เลือกเซนเซอร์และอุปกรณ์ที่รับคำสั่งไปทำงาน (actuator) โดยอ้างอิงสเปก และมี **ราคาจริง** ระบุว่าแอนะล็อกหรือดิจิทัล
- วิธีสื่อสารและแหล่งพลังงานเลือกโดยพิจารณาปัจจัยทั้งสี่ ไม่ใช่ "ใช้ WiFi เพราะในห้องอบรมใช้ WiFi"
- มี **fail-safe อย่างน้อยหนึ่งข้อ** และมี manual override ระบุว่าอยู่ที่ซอฟต์แวร์ บอร์ด หรือสายไฟตรง
- ระบุคนดูแลและความถี่
- งบประมาณรวมเหมาะสมกับขนาดและกำลังลงทุนของฟาร์ม

แบบร่างอยู่ใน [ใบบันทึก](record-sheet.md) หน้าสุดท้าย

## สรุปทั้งหลักสูตร

ทบทวนหน้าที่ของ **ส่วนรับข้อมูล (Input) ส่วนตัดสินใจ (Logic) และส่วนที่ทำงานตามคำสั่ง (Output)** โดยเชื่อมโยงกับกิจกรรมทั้งสามช่วง

1. **เลือกการสื่อสารและพลังงานให้เหมาะกับพื้นที่** จากระยะทาง พลังงาน ปริมาณข้อมูล และค่าใช้จ่าย
2. **ระบบที่ควบคุมภายในฟาร์มยังทำงานได้เมื่ออินเทอร์เน็ตขัดข้อง** การใช้คลาวด์ช่วยให้ดูข้อมูลจากระยะไกลได้ โดยระบบควบคุมหลักยังอยู่ที่ฟาร์ม
3. **ตัวควบคุมการชาร์จก็เป็นระบบ Input → Logic → Output** วัดแรงดัน ตัดสินใจ แล้วจ่ายหรือตัดไฟ และก็เห็นเฉพาะสิ่งที่วัดได้เช่นกัน
4. **ออกแบบแดชบอร์ดตามความต้องการของผู้ใช้** สิ่งสำคัญที่สุดอยู่บนสุด อ่านได้โดยไม่ต้องรู้ตัวเลข
5. **แบบร่างระบบต้องมีราคาและเหตุผล** ระบุเหตุผลที่เลือกอุปกรณ์แต่ละชิ้น ค่าใช้จ่าย และผลกระทบหากอุปกรณ์ขัดข้อง

### คืนอุปกรณ์

- [ ] สั่งปั๊ม Off เทน้ำออก เช็ดปั๊มและสายยางให้แห้ง
- [ ] ยกสวิตช์ลูกลอยออกจากใบ A เช็ดให้แห้ง
- [ ] ถอดสายตามลำดับ: สาย USB และสายโหลดออกจากตัวควบคุมก่อน แผงต่อมา แล้วจึงถอดอะแดปเตอร์ออกจากปลั๊กและจากคู่แบตเตอรี่ท้ายสุด
- [ ] ตรวจรายการอุปกรณ์ตาม [หน้าแรก](index.md) แล้วคืนทั้งชุดพร้อมบัตรประจำทีม

## นำไปใช้ที่ฟาร์มอย่างไร

ซอฟต์แวร์ที่เราใช้เป็นโอเพนซอร์สทั้งหมด และอุปกรณ์หาซื้อได้จากร้านค้าออนไลน์ในไทย Home Assistant ก็ติดตั้งไว้บนแล็ปท็อปของเราแล้ว

| สิ่งที่ต้องมี | ตัวเลือกที่แนะนำ |
|---------------|------------------|
| เครื่องสำหรับเปิด Home Assistant ตลอดเวลา | Raspberry Pi 4/5 หรือ Home Assistant Green หรือคอมพิวเตอร์เก่าหนึ่งเครื่องที่เปิดทิ้งไว้ได้ ควรเลือกเครื่องที่เปิดทำงานต่อเนื่องได้และไม่ถูกปิดหรือนำไปใช้งานที่อื่น |
| บอร์ดเซนเซอร์ | GoGo-IoT หรือ ESP32 ทั่วไป + เซนเซอร์อุณหภูมิความชื้น + เซนเซอร์ความชื้นดินแบบ capacitive + สวิตช์ลูกลอย |
| บอร์ดรีเลย์ | โมดูลรีเลย์ ESP32 สำเร็จรูป (ค้นคำว่า ESP32 relay board) |
| ปั๊มและไฟ | ปั๊มจุ่ม 12V + อะแดปเตอร์ 12V 2A |
| พลังงานสำหรับพื้นที่ไม่มีไฟฟ้า | แผงโซลาร์เซลล์ 12V + ตัวควบคุมการชาร์จ PWM + แบตเตอรี่ 12V ขนาดคิดจากจำนวนชั่วโมงที่ระบบต้องอยู่ได้โดยไม่มีแดด |

*สแกนเพื่อดูคู่มือติดตั้ง Home Assistant บนเครื่องของเราเอง*

**แหล่งเรียนรู้** home-assistant.io · esphome.io ซึ่งมีตัวอย่างไฟล์ตั้งค่าสำหรับเซนเซอร์แทบทุกตัวที่ขายในท้องตลาด · ไฟล์ตั้งค่าของบอร์ดทั้งสองในหลักสูตรนี้ ผู้สอนจะแจกในกลุ่ม

**หัวข้อที่ศึกษาเพิ่มเติมได้หลังการอบรม**

- เขียนไฟล์ตั้งค่า ESPHome เองตั้งแต่ต้น และแฟลชบอร์ดผ่านเบราว์เซอร์
- fail-safe ในตัวบอร์ดที่ยังทำงานได้แม้ Home Assistant หยุดทำงาน (เชื่อมโยงกับคำถามท้ายกิจกรรมที่ 6)
- MQTT broker ของเราเอง สำหรับเชื่อมอุปกรณ์หลายยี่ห้อ
- ทดลองใช้ LoRa สำหรับแปลงที่ WiFi ไปไม่ถึง
- แบตเตอรี่จริงบนตัวควบคุมการชาร์จ และการคำนวณขนาดแผงกับแบตเตอรี่
