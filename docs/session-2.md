# ช่วงที่ 2 — ตรรกะควบคุมอัตโนมัติและการออกแบบ Fail-safe สำหรับฟาร์ม

**Logic ย้ายเข้าซอฟต์แวร์**

ในช่วงที่ 1 เราเป็น Logic เอง ช่วงนี้เราย้ายกฎเข้า Home Assistant แล้วทำให้ฉลาดขึ้น เราจะเริ่มจากระบบไฟกลางคืนสำหรับแปลงไม้ดอก เพื่อเรียนรู้ปัญหาที่ระบบอัตโนมัติทุกระบบต้องเจอ แล้วนำบทเรียนนั้นกลับมาใช้กับระบบรดน้ำของเรา ครึ่งหลังผู้สอนจะ **ทำให้ระบบของเราพังทีละส่วน** ขณะปั๊มทำงานอยู่ เพื่อให้เห็นด้วยตาว่าระบบอัตโนมัติล้มเหลวอย่างไร

> **เมื่อจบช่วงนี้** ระบบจะเปิดไฟเองเมื่อมืดโดยไม่กะพริบ รดน้ำเองเมื่ออากาศแห้ง และหยุดเองเมื่อน้ำหมด เซนเซอร์หาย เดินนานเกิน หรือสั่งแล้วปั๊มไม่เดินจริง


## ก่อนเริ่ม

- [ ] ต่อแล็ปท็อปเข้า WiFi ของโซนเรา `farm-laptop-สี` เปิด VirtualBox กด Start รอจนหน้าจอแสดงที่อยู่ (IP) แล้วเปิดที่อยู่นั้น **วันนี้อาจไม่ใช่เลขเดิมกับเมื่อวาน ให้อ่านจากหน้าจอทุกครั้ง แล้วจดลงช่อง วันที่สอง ในใบบันทึก** รอครึ่งนาที แล้วตรวจว่า entity ของบอร์ดทั้งสองกลับมาแสดงค่า (ไม่ใช่ unavailable)
- [ ] ดูจอกล่องจ่ายไฟว่ายังติด ไฟบอร์ด GoGo-IoT ที่ช่อง USB ยังติด และไฟ **LED** บนบอร์ดรีเลย์ **ติดค้าง ไม่กะพริบ** (กะพริบ = ยังต่อ WiFi ไม่ได้ รอหนึ่งนาทีแล้วดูใหม่)
- [ ] วางปั๊มกลับลงใบ A ปลายสายยางลงใบ A สวิตช์ลูกลอยอยู่ในใบ A เติมน้ำให้ค่อนใบ
- [ ] สลับบทบาทตามตาราง

> ตั้งแต่ตอนนี้จนพักเที่ยง **Home Assistant ของทีมจดค่าทุกอย่างไว้เอง** ครึ่งวันนี้จะกลายเป็นข้อมูลที่เราเปิดอ่านในช่วงที่ 3 จึงอย่าปิด VM ระหว่างช่วงนี้

## ทบทวน: automation มีสามส่วน

**15 นาที** · แล็ปท็อป

เมื่อวานเราเป็น Logic เอง แล้วปิดท้ายด้วย automation ข้อแรก คือลูกลอยแจ้งน้ำต่ำ ให้ปิดปั๊ม เช้านี้เราจะสร้างกฎเพิ่มอีกหลายข้อ จึงเปิดกฎข้อเดิมขึ้นมาดูโครงของมันก่อน

1. **Settings → Automations & scenes** กดที่ชื่อ automation ที่สร้างไว้เมื่อวาน
2. หาสามส่วนบนหน้าจอ **When** · **And if** · **Then do**

| ส่วน | คำถามที่มันตอบ | ของกฎเมื่อวาน |
|------|----------------|----------------|
| **Trigger** (When) | เมื่อไร | ลูกลอยเปลี่ยนเป็น Dry (น้ำหมด) |
| **Condition** (And if) | แต่ต้อง... ด้วย | ไม่มี |
| **Action** (Then do) | ให้ทำอะไร | ปิดสวิตช์ปั๊ม |

ตอนท้ายช่วงที่ 1 เราลอง **ยกลูกลอยค้างไว้ก่อน** แล้วค่อยสั่งเปิดปั๊ม ปรากฏว่าไม่มีอะไรหยุดปั๊มเลย เพราะ trigger ตอบคำถามว่าค่า **เปลี่ยน** เมื่อไร ไม่ใช่ว่าตอนนี้ค่า **เป็น** อะไร สิ่งที่เป็นอยู่แล้วเป็นงานของ condition เราจะได้ใช้ทั้งสองอย่างในเช้านี้

> **จดลงใบบันทึก** automation ข้อแรกของเรา trigger คืออะไร action คืออะไร และถ้าจะให้ปั๊มไม่ยอมเดินเลยตอนลูกลอยยกอยู่ ต้องเพิ่มอะไรตรงไหน

จากนี้ไปเราจะสร้างกฎอีกหลายข้อ เริ่มจากระบบไฟสวนซึ่งเห็นผลในไม่กี่วินาที แล้วเอาบทเรียนที่ได้กลับมาใช้กับระบบรดน้ำ

## กิจกรรมที่ 5 — Think

**75 นาที** · บอร์ด GoGo-IoT, บอร์ดรีเลย์, แล็ปท็อป

> **สลับบทบาทก่อนเริ่ม**

### สถานการณ์: ไฟกลางคืนสำหรับแปลงไม้ดอก

ไม้ดอกหลายชนิด เช่น เบญจมาศ ต้องได้แสงยาวกว่ากลางวันธรรมชาติ สวนจึงเปิดหลอดไฟเมื่อมืด ระบบนี้ต้องตัดสินใจจาก **เซนเซอร์แสง** และสั่ง **หลอดไฟ** ผ่านรีเลย์ ในห้องนี้ **ไฟแสดงสถานะรีเลย์** (Relay Indicator ดวงที่ติดพร้อมเสียงคลิก ไม่ใช่ไฟ LED แสดงการเชื่อมต่อที่ติดค้างอยู่) ทำหน้าที่แทนหลอดไฟในสวน เมื่อรีเลย์ทำงาน ไฟติด นั่นคือหลอดไฟในสวนติด

เราเลือกสถานการณ์นี้ก่อนระบบรดน้ำเพราะเซนเซอร์แสงตอบทันที ใช้มือครอบก็มืด เปิดมือก็สว่าง ทำให้เห็นปัญหาของระบบอัตโนมัติได้ในไม่กี่วินาที

### ปลดปั๊มออกชั่วคราว

รีเลย์ตัวเดียวของเราต่อปั๊มอยู่ ระหว่างฝึกเรื่องไฟสวน รีเลย์จะเปิดปิดถี่ ซึ่งไม่ดีกับปั๊ม **Hardware** คลายสกรูขั้ว **NO** บนบอร์ดรีเลย์ ถอดสายบวกของปั๊มออก แล้วพับปลายสายให้ห่างจากขั้วอื่น รีเลย์จะยังคลิกและไฟแสดงสถานะรีเลย์ยังติด แต่ปั๊มไม่เดิน เราจะต่อกลับตอนกลับมาที่ระบบรดน้ำ

### (ก) เกณฑ์เดียว: มืดแล้วเปิดไฟ

ทีมเลือก **ค่าเกณฑ์แสง** จากค่าปกติในห้องและค่าตอนครอบที่จดไว้ เลือกค่ากลาง ๆ ระหว่างสองค่านั้น

1. **Settings → Automations & scenes** กด **+ Create automation → Create new automation**
2. ในส่วน **When** กด **+ Add trigger → Entity → Numeric state**
3. เลือก entity แสง ช่อง **Below** พิมพ์ค่าเกณฑ์
4. ในส่วน **Then do** กด **+ Add action** ค้นหา **Switch → Turn on** เลือก entity สวิตช์ของบอร์ดรีเลย์
5. **Save** ตั้งชื่อ `ไฟสวน - เปิด`

![ตัวแก้ไข automation แสดง trigger แบบ Numeric state ของแสง ช่อง Below และ action Switch turn on](images/placeholder.png){ width="60%" }

**ทดสอบ** Hardware ครอบบอร์ด ไฟแสดงสถานะรีเลย์ติดหรือไม่ เปิดมือ ไฟดับหรือไม่ เพราะอะไร

> trigger แบบ Numeric state ทำงานเฉพาะตอนค่า **ข้าม** เส้นเกณฑ์ ถ้าค่าอยู่ใต้เกณฑ์อยู่แล้วตั้งแต่ก่อนสร้างกฎ จะยังไม่มีอะไรเกิดขึ้น ต้องทำให้ค่าขึ้นเหนือเกณฑ์ก่อนแล้วค่อยลดลงมาใหม่

สั่ง Off ด้วยมือก่อนไปขั้นถัดไป

### ดูปัญหาให้เห็นก่อนแก้

สร้าง automation ข้อที่สองด้วยวิธีเดียวกัน แต่ trigger ใช้ช่อง **Above** พิมพ์ **ค่าเดียวกับค่าเปิด** และ action เป็น **Switch → Turn off** ตั้งชื่อ `ไฟสวน - ปิด`

ตอนนี้ระบบมีกฎครบ มืดเปิด สว่างปิด ดูเหมือนถูกต้อง

**Hardware** ค่อย ๆ เลื่อนมือเข้าหาบอร์ดจนค่าแสงอยู่ใกล้เกณฑ์ แล้วขยับมือช้า ๆ ขึ้นลงตรงนั้นราวหนึ่งนาที เหมือนเมฆบางลอยผ่านตอนพลบค่ำ **Driver** นับจำนวนครั้งที่ไฟแสดงสถานะรีเลย์ติดดับ

> อาการนี้เรียกว่า **chattering** ในสวนจริงคือหลอดไฟกะพริบทุกเย็น รีเลย์เสียก่อนเวลา และถ้าเป็นปั๊มก็คือปั๊มกระตุกจนพัง

### (ข) Hysteresis: ปิดด้วยเกณฑ์อีกค่า

เปิด `ไฟสวน - ปิด` แก้ค่า **Above** ให้สูงกว่าค่าเปิดพอสมควร (เช่น สูงกว่าราวหนึ่งในสี่ของระยะระหว่างค่ามืดกับค่าสว่าง) กด Save แล้วให้ Hardware ทำแบบเดิม นับใหม่

> **จดลงใบบันทึก** จำนวนครั้งที่ไฟติดดับใน 1 นาที ก่อนแก้และหลังแก้ · ค่าเปิดไฟและค่าปิดไฟของทีม

- [ ] **ทีมตรวจเอง** ขยับมือรอบเกณฑ์หนึ่งนาทีแล้วไฟติดดับไม่เกิน 2 ครั้ง ถือว่าผ่าน ถ้ายังกะพริบถี่ ให้ถ่างค่าเปิดกับค่าปิดออกอีก

### (ค) เงื่อนไขเวลา *(เมื่อมีเวลา)*

สวนไม้ดอกไม่ได้เปิดไฟทั้งคืน แต่เปิดเป็นช่วง เปิด `ไฟสวน - เปิด` ในส่วน **And if** กด **+ Add condition → Time** ตั้ง **After** และ **Before**

เพื่อทดสอบในห้อง ตั้งช่วงที่ครอบเวลาปัจจุบันก่อน แล้วลองตั้งช่วงที่ไม่ครอบ เพื่อดูว่า trigger ทำงานแต่ action ไม่เกิด

### (ง) แจ้งเตือน *(เมื่อมีเวลา)*

เพิ่ม action อีกอันใน `ไฟสวน - เปิด` ค้นหา **notification → Send a persistent notification** ใส่ข้อความที่อยากให้เจ้าของสวนเห็น ข้อความจะขึ้นที่ไอคอนกระดิ่งมุมล่างซ้าย

ถ้ามีใครติดตั้งแอป Home Assistant Companion ไว้ ให้ใช้ **Send a notification via mobile_app** แทน ข้อความจะเด้งบนโทรศัพท์จริง

### สลับสถานการณ์: กลับมาที่ระบบรดน้ำ

รีเลย์ของเรามีตัวเดียว ตอนนี้จะให้ทำหน้าที่ปั๊มแทนหลอดไฟ

1. **ปิดสวิตช์** ของ `ไฟสวน - เปิด` และ `ไฟสวน - ปิด` ทั้งสองข้อ (สวิตช์ทางขวาในหน้า Automations) กฎยังอยู่ แต่ไม่ทำงาน แล้วสั่งสวิตช์รีเลย์เป็น Off
2. **Hardware** ต่อสายบวกของปั๊มกลับเข้าขั้ว **NO** ขันแน่น ตรวจว่าปั๊มจมอยู่ในใบ A และปลายสายยางอยู่ในใบ A (น้ำวน)
3. สร้าง automation `รดน้ำ - เปิดปั๊ม`: Numeric state ของ **ความชื้นอากาศ** ช่อง **Below** ใส่ค่าเกณฑ์จากช่วงที่ 1 (สูงกว่าค่าปกติในห้องเล็กน้อย) → Switch turn on
4. สร้าง `รดน้ำ - ปิดปั๊ม`: Numeric state ของความชื้นอากาศ ช่อง **Above** ใส่ค่าที่ **สูงกว่า** ค่าเปิดราว 5–10 % (ใช้บทเรียนจากข้อ (ข) ทันที) → Switch turn off
5. ทดสอบ: ค่าในห้องต่ำกว่าเกณฑ์เปิดอยู่แล้ว ให้ Hardware เป่าลมใส่บอร์ดจนค่าพุ่งเกินเกณฑ์ปิด ปั๊มหยุดหรือไม่ แล้วหยุดเป่า รอให้ค่าตกลงต่ำกว่าเกณฑ์เปิด ปั๊มกลับมาเดินหรือไม่ ใช้เวลากี่วินาที

### แผงควบคุม

**Overview** → ดินสอ → **+ Add card → Entities** เพิ่มห้าอย่าง แล้วตั้งชื่อ card ว่า `แผงควบคุม`

- automation `รดน้ำ - เปิดปั๊ม` และ `รดน้ำ - ปิดปั๊ม`
- automation `ไฟสวน - เปิด` และ `ไฟสวน - ปิด` (ปิดอยู่)
- entity สวิตช์ของบอร์ดรีเลย์ (นี่คือ **manual override** บนหน้าจอ)

![card แผงควบคุม แสดงสวิตช์ของ automation สี่ข้อ สองข้อเปิด สองข้อปิด และสวิตช์รีเลย์](images/placeholder.png){ width="55%" }

ลองปิดสวิตช์ของ `รดน้ำ - เปิดปั๊ม` แล้วทำให้อากาศแห้ง ปั๊มทำอะไร และยังสั่งด้วยมือได้หรือไม่

**คำถามของ Recorder** ค่าเปิดและค่าปิดของระบบไฟสวนคือเท่าไร ทำไมสองค่านี้ต้องต่างกัน และเราเอาบทเรียนนี้ไปใช้กับระบบรดน้ำอย่างไร

## กิจกรรมที่ 6 — Failure lab

**45 นาที** · ระบบรดน้ำทำงานอยู่ ปั๊มจมในใบ A น้ำวนกลับใบ A สวิตช์ลูกลอยในใบ A

> **สลับบทบาทก่อนเริ่ม**

### รอบก่อกวน

**จับคู่กับทีมข้าง ๆ** ทีมของเราจะเป็นทั้งผู้ก่อกวนและผู้ถูกก่อกวน สลับกันไปมา ผู้สอนแจกบัตรก่อกวน 3 ใบให้ทุกทีม **ห้ามให้ทีมคู่เห็นบัตร**

ก่อนเริ่ม ทั้งสองทีมทำให้ปั๊มของตัวเองเดินอยู่ (ปล่อยค่าความชื้นตามปกติของห้อง ถ้าปั๊มไม่เดินให้ขยับค่าเกณฑ์เปิดขึ้นชั่วคราว) น้ำวนในถังเดียวจึงไม่มีวันหมด

ทำสามรอบ แต่ละรอบมีสองครึ่ง

1. **ครึ่งแรก เราเป็นผู้สังเกต** ทุกคนในทีมหันไปมองแดชบอร์ดอย่างเดียว **ห้ามมองโต๊ะอุปกรณ์** คนจากทีมคู่จะเดินมาทำอะไรบางอย่างกับระบบของเราตามบัตรของเขา
2. **ครึ่งหลัง เราเป็นผู้ก่อกวน** **Tester** ของทีมเราถือบัตรใบที่ตรงกับรอบนั้น เดินไปทำกับระบบของทีมคู่ แล้วกลับมา

ตอนเป็นผู้สังเกต หน้าที่คือ **ดูอย่างเดียว ห้ามแก้** จนกว่าจะจบรอบ

> **จดลงใบบันทึกทันทีทุกรอบ** เห็นอะไรบนแดชบอร์ด · ปั๊มทำอะไร · ทีมคิดว่าสาเหตุคืออะไร · ใช้เวลากี่วินาทีจึงสังเกตเห็น

เมื่อครบสามรอบ **เปิดบัตรเทียบกัน** ทั้งสองทีมดูว่าเดาถูกกี่รอบ แล้วตอบร่วมกันว่า **รอบไหนที่ปั๊มยังเดินอยู่แม้ Logic ไม่รู้เรื่องอะไรแล้ว** และ **รอบไหนที่แดชบอร์ดดูปกติทุกอย่างแต่ระบบไม่ทำงานจริง**

> พอสำหรับตอนนี้: เมื่อการเชื่อมต่อขาด entity จะกลายเป็น **unavailable** และปั๊มค้างอยู่ในสถานะสุดท้ายที่ได้รับคำสั่ง โดยไม่มีใครสั่งมันต่อ เราจะเปิดดูว่าการเชื่อมต่อนั้นคืออะไรในช่วงที่ 3

### Fail-safe 1 — น้ำในถังหมด หยุดปั๊ม

นี่คือเหตุผลที่ระบบของเรามีสวิตช์ลูกลอย ปั๊มที่ดูดอากาศเพราะน้ำหมดจะพังภายในไม่กี่นาที กฎข้อนี้เรามีอยู่แล้วตั้งแต่ช่วงที่ 1 (`น้ำหมด หยุดปั๊ม`) แต่ตอนต้นช่วงเราพบว่ากฎนั้นมีช่องโหว่ ครั้งนี้เราปิดช่องโหว่ให้ครบ

1. **Settings → Automations & scenes** เปิด `น้ำหมด หยุดปั๊ม` จากช่วงที่ 1 เปลี่ยนชื่อเป็น `Fail-safe - น้ำหมด` แล้วเพิ่ม action อีกหนึ่งอย่าง **Send a persistent notification** ข้อความ `น้ำในถังต่ำ หยุดปั๊มแล้ว` กด Save
2. ทดสอบ: ปั๊มเดินอยู่ ให้ Hardware ยกสวิตช์ลูกลอยขึ้นพ้นน้ำ Tester จับเวลาว่าปั๊มดับเมื่อไร และข้อความแจ้งเตือนขึ้นหรือไม่ แล้ววางกลับ
3. **ปิดช่องโหว่ที่หนึ่ง** ตอนนี้กฎรดน้ำและกฎน้ำหมดขัดกันได้ อากาศแห้งสั่งเปิด แต่น้ำหมดสั่งปิด ถ้าลูกลอยยกอยู่แล้วอากาศแห้งอีกครั้ง `รดน้ำ - เปิดปั๊ม` จะเปิดปั๊มทั้งที่น้ำหมด เพราะ trigger ของกฎน้ำหมดทำงานเฉพาะตอนลูกลอย **เปลี่ยน** สถานะ เปิด `รดน้ำ - เปิดปั๊ม` ในส่วน **And if** กด **+ Add condition → Entity → State** เลือกสวิตช์ลูกลอย สถานะ **Wet** (มีน้ำ) กด Save
4. ทดสอบ: ยกลูกลอยค้างไว้ แล้วทำให้อากาศแห้ง (ค่าต่ำกว่าเกณฑ์เปิด) ปั๊มต้อง **ไม่เดิน** วางลูกลอยกลับ รอให้ค่าข้ามเกณฑ์อีกครั้ง ปั๊มจึงเดิน
5. **ปิดช่องโหว่ที่สอง** condition ในข้อ 3 กันเฉพาะ automation รดน้ำ ถ้ามีคนกดสวิตช์ปั๊มบนแดชบอร์ด หรือกดปุ่มบนบอร์ดรีเลย์ ตอนน้ำหมด ปั๊มยังเดินได้ เปิด `Fail-safe - น้ำหมด` กด **+ Add trigger → Entity → State** เลือกสวิตช์ปั๊ม ช่อง **To** เลือก **On** แล้วในส่วน **And if** กด **+ Add condition → Entity → State** เลือกสวิตช์ลูกลอย สถานะ **Dry** กด Save กฎข้อนี้มี trigger สองอัน: ลูกลอยเปลี่ยนเป็น Dry หรือ ปั๊มถูกสั่งเปิด และทำงานเฉพาะเมื่อน้ำหมดจริง
6. ทดสอบ: ยกลูกลอยค้างไว้ Driver กดสวิตช์ปั๊มบนแดชบอร์ดให้เป็น On ปั๊มต้องดับเองภายในราวหนึ่งวินาที Hardware กดปุ่มบนบอร์ดรีเลย์ ผลต้องเหมือนกัน วางลูกลอยกลับ

> condition แบบนี้ต้องการ **หลักฐานว่ามีน้ำ** ไม่ใช่แค่ไม่มีสัญญาณว่าน้ำหมด ถ้าสายลูกลอยหลุด สวิตช์จะอ่านได้ Dry ถ้าบอร์ดดับ สถานะจะเป็น unavailable ทั้งสองอย่างไม่ใช่ Wet ปั๊มก็ไม่เดิน นี่คือหลักของ fail-safe: เมื่อไม่แน่ใจ ให้ไปทางปลอดภัย

> **สิ่งที่กฎนี้ยังกันไม่ได้** ทุกอย่างในข้อนี้อยู่ใน Home Assistant ถ้า Home Assistant ดับ หรือแล็ปท็อปหลุดจาก WiFi ไม่มีใครสั่งปิด ปุ่มบนบอร์ดรีเลย์และสวิตช์ในตู้ควบคุมยังเปิดปั๊มได้ตามปกติ เก็บข้อนี้ไว้ตอบคำถามของ Recorder ท้ายกิจกรรม

### Fail-safe 2 — ปั๊มเดินได้ไม่เกินเวลาที่กำหนด

ไม่ว่า Logic จะคิดอะไร ปั๊มไม่ควรเดินติดต่อกันนานเกินที่แปลงจะรับได้

1. สร้าง automation ชื่อ `Fail-safe - เวลาปั๊มสูงสุด`
2. Trigger: **Entity → State** เลือกสวิตช์ปั๊ม ช่อง **To** เลือก **On** ช่อง **For** ตั้ง **30 วินาที** (ในฟาร์มจริงอาจเป็น 10–20 นาที)
3. Action: **Switch → Turn off** สวิตช์ปั๊ม และแจ้งเตือน `ปั๊มเดินเกินเวลา ตัดการทำงานแล้ว โปรดตรวจสอบ`
4. ทดสอบ: สั่งเปิดปั๊มด้วยมือ Tester จับเวลาว่าดับเองเมื่อไร

> **หลังถูกตัดแล้วเกิดอะไร** ปั๊มจะ**ไม่**กลับมาเดินเอง จนกว่าค่าความชื้นจะขึ้นเหนือเกณฑ์แล้วตกลงมาข้ามเกณฑ์เปิดอีกครั้ง เพราะ trigger ทำงานเฉพาะตอนค่า **ข้าม** เส้น ในฟาร์มจริงนั่นอาจเป็นหลายวัน หรือไม่เกิดเลยถ้าดินยังแห้งอยู่ fail-safe ที่ตัดการทำงานจึงต้องมีแจ้งเตือนคู่กันเสมอ เพื่อให้คนมาดู แก้สาเหตุ แล้วสั่งเริ่มใหม่

### Fail-safe 3 — เซนเซอร์หาย ไปสู่สถานะปลอดภัย *(เมื่อมีเวลา)*

ทีมตกลงกันก่อนว่า **ถ้า Logic ไม่รู้ค่าความชื้นแล้ว ปั๊มควรเปิด ปิด หรือคงสถานะเดิม** และเพราะอะไร

1. สร้าง automation ชื่อ `Fail-safe - เซนเซอร์หาย`
2. Trigger: **Entity → State** เลือกความชื้นอากาศ ช่อง **To** พิมพ์ `unavailable` แล้วเพิ่ม trigger อีกอันแบบเดียวกันแต่ To เป็น `unknown`
3. Action: **Switch → Turn off** สวิตช์ปั๊ม และแจ้งเตือน `ไม่ได้รับค่าจากเซนเซอร์ หยุดปั๊มเพื่อความปลอดภัย`
4. ทดสอบ: ปั๊มเดินอยู่ ให้ Hardware ถอดสาย USB ของ **บอร์ด GoGo-IoT** ออกจากช่อง USB ของกล่องจ่ายไฟ จับเวลาว่าปั๊มดับเมื่อไร แล้วเสียบกลับ

### Fail-safe 4 — สั่งแล้วเดินจริงหรือไม่ *(เมื่อมีเวลา)*

สามข้อที่ผ่านมากันไม่ให้ **สั่งผิด** ข้อนี้ต่างออกไป คือ **สั่งถูกแล้วแต่ของจริงไม่ทำงาน** Home Assistant บอกว่าสวิตช์เป็น On รีเลย์คลิกจริง ไฟแสดงสถานะรีเลย์ติดจริง แต่ปั๊มอาจไม่เดิน เพราะสายหลุด ขั้วหลวม ปั๊มติดขัด หรือปั๊มโผล่พ้นน้ำ **คำสั่ง ไม่เท่ากับ ผลลัพธ์** ระบบที่ดีต้อง **ยืนยัน** ว่าเกิดขึ้นจริง ไม่ใช่เชื่อว่าคำสั่งสำเร็จเสมอ

บอร์ด GoGo-IoT มีเซนเซอร์วัดความสั่น จึงยืนยันแทนเราได้ มีสอง entity

| entity | บอกอะไร |
|---|---|
| `ความสั่นสะเทือน (vibration)` | ความแรงของการสั่น หน่วย **mg** (มิลลิจี) |
| `ปั๊มกำลังทำงาน (pump running)` | คำตัดสิน เดิน / ไม่เดิน |

เกณฑ์ที่เฟิร์มแวร์ใช้ตัดสิน (ระดับ **กลาง** ซึ่งเป็นค่าเริ่มต้น) คือ **เกิน 25 mg = เดิน · ต่ำกว่า 12 mg = ไม่เดิน** สองค่านี้ต่างกันโดยตั้งใจ เป็น **hysteresis แบบเดียวกับที่เราทำเองในข้อ (ข)** และต้องสั่นต่อเนื่อง 2 วินาทีจึงนับว่าเดิน (กันการเคาะโต๊ะ) กับเงียบ 5 วินาทีจึงนับว่าหยุด

ถ้าคำตัดสินไม่ตรงกับความจริง (ปั๊มเดินอยู่แต่บอกว่าไม่เดิน หรือกลับกัน) ให้เปลี่ยน **ความไวตรวจจับปั๊ม (pump sensitivity)** ได้เอง ทั้งในหน้าอุปกรณ์ของ Home Assistant (หัวข้อ **Configuration**) และในหน้าเว็บของบอร์ด

| ระดับ | เดินเมื่อเกิน | หยุดเมื่อต่ำกว่า | ใช้เมื่อ |
|---|---|---|---|
| **สูง (high)** | 15 mg | 10 mg | บอร์ดแนบปั๊มไม่แน่น หรือปั๊มสั่นเบา · เสี่ยงถูกเคาะโต๊ะหลอก |
| **กลาง (medium)** | 25 mg | 12 mg | ค่าเริ่มต้น |
| **ต่ำ (low)** | 40 mg | 20 mg | บอร์ดแนบปั๊มแน่นมาก หรือโต๊ะสั่นง่าย |

> **คำถามชวนคิด** ทำไมเลื่อนความไวขึ้นแล้วเสี่ยงถูกหลอกมากขึ้น เกณฑ์ *เดิน* กับเกณฑ์ *หยุด* ของแต่ละระดับ ห่างกันเท่าไร และทำไมต้องห่าง

> **ตำแหน่งบอร์ดสำคัญ** เซนเซอร์อยู่บนบอร์ด GoGo-IoT ไม่ได้อยู่ที่ปั๊ม ก่อนทดสอบข้อนี้ให้ **Hardware** วางบอร์ดให้แนบกับสายยาง หรือวางบนถาดข้างถังน้ำ ถ้าบอร์ดอยู่ไกลปั๊ม จะไม่รู้สึกถึงการสั่นและค่าจะค้างอยู่ใกล้ 0

1. สร้าง automation ชื่อ `Fail-safe - สั่งแล้วไม่เดิน`
2. Trigger: **Entity → State** เลือกสวิตช์ปั๊ม ช่อง **To** ใส่ `On` ช่อง **For** ใส่ **15 วินาที** (สั้นกว่า Fail-safe 2 โดยตั้งใจ ถ้าใช้ 30 วินาทีเท่ากัน กฎสองข้อจะทำงานพร้อมกันและเราจะไม่รู้ว่าข้อความที่ขึ้นมาจากข้อไหน)
3. Condition: **Entity → State** เลือก `ปั๊มกำลังทำงาน` สถานะ **Off**
4. Action: **Switch → Turn off** สวิตช์ปั๊ม และแจ้งเตือน `สั่งปั๊มแล้วแต่ไม่มีการสั่น ตรวจสายและระดับน้ำ`
5. ทดสอบ: **Hardware** คลายสกรูขั้ว **NO** ถอดสายบวกของปั๊มออก เหมือนตอนต้นช่วง แล้วสั่งสวิตช์ปั๊มเป็น On Tester จับเวลา ภายใน 15 วินาทีต้องมีข้อความแจ้งเตือนของข้อนี้ขึ้นและสวิตช์ถูกปิดเอง ก่อนที่ Fail-safe 2 จะถึง 30 วินาที แล้วต่อสายกลับ ขันให้แน่น

> **ดูค่าจริงก่อนเชื่อคำตัดสิน** เปิดกราฟ `ความสั่นสะเทือน (vibration)` ใน History เทียบช่วงที่ปั๊มเดินกับช่วงที่หยุด ถ้าสองช่วงไม่ต่างกันชัดเจน แปลว่าบอร์ดอยู่ไกลปั๊มเกินไป ให้ขยับบอร์ดเข้าใกล้แล้วทดสอบซ้ำ

![รายการ automation ทั้งหมดของทีม: ไฟสวนสองข้อ (ปิด) รดน้ำสองข้อ และ Fail-safe สี่ข้อ](images/placeholder.png){ width="60%" }

### ใครกันอะไร

| ล้มเหลวที่ | Home Assistant เห็นอะไร | กฎที่หยุดปั๊ม |
|---|---|---|
| สายลูกลอยหลุด หรือลูกลอยค้าง | ลูกลอยเป็น **Dry** | Fail-safe 1 |
| บอร์ด GoGo-IoT ดับ หรือหลุดจาก WiFi | entity ทุกตัวของบอร์ดเป็น **unavailable** | Fail-safe 3 ถ้าสร้างไว้ · กฎรดน้ำไม่เริ่มรอบใหม่เพราะลูกลอยไม่ใช่ Wet · แต่ปั๊มที่เดินอยู่แล้วเดินต่อ |
| สั่งแล้วปั๊มไม่เดิน | สวิตช์เป็น On แต่ `ปั๊มกำลังทำงาน` เป็น Off | Fail-safe 4 ถ้าสร้างไว้ |
| ปั๊มเดินนานผิดปกติไม่ว่าจากสาเหตุใด | สวิตช์เป็น On นานเกิน | Fail-safe 2 |
| แล็ปท็อปหลุดจาก WiFi หรือ Home Assistant ดับ | ไม่มีใครเห็นอะไรเลย | **ไม่มีข้อไหนเลย** ปั๊มค้างอยู่ในคำสั่งสุดท้าย |

- [ ] **ทีมตรวจเอง** ทดสอบ Fail-safe 1 และ 2 แล้วเห็นปั๊มดับเองจริงทั้งสองข้อ และมีข้อความแจ้งเตือนขึ้น ข้อ 3 และ 4 เมื่อมีเวลา

**คำถามของ Recorder** fail-safe ทั้งหมดอยู่ใน Home Assistant ถ้าแล็ปท็อปดับหรือปิดฝาไปเหมือนรอบก่อกวน fail-safe เหล่านี้ยังทำงานหรือไม่ ถ้าไม่ ควรมีอะไรอยู่ที่ไหนอีกจึงจะปลอดภัยจริง

**15 นาที**

### อภิปราย

- ระบบสำรอง (redundancy) ในฟาร์มมีอะไรบ้าง อะไรคุ้มค่าทำก่อน
- watchdog คืออะไร ต่างจาก fail-safe ที่เราทำอย่างไร
- ชิ้นส่วนไหนในระบบของเราจะเสียก่อน และเพราะอะไร

> **จดลงใบบันทึก** ตารางบำรุงรักษา: ใครดูแล บ่อยแค่ไหน ดูอะไร สำหรับเซนเซอร์ สวิตช์ลูกลอย ปั๊มและท่อ รีเลย์ และเครือข่าย

### สาธิต: ตู้ควบคุมปั๊ม Auto / Off / Manual

ผู้สอนต่อตู้ควบคุมจริงเข้าชุดอุปกรณ์ของผู้สอน แล้วบิดสวิตช์ขณะ automation ทำงานอยู่ ดูว่าปั๊มฟังใคร

![ตู้ควบคุมปั๊มน้ำจริง เห็นสวิตช์เลือกสามตำแหน่ง Auto Off Manual และหลอดไฟแสดงสถานะ](images/placeholder.png){ width="50%" }

| ตำแหน่ง | ใครสั่งปั๊ม | ใช้เมื่อไร |
|---------|-------------|------------|
| **Auto** | ตัวควบคุม | ทำงานปกติ |
| **Off** | ไม่มีใคร ปั๊มเดินไม่ได้ | ซ่อมบำรุง เจอน้ำรั่ว |
| **Manual** | คน โดยไม่ผ่านตัวควบคุม | เซนเซอร์เสีย เครือข่ายล่ม แต่พืชยังต้องการน้ำ |

> สวิตช์นี้คือคำตอบส่วนหนึ่งของคำถาม Recorder ในกิจกรรมที่ 6 ชั้นป้องกันที่ไม่ขึ้นกับ Logic เลย เช่นเดียวกับสวิตช์ลูกลอยในฟาร์มจริง ซึ่งมักต่อสายตัดไฟปั๊มโดยตรง ไม่ต้องผ่านคอนโทรลเลอร์

### สิ่งที่เราได้เรียนรู้

1. **automation = trigger + condition + action** และการทดสอบต้องทำให้ค่า **ข้าม** เกณฑ์จริง
2. **hysteresis คือกฎสองข้อที่มีเกณฑ์ต่างกัน** ไม่มีมันหลอดไฟจะกะพริบและปั๊มจะกระตุก บทเรียนนี้ใช้กับ Output ทุกชนิด
3. **ระบบล้มเหลวได้จากทุกจุด** เซนเซอร์ เครือข่าย หรือตัว Logic เอง และ Output จะค้างอยู่ในคำสั่งสุดท้าย
4. **fail-safe ต้องพาระบบไปสู่สถานะปลอดภัย** ไม่ใช่แค่แจ้งเตือน และควรมีชั้นที่ไม่ขึ้นกับ Logic หลัก
5. **ระบบต้องมีคนดูแล** ใครตรวจอะไรบ่อยแค่ไหน ต้องเขียนไว้ตั้งแต่ตอนออกแบบ
