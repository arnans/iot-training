1. Board firmware — six images

One image per board type, per zone colour. The zone colour is baked in: a red-zone image only joins the red SSID. Built and verified 12 Sep 2026.

Board Red zone Green zone Blue zone
GoGo-IoT sensor board (ESP32-C3) gogo-iot-red.factory.bin gogo-iot-green.factory.bin gogo-iot-blue.factory.bin
Relay board (ESP32-C6-Relay_X1) gogo-relay-red.factory.bin gogo-relay-green.factory.bin gogo-relay-blue.factory.bin

To flash a board: plug it into a laptop over USB-C, open https://web.esphome.io in Chrome or Edge → Connect → pick the serial port → Install → choose the .bin for that board and zone. Needs internet.

The colour on the board must match the colour on the kit and on the team card. A mismatched board joins the wrong WiFi and the team's Home Assistant never sees it. The board says which it is — its name reads gogo-iot-red-a1b2c3.

Spare boards flashed during the workshop must be flashed to that table's zone colour.

6. Running the activities

Each activity in the worksheet opens with a checklist for the group, ใบงาน: one item per sub-section, holding the question and its answer boxes, with a link down to the steps. This section follows the same items, so a TA looking at a team's screen can find the matching entry here. Each item gives Done when (what a finished answer looks like) and If stuck (what to check first). Minutes are the design estimate, not a rehearsed timing.

How to run it. Project the checklist and talk through it one item at a time; teams work down it while you talk. The prose under each item is for the team that falls behind or wants the reason.

The question added with the checklists, s2.fs.none, the two from the Activity 5 pilot, s2.time.trace and s2.time.why, and the Session 1 lighting keys (s1.light.on, s1.rule.dark.*, s1.rule.bright.*, s1.auto.pass, s1.timer.at, s1.timer.ok) are on the record sheet like every other answer. Session 1 no longer records the supply voltage, the wired-right-first-time self-report, the control-box position or the manual-round counts (Roger, 15 Sep 2026).

Session 1 · Activity 1 — Sense (35 min)

Teams leave with the sensor board's name and IP, a first reading of every sensor from the board's own web page, and a sense that the float is a yes/no sensor. No Home Assistant yet.

1.1 Plug in the float switch

Done when the float's Grove lead is in port 1, the board is on the laptop's USB, and the float is floating in the glass.

If stuck A float in any other port never changes state; only port 1 is configured.

1.2 Read the board's name and IP

Done when a name like gogo-iot-red-a1b2c3 is written down whose colour matches the team card, with an IP under it. The IP line appears 10–20 seconds after the name.

If stuck The log is blank or the name has scrolled past: press Reset device in the web page. Unplugging the cable or pressing the board's button drops the browser's connection. Firefox cannot connect, so use Chrome or Edge. A name but no IP within a minute: the board cannot join WiFi. Check the colour, and swap the board if it is wrong.

1.3 Open the board's web page

Done when http://<IP> shows the list of entities, updating without a refresh.

If stuck The laptop is not on farm-laptop-<colour> for the board's colour. The page lives on the board, not on the internet.

1.4 What each sensor measures

Done when each row has a room value and a test value that visibly differs from it: humidity rises when breathed on, light drops when covered, vibration rises from a few mg at rest when the table is knocked. The float reads ON floating and OFF lifted. The light and humidity values change within about one to two seconds, because the board reads them once a second. Session 2 uses the room and covered light numbers to set its thresholds.

If stuck Humidity barely moves: breathe slowly for the full five seconds, close to the board. The float never changes: the lead is not in port 1.

End-of-activity question

A good answer says humidity decides watering (standing in for soil moisture on a real farm), and the float tells whether the reservoir still has enough water for the pump. It only says yes or no, not how much.

Session 1 · Activity 2 — Act (40 min)

Teams leave with the 12 V lamp circuit wired by their own hands, the relay board powered from the charge controller's USB, and the LED module lighting on command. No water in Session 1 beyond the float's glass; the pump is first wired in Session 2 (5.6).

2.1 Know the relay board

Done when every member can point at COM and NO (used) and at 7-60 Input / GND (never used) on the real board.

2.1 Read name and IP, click the relay

Done when a gogo-relay-<colour>-… name and IP are written down. The relay clicks from the web page switch and from the board's own button. The USB lead is then unplugged from the laptop, but left in the board.

If stuck Same as 1.2. The LED blinking means no WiFi; a steady LED means connected.

2.2 Charge controller parts and the relay circuit

Done when the team can find the middle pair (battery symbol, where the adapter goes), the right pair (lamp symbol, the 12 V output) and the two USB ports, and can say from the diagram why the +12 V lead goes through COM and NO while the negative lead goes straight to the lamp.

2.2 Wire it

Done when all six steps are done and a second person has checked every screw. No bare ends touch, no wire is in NC or 7-60 Input / GND, and the adapter is still unplugged.

If stuck Check for a wire on NC instead of NO (the LED is then lit whenever the relay is Off), and for the load pair and the battery pair swapped. The LED's red lead belongs on NO and the black lead on the negative row; a reversed LED stays dark but is not damaged.

2.2 Power on and light the lamp

Done when the charge controller screen shows about 12 V. The relay board lights and rejoins WiFi. The LED lights on On and darkens on Off, and its lenses point away from the GoGo-IoT board, at least 30 cm off. A lamp shining onto the light sensor makes the Activity 3 rules fight themselves.

If stuck Screen dark: unplug first, then check the adapter is on the middle pair, red to plus. Screen on but the relay board is dark: reseat its USB lead or try the other port. Relay clicks but the LED stays dark: swap the LED's two leads. The page will not open after a minute: move the relay board's USB lead to the laptop briefly to read a new IP (the relay restarts Off), then move it back.

The Auto / Off / Manual control-box talk has no worksheet item any more (removed 15 Sep 2026). If you give it, it is two minutes before the break with nothing to fill in; Session 2's debrief demo carries the idea.

End-of-activity question

A good answer says a 220 V pump needs a relay or contactor rated for the pump's AC current, including its start-up surge. It also needs 220 V-rated wiring, an enclosure and protection (breaker, RCD), and an electrician to wire it, not the team. Before the break every relay is Off and every lamp is dark.

Session 1 · Activity 3 — Logic (40 min)

Teams leave with both boards in their own Home Assistant, a light threshold they chose, and two automations, มืด-เปิดไฟ and สว่าง-ปิดไฟ on one shared threshold, passing 3 of 3. Fast teams also leave with a tested (and then disabled) ปิดไฟตามเวลา. Cut on 15 Sep 2026 to reduce reading during the live session: no history graph (Session 3 opens on it) and no "be the Logic yourself" round; 3.3 goes straight from threshold to rule sentences to the two automations.

3.1 Add both boards

Done when the representative's laptop is logged in with the credentials you project now, and both boards are added from the discovered cards with the last six characters matching the names written down. Renaming the devices is optional.

If stuck The Login page no longer loads: the VM's IP changed, so read it again from the VM window. Every team in the zone sees every card. Adding a neighbour's card looks like success, but the team then watches the neighbour's sensors and its automation drives the neighbour's lamp. Check the six characters before adding. No card at all: + Add integration → ESPHome → Add device → Setup another instance of ESPHome, then type the board name without .local.

3.2 Test the boards in Home Assistant

Done when the GoGo-IoT device page shows the same entities as the board's web page and the light value drops under a cupped hand, and the lamp toggles from the laptop and from a phone, with both screens agreeing.

If stuck The phone must be on the zone WiFi, not mobile data, and must use the IP from the VM screen, never homeassistant.local. If it still fails, skip this step and flag it to a TA; the rest of the activity does not need the phone.

3.3 Threshold, rule sentences, two automations

Done when the threshold sits roughly halfway between the open and covered readings taken now on the device page (80 and 7 → about 40), not copied from Activity 1 because the room may have changed. The two sentences read: dark, "if the light sensor is below the threshold, turn the lamp on"; bright, "if it is above, turn the lamp off". Then covering the board lights the lamp and uncovering darkens it, three rounds out of three, with nobody touching the switch. Both rules use the same threshold on purpose. The scenario is the flower-farm night light: the LED is the lamp, a cupped hand is dusk.

If stuck The value barely moves: the hand is not over the light sensor (right-hand group on the board). It never rises again: the lit LED is shining under the hand; turn it away. Covering does nothing: the reading was already below the threshold when the rule was saved. A crossing trigger needs the value to go above, then below again, so uncover, set the relay Off and cover again. The board sends a light value about once a second, so hold the cover for two seconds. Check that the trigger entity is ความสว่าง (light) and the action is the team's own relay. The lamp flickers while the hand moves slowly: that is expected with one shared threshold, tell them to cover fully and quickly; it is the opening lesson of Session 2, not a fault.

3.4 Optional: lamp off at a chosen time

Done when the lamp, switched On from the device page, goes off by itself at the minute the team chose, and the team has then switched the rule off. Left on, it fires every day at that time, including during Session 3 with the pump on the relay.

If stuck Nothing happens: the chosen time is already past, so pick a new future minute. Home Assistant runs on Asia/Bangkok time; read the laptop clock. The lamp went off early: สว่าง-ปิดไฟ fired because the sensor was covered then uncovered; start with the sensor open.

End-of-activity question

A good answer says the lamp switches on and off repeatedly, because one value is both the on and the off line, so every wobble across it fires a rule. Leave it there: Session 2 opens by measuring it and fixing it with a second threshold.

Session 2 · Activity 5 — automations and hysteresis (70 min)

Teams leave with four automations (five if they did the Session 1 timer): two watering rules on, the two garden-lamp rules and the timer off, and the pump wired for the first time. They also leave with their thresholds, two flicker counts and the written answer. Keys go into the team's JSON as s2.light.off, s2.chatter.*, s2.time.*, s2.pump_back_t, s2.hum.*, s2.q5; the on-threshold is Session 1's s1.light.on.

During the recap the lamp rules from Session 1 are live, so anyone shading the board lights the lamp. That is a free demo, not a fault.

Before start (ก่อนเริ่ม) · ~3 min

Done when the four worksheet checks are ticked (they report to the dashboard as one activity, 15 Sep 2026): Home Assistant is up, the sensor board shows values, the relay board switches the LED, and the team has agreed to leave both boards and Home Assistant on for the half-day recording. Also confirm what the worksheet no longer asks: มืด-เปิดไฟ and สว่าง-ปิดไฟ are on with the same threshold, ปิดไฟตามเวลา (if it exists) is off, and covering the board lights the lamp. Today's VM IP is read off the screen; the record sheet still has a box for it.

If stuck The lamp will not light: same as Session 1's 3.4 (no crossing yet, or the room got darker than the threshold overnight, so raise the threshold or add light).

5.1 Lamp flickers near the threshold · ~5 min

Done when the team has a one-minute count with the off rule at the same value as the on rule. It should be clearly higher than the count they get in 5.2. There is no fixed expected number: TEST-PLAN test E still owes a bench count.

If stuck A count of 0–2 means the hand is not crossing the threshold. Have one person watch the value on the device page while another finds the height where it sits at the threshold, then waver there.

5.2 Separate the on and off thresholds · ~8 min

Done when the off threshold sits above the on-threshold and below the room reading, about a quarter of the range above (82 / 6 / on 40 → off about 60). Self-check passes on all three: ≤ 2 switches in a minute, cover → on, uncover → off.

If stuck The lamp never goes off: the off threshold is above the room reading. It still flickers: widen the gap, and turn the LED so it does not shine onto the board's light sensor.

5.3 Time window · 5.4 Lamp on when the time arrives · ~12 min tests, ~5 min fix

Done when

  • Traces answer: the latest run stopped at the condition (the And if / Time box). The trigger fired but was blocked.
  • Why re-check light in And if: the time trigger fires whether or not it is dark. Without the light condition the lamp would switch on at the start time in daylight.
  • Tick: with the sensor kept covered, the lamp turns on at After and off at Before.

If stuck Traces shows no new run at all: nothing crossed. Uncover, set the relay Off, then cover again. The timed test does nothing: the chosen times are already past. Both After and the trigger's At must move to a future minute, and the same goes for Before and At on the off rule. Home Assistant runs on Asia/Bangkok time, so read the laptop clock.

5.5 Notification · ~4 min

Done when a message appears under the bell icon, bottom-left, when มืด-เปิดไฟ runs.

If stuck Covering does nothing now: the time window from 5.3 excludes the current time, so widen it. Send a notification via mobile_app is missing from the list: it only appears after a phone has logged in through the Companion app. Persistent notification is always available.

5.6 Wire the pump, set up the water · ~10 min

Done when both lamp rules and the timer are off and the relay is Off before any screw is touched; the LED's two leads are off the terminal block and the pump's leads sit on the same two points, + on the block terminal fed from NO, − on the negative terminal; container A is three-quarters full with the pump submerged and the float in it reading Wet; the pump has moved water A → B on a 10-second command; the hose is back in A (recirculating); and the changeover time is written down. Session 3 uses it to tell lamp commands from pump commands on the relay's history graph.

If stuck Relay clicks, pump silent: the + lead went to a terminal fed from NC, or the − lead is not on the negative terminal, or the controller's load pair is off (its load mode; tell the instructor). Pump runs with the relay Off: lead on NC. The lamp turned the relay on during the swap: a lamp rule was left enabled. Nothing watches the float yet, and the worksheet says so; the float rule is built in 6.1.

5.7 Watering rules · ~12 min

Done when the pump-on threshold sits a little above room humidity; off threshold 5–10 % above that. The pump does not start when the rule is saved. That is expected, because nothing crossed. Blowing on the board pushes humidity past the off threshold; when blowing stops and it falls back below the on threshold, the pump starts. The restart time depends on the room, and any measured number is fine.

If stuck The pump never restarts after blowing: the on-threshold is below the room reading, so the value never crosses it on the way down.

5.8 Disable a rule, run the pump by hand · ~5 min

Done when with รดน้ำ - เปิดปั๊ม disabled and dry air, the pump stays still, but the relay's device page still runs it. The Automations list ends as: รดน้ำ - เปิดปั๊ม, รดน้ำ - ปิดปั๊ม on; มืด-เปิดไฟ, สว่าง-ปิดไฟ and ปิดไฟตามเวลา off.

Check this list at every table before the break. Activity 6's sabotage rounds assume exactly this state. A lamp rule left on switches the relay whenever the room light changes, and a timer rule left on switches it off at the same minute every day. Those are the likeliest causes of a pump "running by itself" or stopping unexplained in the failure lab.

End-of-activity question · ~3 min

A good answer gives the team's own on and off light thresholds. It says that one shared value makes the output flicker whenever the reading hovers at it, and that watering applies the same fix: the off threshold is set 5–10 % above the on threshold.

Session 2 · Activity 6 — Failure lab (50 min)

Every problem runs the same three steps: the paired team sabotages, our team fixes, the paired team sabotages again. While being sabotaged, the team watches only its Home Assistant screen. Required: problems 1, 2 and 5 seen, 1 and 2 fixed and re-tested. Problems 3 and 4 when time allows. Pairing is explained live, not in the worksheet.

Before every problem

Done when both watering rules are on, both lamp rules and the timer are off, the float sits in container A reading Wet, both boards show values, and the two device pages are open in separate tabs. No float rule exists yet; problem 1 builds it.

If stuck A pump started by hand keeps running because the room never reaches the off threshold. That is expected; do not let teams change the humidity thresholds to make the pump run.

6.1 Problem 1 — water gone, pump still starts (Fail-safe 1)

Done when the sabotage (float lifted until Dry, then the pump commanded On from the board's button or the device page) runs the pump with nothing stopping it, because no rule looks at the float at all. After the fix, Fail-safe - น้ำหมด (two triggers, one condition, two actions) stops the pump within about a second, with a notification, whether started from the button or the device page, and lifting the float mid-run stops it too.

If stuck The first trigger is float → Dry (state, not numeric). The second trigger must be pump switch → On with the condition float → Dry. The watering rule's condition is float → Wet**, not "not Dry": a cut wire reads Dry and an offline board reads unavailable, and neither is Wet.

6.2 Problem 2 — pump never stops (Fail-safe 2)

Done when a pump started by hand and left alone runs on, and after the fix it stops by itself at about 30 s with a notification.

If stuck The trigger needs For 30 seconds on pump → On. After the cutoff the pump does not come back by itself; that is by design, and it is why the notification matters.

6.3 Problem 3 — sensor board off (Fail-safe 3) · when time allows

Done when the team has chosen open, close or hold, with a reason; off is the defensible choice for a pump. When the board is switched off, its entities go unavailable while the pump runs on. After the fix, the Traces page of Fail-safe - เซนเซอร์หาย shows a run when humidity went unavailable, with the Off and the notification. The 30 s cutoff often stops the pump first, because the board can take longer than that to be marked unavailable; the worksheet accepts that (15 Sep 2026), so judge by Traces, not by which rule stopped the pump.

If stuck Pulling USB does nothing because the 18650 cell keeps the board alive, so use the board's ON/OFF switch. If the pump stopped at 30 s, that was Fail-safe 2; the sensor-lost rule still counts as working when its Trace shows a run. Restart the pump before re-testing so the 30 s timer starts fresh.

6.4 Problem 4 — commanded but not running (Fail-safe 4) · when time allows

Done when with the pump lead unscrewed from NO, the relay clicks and the screen says On but no water flows. After the fix the switch turns itself off within 15 s. With the lead back, the pump runs past 15 s.

If stuck The rule cuts a pump that is running: the sensor board is not touching the pump, or ความไวตรวจจับปั๊ม is too low, so set it to high. The 15 s is deliberately shorter than Fail-safe 2 so the two rules can be told apart.

6.5 Problem 5 — laptop off WiFi

Done when the team has seen the pump run on with every fail-safe silent. There is no fix inside Home Assistant. Stop the pump with the relay board's button before turning WiFi back on: the Off that Fail-safe 2 tried to send while the link was down failed and is not retried, so waiting for a rule after reconnecting leaves the pump running. One person watches the pump; cap the run at about 40 s.

6.6 Which rule stops which problem

Done when the "no rule" answer names the laptop or Home Assistant down or off WiFi. Since 15 Sep 2026 the worksheet's table credits the 30 s cutoff with catching a float stuck floating (reads Wet with the tank empty), so that row is no longer a "no rule" case, though it still needs a person to go and look. The self-check (1, 2, 5 seen; 1, 2 fixed) is ticked.

End-of-activity question

A good answer says no: every fail-safe lives in Home Assistant, so they all stop with it. Real safety needs something that works without it: a float wired to cut pump power directly, a limit built into the board's own firmware, and a manual Auto / Off / Manual switch. The control-box demo in the debrief answers this.

Session 3 · Reading the recorded data (20 min)

Open the history

Done when History shows humidity, light and the relay switch from the start of Session 2 until now.

If stuck Check the selected time range first. A VM shutdown or restart keeps the history (the recorder stores it in its database) but leaves a gap while it was off; only a rebuilt VM has none. A team with too little data reads the instructor's projected sample or a neighbour's screen, says so in its answer, and carries on.

Three points on the graph

Done when each point has what was seen, a time, what the team was doing, and what a farm would check. Any three the team can explain are fine; graphs differ between teams.

If stuck A relay bar that is On is a command, not a running pump. Before the recorded changeover time (s2.pump_back_t), from Session 1 until 5.6, it was driving the lamp. Only vibration shows the pump actually ran.

Values the graph always gives

Done when the lowest and highest humidity since Session 2 are written down, each with its time.

The question the graph cannot answer

A good answer says there is no data from the break after Session 1 because the laptop running Home Assistant (the recorder) was closed or taken away; the board kept measuring, but nobody recorded it. A farm needs a machine that stays on, with power through the night. This feeds the power step in Activity 8.

Session 3 · Activity 7 — Dashboard (35 min)

Plan 5 · build 25 · test with someone else 5.

7.1 The user · 7.2 What they see and control

Done when one named user is chosen (owner on a phone, worker on a tablet, manager on a big screen). There are three things the user must see and two they must control, written in the user's words ("air humidity", "is the water up to the float?", "start the pump"), not entity names.

7.3 Build

Done when the four minimum cards are on the dashboard: humidity Gauge, float Tile named for the user (the worksheet suggests ระดับน้ำที่ลูกลอย), pump Tile (สั่งปั๊ม), and an Entities card listing the automations. History graph, severity colours and icons come only after that.

7.4 Someone else tries it

Done when someone who did not build the dashboard (a member of the paired team, or a teammate who took no part) answers all three questions within 30 seconds on a phone: what is the humidity, is the water up to the float, where is the pump control.

If stuck The phone must be on the zone WiFi and use the VM's IP. The new dashboard is in the left menu under the name the team gave it, not under Overview.

End-of-activity question

A good answer names the question the tester struggled with and the specific change made: moving a card up, renaming a tile, adding a colour.

Session 3 · Activity 8 — Design challenge (85 min)

Pick 5 · network 20 · power 15 · fill the canvas 30 · exchange 10 · revise 5. The design canvas itself is at the end of the team record sheet; the checklist holds the decision steps.

8.1 Pick the scenario

Done when a scenario is written down (card A–E) and the farm and its problem are written at the top of the canvas. Recommend E (a member's own farm) when one exists. C and D are advanced; teams choosing them may put the specialist parts under "not sure yet".

8.2 The network we already use

Done when the team has found ssid, name_add_mac_suffix and api in the ESPHome file, and has opened the board's page from the IP entity Home Assistant shows. There is no fixed IP in the file: the router hands it out.

8.3 Choose the farm network

Done when both links have a distance, whether the far end has power, what was eliminated and why, and what remains. The instructor models card B on screen (400 m, no mains: WiFi and Zigbee out on distance, cellular out on power; ESP-NOW, LoRa and RS-485 remain). The two canvas rows are filled from the survivors, with a reason.

If stuck The weak answer is "WiFi, because the workshop used WiFi". Ask for the distance and the power at the far end first.

The worksheet's reference table carries no range figures (cut 15 Sep 2026), so give them on screen before the elimination: WiFi about 30–50 m from the router in the open, ESP-NOW 100–200 m board to board, Zigbee 10–30 m per hop, LoRa 1–10 km, RS-485 up to about 1 km of cable, cellular wherever there is signal. General estimates; กำพล to confirm against what they teach.

8.4 If the internet goes down

Done when

  • Our system: automations yes, dashboard on the farm WiFi yes, live data from outside no, new data still logged yes.
  • Cloud-run system: automations no, farm dashboard no, live data from outside no, nothing new logged.

8.5 Home Assistant Cloud demo

Done when the answers are mobile internet and on the farm (laptop). The cloud service is only a door in; the farm's Home Assistant still decides and records.

8.6 Choose remote access for the team's farm

Done when need, method and "what is lost if the farm's internet dies" are consistent. For example, notifications only means only messages are lost; the farm keeps running. The canvas's third communication row and "where the logic runs" are filled.

The worksheet's menu has four options since 15 Sep 2026: notifications only, Home Assistant Cloud, VPN, and pushing data to a cloud platform. "Opening a door yourself" (port forwarding, DDNS, a tunnel) was cut; mention it live if a team asks, with the warning that a bad setup exposes the farm.

Question after step 1

A good answer says that with the internet down, local automations, the dashboard on the farm WiFi and logging carry on, while remote viewing and notifications stop. With Home Assistant down, automations, logging and the dashboard all stop. Only protection in the board or the wiring, and the manual switch, remain.

8.7 The supply box

Done when the screen reads about 12 V and the battery icon reads not full. A charged lead-acid battery sits at 12.7–13.0 V. The controller judges only from the voltage it measures, just like Home Assistant.

8.8 How many panels, and a battery?

Done when the table matches the answer table folded under ตรวจคำตอบ on the worksheet (Wh/day and panels only since 15 Sep 2026; the battery remarks below are talking points):

  • Sensor board: 12 Wh/day, 1 panel, battery yes. Its night is 6 Wh, which the board's 18650 covers.
  • Router + Home Assistant host: 240 Wh/day, 4 panels, battery yes, about 20 Ah at 12 V for a night.
  • Kit pump: 36 Wh/day, 1 panel, no battery if it runs in daylight.
  • Farm pump: 2,250 Wh/day, 38 of our panels, no battery. It runs direct from the panels in daylight, and the farm stores water, not electricity.
  • One night: sensor board 6 Wh; farm pump at night 2,250 Wh.

If stuck Panels are rounded up to a whole panel, and Wh per day is watts × hours (0.5 W × 24 h = 12 Wh).
