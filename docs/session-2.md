# ช่วงที่ 2 — ตรรกะควบคุมอัตโนมัติและการออกแบบ Fail-safe สำหรับฟาร์ม

**ให้โปรแกรมตัดสินใจและสั่งงานแทนเรา**

ช่วงนี้เราจะลดอาการไฟกะพริบ เพิ่มเงื่อนไขเวลา แล้วต่อปั๊มแทนหลอดไฟเพื่อทดลองกฎรดน้ำ จากนั้นจำลองปัญหาและเพิ่มกฎป้องกันความเสียหาย (fail-safe)

## ก่อนเริ่ม ให้ตรวจสอบดังนี้

- [ ] Home Assistant ยังใช้งานได้
- [ ] บอร์ดเซนเซอร์ใช้งานได้
- [ ] บอร์ดรีเลย์ใช้งานได้ สามารถเปิด–ปิดไฟ LED ได้
- [ ] เปิดบอร์ดเซนเซอร์และ Home Assistant ทิ้งไว้ตลอดช่วงนี้ เพื่อให้ Home Assistant บันทึกประวัติค่าเซนเซอร์ไว้อ่านและวิเคราะห์ในช่วงที่ 3

## กิจกรรมที่ 4 — ทบทวนส่วนประกอบของกฎอัตโนมัติ

**15 นาที**

**อุปกรณ์ที่ใช้** แล็ปท็อป

เปิดกฎ `มืด-เปิดไฟ` แล้วหาว่าเหตุการณ์ใดเริ่มกฎ ต้องตรวจเงื่อนไขอะไร และระบบจะทำอะไร

1. **Settings → Automations & scenes** กดที่ชื่อ `มืด-เปิดไฟ` ที่สร้างไว้ในช่วงที่ 1
2. หาสามส่วนบนหน้าจอ **When** · **And if** · **Then do**

| ส่วน | หน้าที่ | ตัวอย่างจากกฎช่วงที่ 1 |
|------|----------------|----------------|
| **Trigger** (When) | ทำงานเมื่อไร | ค่าความสว่างข้ามเกณฑ์ลงต่ำกว่าค่าที่ตั้ง (มืด) |
| **Condition** (And if) | ต้องผ่านเงื่อนไขใดเพิ่มเติม | ไม่มี |
| **Action** (Then do) | ให้ทำอะไร | เปิดหลอดไฟ |

**Trigger** เริ่มกฎ → **Condition** ตรวจเงื่อนไข → **Action** สั่งงาน กฎจากช่วงที่ 1 ยังไม่มี condition

> **บันทึกผล** automation ข้อแรกของเรา trigger {{f:s2.auto1.trigger|18}} action {{f:s2.auto1.action|18}} condition {{f:s2.auto1.condition|10}}

ต่อไปจะปรับกฎไฟสวน แล้วนำหลักเดียวกันไปใช้กับปั๊ม

### 5.1 สังเกตไฟกะพริบ { #a5-1 }

ใช้หลอด LED แทนไฟสวน เปิดกฎ `มืด-เปิดไฟ` และ `สว่าง-ปิดไฟ` ไว้ทั้งคู่ ขณะนี้เกณฑ์เปิดและปิดเป็นค่าเดียวกัน: {{n:s1.light.on|4}} หันหลอดออกจากเซนเซอร์ก่อนทดสอบ

1. เลื่อนมือจนค่าแสงอยู่ใกล้เกณฑ์ แล้วขยับมือขึ้นลงช้า ๆ
2. ให้สมาชิกอีกคนจับเวลา 1 นาที นับทุกครั้งที่ไฟเปลี่ยนจากติดเป็นดับหรือดับเป็นติด
3. บันทึกก่อนแก้ {{n:s2.chatter.before|3}} ครั้งใน 1 นาที

> **Chattering** คือการเปิด–ปิดถี่เมื่อค่าแกว่งข้ามเกณฑ์ไปมา ทำให้รีเลย์และอุปกรณ์สึกหรอเร็ว

[↑ กลับไปที่ใบงาน](#a5){ .ws-back }

### 5.2 แยกเกณฑ์เปิดและปิด { #a5-2 }

1. เปิดกฎ `สว่าง-ปิดไฟ` ปรับ **Above** ให้สูงกว่าเกณฑ์เปิด แต่ต่ำกว่าค่าแสงเมื่อไม่บังเซนเซอร์ เช่น เปิดต่ำกว่า 40 ปิดสูงกว่า 60 เมื่อในห้องอ่านได้ 80
2. กด **Save** แล้วขยับมือแบบเดิม 1 นาที
3. บันทึกเกณฑ์ปิด {{n:s2.light.off|4}} และจำนวนครั้งหลังแก้ {{n:s2.chatter.after|3}} ครั้ง

การเว้นระยะระหว่างเกณฑ์เปิดกับเกณฑ์ปิดเรียกว่า **hysteresis** เมื่อค่าอยู่ระหว่างสองเกณฑ์ อุปกรณ์จะคงสถานะเดิม

**ผ่านเมื่อ** ขยับมือใกล้เกณฑ์เปิดแบบเดิมแล้วไฟเปลี่ยนสถานะไม่เกิน 2 ครั้งใน 1 นาที และยังครอบให้ไฟติด–เอามือออกให้ไฟดับได้

> ถ้ายังกะพริบ ให้เพิ่มระยะห่างของเกณฑ์ ถ้าไฟไม่ติดหรือไม่ดับ ให้ตรวจว่าเกณฑ์ทั้งสองยังอยู่ระหว่างค่ามืดกับค่าสว่างที่วัดได้

[↑ กลับไปที่ใบงาน](#a5){ .ws-back }

### 5.3 จำกัดช่วงเวลาเปิดไฟ { #a5-3 }

1. เปิด `มืด-เปิดไฟ` ใน **And if** กด **+ Add condition → Time** ตั้ง **After** และ **Before** แล้วกด **Save**
2. **ทดสอบในเวลา:** ตั้งช่วงที่ครอบคลุมเวลาปัจจุบัน แล้วครอบเซนเซอร์ ไฟควรติด
3. **ทดสอบนอกเวลา:** ตั้งช่วงที่ยังมาไม่ถึง แล้วครอบเซนเซอร์ ไฟควรไม่ติด เปิด **Traces** ดูว่ากฎหยุดที่ส่วนใด

**ก่อนทดสอบแต่ละรอบ:** เอามือออก รอให้ค่าแสงสูงกว่าเกณฑ์เปิด และสั่งรีเลย์ **Off** เพื่อให้เริ่มจากสภาพเดียวกัน

> Condition ตรวจเมื่อเกิด trigger เท่านั้น การถึงช่วงเวลาที่ตั้งไว้ยังไม่ทำให้กฎเริ่มเอง

> **บันทึกผล** รอบล่าสุดใน Traces หยุดที่ส่วนใด {{f:s2.time.trace|16}}

### 5.4 ให้ไฟเปิดได้เมื่อถึงเวลา { #a5-3b }

ถ้าฟ้ามืดก่อนถึงเวลา ค่าแสงจะไม่ข้ามเกณฑ์อีก เราจึงต้องเพิ่ม trigger เวลาและตรวจว่ายังมืดอยู่

1. ใน `มืด-เปิดไฟ` เพิ่ม **When → + Add trigger → Time** ตั้ง **At** ให้ตรงกับ **After**
2. เพิ่ม **And if → + Add condition → Numeric state** เลือก **ความสว่าง (light)** ใส่เกณฑ์เปิดใน **Below** เก็บเงื่อนไขเวลาเดิมไว้
3. ใน `สว่าง-ปิดไฟ` เพิ่ม **Time trigger** ตั้ง **At** ให้ตรงกับ **Before** ของกฎเปิดไฟ แล้วบันทึกทั้งสองกฎ

**ทดสอบโดยไม่แตะเซนเซอร์**

1. สั่งรีเลย์ **Off** และครอบเซนเซอร์ให้มืดค้างไว้
2. ตั้งเวลาเปิดเป็นอีก 2 นาทีข้างหน้า และเวลาปิดช้ากว่านั้น 1 นาที แก้ **After / Before** และ **At** ให้ตรงกัน แล้วกด **Save**
3. รอดูว่าไฟติดและดับตามเวลา หากทดสอบซ้ำ ให้ตั้งเวลาใหม่ทั้งสองกฎ

> หลาย trigger หมายถึงเกิดเหตุการณ์ใดเหตุการณ์หนึ่งก็เริ่มกฎได้ แต่ condition ทุกข้อยังต้องผ่าน

> **บันทึกผล** เมื่อเพิ่ม trigger เวลาแล้ว ทำไมยังต้องตรวจค่าความสว่างในส่วน And if อีก {{f:s2.time.why|30}}

[↑ กลับไปที่ใบงาน](#a5){ .ws-back }

### 5.5 เพิ่มการแจ้งเตือน { #a5-4 }

ใน `มืด-เปิดไฟ` เพิ่ม **Action → Send a persistent notification** ใส่ข้อความ เช่น `ไฟสวนเปิดแล้ว` แล้วกด **Save** ข้อความจะอยู่ที่ไอคอนกระดิ่ง

**ทดสอบ:** ตั้งช่วง **After–Before** ให้ครอบคลุมเวลาปัจจุบัน เริ่มจากไฟดับและค่าแสงสูงกว่าเกณฑ์เปิด แล้วครอบเซนเซอร์ ไฟต้องติดและมีข้อความแจ้งเตือน

> **ทำเพิ่มเมื่อมีเวลา:** ถ้าเข้า Home Assistant ผ่านแอป Companion ไว้แล้ว ลองใช้ **Send a notification via mobile_app** เพื่อส่งข้อความไปยังโทรศัพท์

[↑ กลับไปที่ใบงาน](#a5){ .ws-back }

### 5.6 ต่อปั๊มแทนหลอดไฟ { #a5-5 }

ใช้รีเลย์ตัวเดิมควบคุมปั๊มแทนหลอดไฟ จัดภาชนะน้ำไว้คนละด้านกับแล็ปท็อป

1. **ปิดกฎไฟสวนและกฎตั้งเวลาทุกกฎ** แล้วสั่งรีเลย์ **Off** การปิดกฎไม่ได้ปิดรีเลย์ ต้องทำทั้งสองอย่าง
2. **ถอดอะแดปเตอร์ออกจากปลั๊ก** ก่อนแก้สาย ถอดสายหลอด LED ที่เต๋าต่อสายและเก็บหลอดไว้
3. ต่อสายปั๊มแทนสายหลอด: สายบวกเข้าจุดที่มาจาก **NO** และสายลบเข้าจุดลบ ขันสกรูให้แน่น ไม่มีสายเข้า **NC**
4. วางภาชนะ A และ B บนถาด เติมน้ำใน A ให้ปั๊มจมทั้งตัว หนีบปลายสายยางไว้ใน B
5. วางลูกลอยใน A แล้วเสียบอะแดปเตอร์ รอให้บอร์ดเชื่อมต่อ หน้าอุปกรณ์ต้องแสดง **Wet**
6. สั่งปั๊ม **On** ประมาณ 10 วินาที แล้ว **Off** ตรวจว่าน้ำไหลจาก A ไป B และปั๊มยังจมน้ำอยู่
7. เทน้ำกลับ A แล้วย้ายและยึดปลายสายยางไว้ใน A ให้น้ำไหลวน ตรวจระดับน้ำระหว่างทดลองเสมอ
8. บันทึกเวลาที่ต่อปั๊ม {{f:s2.pump_back_t|5}} น. ใช้แยกช่วงหลอดไฟกับปั๊มเมื่ออ่านกราฟในช่วงที่ 3

> หากปั๊มไม่เดิน ให้สั่ง **Off** และถอดปลั๊กก่อนตรวจสายบวกจาก NO สายลบ และกล่องจ่ายไฟ หากปั๊มเดินทั้งที่ Off ให้ตรวจว่าเผลอต่อกับ NC หรือไม่
> **ยังไม่มีกฎตรวจลูกลอย** ต้องให้ปั๊มจมน้ำตลอด เราจะเพิ่มการป้องกันในกิจกรรมที่ 6

### 5.7 สร้างกฎรดน้ำ { #a5-5b }

**ใช้ความชื้นอากาศจำลองการรดน้ำ** เพื่อให้เป่าลมแล้วเห็นผลได้เร็ว ในฟาร์มจริงต้องเลือกค่าที่เหมาะกับพืชและพื้นที่ เช่น ความชื้นดิน

ค่าห้องที่บันทึกไว้ {{n:s1.hum.room}} % ตรวจค่าปัจจุบันอีกครั้งเพื่อใช้เลือกเกณฑ์ โดยเก็บค่าจากช่วงที่ 1 ไว้เปรียบเทียบ

1. สร้าง `รดน้ำ - เปิดปั๊ม` เลือก **Trigger → Entity → Numeric state → ความชื้นอากาศ** ตั้ง **Below** สูงกว่าค่าห้องเล็กน้อย และ **Action → Switch → Turn on** รีเลย์ของกลุ่ม
2. สร้าง `รดน้ำ - ปิดปั๊ม` ด้วยวิธีเดียวกัน ตั้ง **Above** สูงกว่าเกณฑ์เปิด 5–10 จุดเปอร์เซ็นต์ และ **Action → Switch → Turn off** บันทึกทั้งสองกฎ
3. สั่งปั๊ม **On** จากหน้าอุปกรณ์ เป่าลมจนความชื้นสูงกว่าเกณฑ์ปิด ปั๊มต้องหยุด
4. หยุดเป่าและจับเวลา รอให้ค่าลดต่ำกว่าเกณฑ์เปิด ปั๊มต้องกลับมาเดิน ถ้าค่าไม่ข้ามเกณฑ์ ให้ปรับเกณฑ์ให้อยู่ในช่วงที่ทดลองได้

> **บันทึกผล** เกณฑ์ความชื้นอากาศ เปิดปั๊มเมื่อต่ำกว่า {{n:s2.hum.on|4}} % ปิดปั๊มเมื่อสูงกว่า {{n:s2.hum.off|4}} % · หยุดเป่าแล้วปั๊มกลับมาเดินใน {{n:s2.hum.restart|3}} วินาที

### 5.8 หยุดกฎและสั่งปั๊มด้วยมือ { #a5-6 }

**สวิตช์ของกฎ** ใช้เปิด–ปิดการทำงานอัตโนมัติ ส่วน **สวิตช์รีเลย์** ใช้สั่งปั๊ม หากกฎยังเปิดอยู่ กฎอาจสั่งงานแทรกหลังเรากดสวิตช์ได้

1. ปิดกฎ `รดน้ำ - เปิดปั๊ม` และสั่งรีเลย์ **Off** เป่าลมให้ความชื้นสูงกว่าเกณฑ์เปิด แล้วหยุดเป่า เมื่อค่าลดข้ามเกณฑ์ ปั๊มต้องไม่เริ่มเอง
2. สั่งรีเลย์ **On** แล้ว **Off** ปั๊มต้องเดินและหยุดตามคำสั่ง
3. เปิดกฎ `รดน้ำ - เปิดปั๊ม` กลับ ก่อนทำกิจกรรมถัดไปให้ **กฎรดน้ำสองกฎเปิด** และ **กฎไฟสวนกับกฎตั้งเวลาปิด**

> ช่วงที่ 3 จะรวมสวิตช์เหล่านี้ไว้บนแดชบอร์ด

### ก่อนจำลองปัญหาทุกข้อ { #a6-0 }

- กฎรดน้ำเปิด กฎไฟสวนและกฎตั้งเวลาปิด
- ปั๊มจมน้ำ สายยางยึดไว้ใน A ลูกลอยแสดง **Wet**
- บอร์ดทั้งสองแสดงค่าปัจจุบัน เปิดหน้าอุปกรณ์ไว้คนละแท็บ
- ใช้ปุ่มสั่งปั๊มในการทดสอบ ไม่ต้องเปลี่ยนเกณฑ์ความชื้น

### 6.1 น้ำต่ำแต่ปั๊มยังเดิน { #a6-1 }

**จำลอง:** ยกลูกลอยพ้นน้ำ รอให้แสดง **Dry** แล้วสั่งปั๊ม On โดยให้ตัวปั๊มจมน้ำตามเดิม

**สังเกต:** ปั๊มยังเดิน เพราะกฎเดิมดูความชื้นแต่ไม่ตรวจระดับน้ำ จากนั้นสั่ง Off ก่อนแก้กฎ

**เพิ่มกฎ:** หยุดปั๊มเมื่อน้ำต่ำ และหยุดด้วยหากมีคนสั่ง On ขณะน้ำต่ำ

1. สร้างกฎใหม่ เพิ่ม **Trigger → Entity → State** เลือกลูกลอย **To: Dry**
2. เพิ่ม trigger อีกข้อ เลือกสวิตช์รีเลย์ **To: On**
3. เพิ่ม **Condition → Entity → State** เลือกลูกลอย **Dry**
4. เพิ่ม **Action → Switch → Turn off** รีเลย์ และ **Send a persistent notification** ข้อความ `น้ำในถังต่ำ หยุดปั๊มแล้ว` บันทึกชื่อ `Fail-safe - น้ำหมด`
5. เปิดกฎ `รดน้ำ - เปิดปั๊ม` เพิ่ม condition ให้ลูกลอยเป็น **Wet** ก่อนเริ่มปั๊ม แล้วบันทึก

**ทดสอบให้ผ่านทั้งสองแบบ**

- ลูกลอยเป็น Dry แล้วสั่ง On ทั้งจากปุ่มบนบอร์ดและหน้าอุปกรณ์ ปั๊มต้องหยุดและมีแจ้งเตือน
- ลูกลอยเป็น Wet สั่งปั๊มเดิน แล้วยกลูกลอยให้เป็น Dry ปั๊มต้องหยุดเช่นกัน

วางลูกลอยกลับในน้ำ การกลับเป็น Wet อย่างเดียวไม่ได้สั่งปั๊มให้เริ่มใหม่

> **บันทึกผล** จำลองปัญหาสำเร็จหรือไม่ {{r:s2.sab.1.ok|สำเร็จ|ไม่สำเร็จ}} · เกิดอะไรขึ้น {{f:s2.sab.1.what|24}}
>
> แก้ได้แล้วหรือไม่ {{r:s2.sab.1.fixed|แก้ได้|ยังไม่ได้}} · หมายเหตุ {{f:s2.sab.1.note|24}}

> กฎเปิดปั๊มต้องเห็น **Wet** จึงจะเริ่มได้ ถ้าสายลูกลอยหลุดจะอ่าน Dry ถ้าบอร์ดขาดการเชื่อมต่อจะเป็น unavailable ทั้งสองกรณีไม่ผ่านเงื่อนไข

[↑ กลับไปที่ใบงาน](#a6){ .ws-back }

### 6.2 ปั๊มเดินนานเกินไป { #a6-2 }

**จำลอง:** สั่งปั๊ม On รอ 1 นาทีโดยรักษาความชื้นให้คงที่และดูระดับน้ำ

**สังเกต:** ปั๊มยังเดิน เพราะความชื้นไม่ข้ามเกณฑ์ปิด สั่ง Off ก่อนสร้างกฎ

**วิธีแก้**

1. สร้าง automation ชื่อ `Fail-safe - จำกัดเวลาเปิดปั๊ม`
2. Trigger: **Entity → State** เลือกสวิตช์ปั๊ม ช่อง **To** เลือก **On** ช่อง **For** ตั้ง **30 วินาที** (ใช้สำหรับการทดลองนี้)
3. Action: **Switch → Turn off** สวิตช์ปั๊ม และแจ้งเตือน `ปั๊มเดินเกินเวลา ตัดการทำงานแล้ว โปรดตรวจสอบ`

**ถือว่าแก้ได้เมื่อ** กดปุ่มให้ปั๊มเดินอีกครั้ง ปั๊มต้องหยุดเองที่ราว 30 วินาที พร้อมข้อความแจ้งเตือน

> **บันทึกผล** จำลองปัญหาสำเร็จหรือไม่ {{r:s2.sab.2.ok|สำเร็จ|ไม่สำเร็จ}} · เกิดอะไรขึ้น {{f:s2.sab.2.what|24}}
>
> แก้ได้แล้วหรือไม่ {{r:s2.sab.2.fixed|แก้ได้|ยังไม่ได้}} · หมายเหตุ {{f:s2.sab.2.note|24}}

> เมื่อตัดปั๊มแล้ว ให้ตรวจสาเหตุก่อนเริ่มใหม่ กฎรดน้ำจะเริ่มอีกครั้งเมื่อความชื้นข้ามเกณฑ์เปิด ไม่ใช่ทันทีที่ปัญหาหมดไป

### 6.3 บอร์ดเซนเซอร์ดับ — ทำเพิ่ม { #a6-3 }

![ตำแหน่งสวิตช์ ON/OFF ทางซ้ายของบอร์ด GoGo-IoT ใกล้ช่อง USB-C และกลุ่มเซนเซอร์ทางขวา](images/gogo-iot-main-parts.png){ width="100%" }

ใช้สวิตช์ **ON / OFF** ปิดบอร์ด ไม่ใช่ปุ่ม BOOT การถอด USB อย่างเดียวอาจไม่ดับเพราะมีถ่านในบอร์ด

**จำลอง:** สั่งปั๊ม On แล้วปิดสวิตช์ GoGo-IoT ดูว่าเมื่อใดค่าความชื้นเปลี่ยนเป็น **unavailable** และปั๊มหยุดด้วยกฎใด จากนั้นเปิดบอร์ดกลับ

> กฎจำกัดเวลาอาจหยุดปั๊มก่อนระบบตรวจพบว่าบอร์ดหาย ให้ดูชื่อกฎในแจ้งเตือนหรือ **Traces** อย่าตัดสินจากการหยุดของปั๊มอย่างเดียว

**อภิปรายก่อนสร้างกฎ:** หากไม่ได้รับค่าความชื้น กลุ่มคิดว่าปั๊มควรเปิด ปิด หรือคงสถานะเดิม เพราะอะไร

> **บันทึกผล** กลุ่มเลือกให้ปั๊ม {{r:s2.fs3.choice|เปิด|ปิด|คงสถานะเดิม}} เพราะ {{f:s2.fs3.why|30}}

**กฎตัวอย่างนี้เลือกหยุดปั๊ม** เพื่อป้องกันการสูบน้ำต่อโดยไม่มีข้อมูล

1. สร้าง automation ชื่อ `Fail-safe - เซนเซอร์หาย`
2. Trigger: **Entity → State** เลือกความชื้นอากาศ ช่อง **To** พิมพ์ `unavailable` แล้วเพิ่ม trigger อีกอันแบบเดียวกันแต่ To เป็น `unknown`
3. Action: **Switch → Turn off** สวิตช์ปั๊ม และแจ้งเตือน `ไม่ได้รับค่าจากเซนเซอร์ หยุดปั๊มเพื่อความปลอดภัย`

**ทดสอบซ้ำ:** รอให้บอร์ดกลับมาแสดงค่า แล้วสั่งปั๊ม On และปิดบอร์ดอีกครั้ง ตรวจใน **Traces** ว่ากฎ `Fail-safe - เซนเซอร์หาย` ทำงานเมื่อค่าเป็น unavailable และสั่ง Off พร้อมแจ้งเตือน แม้กฎจำกัดเวลาจะหยุดปั๊มไปก่อน จากนั้นเปิดบอร์ดกลับ

> **บันทึกผล** จำลองปัญหาสำเร็จหรือไม่ {{r:s2.sab.3.ok|สำเร็จ|ไม่สำเร็จ}} · เกิดอะไรขึ้น {{f:s2.sab.3.what|24}}
>
> แก้ได้แล้วหรือไม่ {{r:s2.sab.3.fixed|แก้ได้|ยังไม่ได้}} · หมายเหตุ {{f:s2.sab.3.note|24}}

### 6.4 สั่งแล้วปั๊มไม่เดิน — ทำเพิ่ม { #a6-4 }

**เตรียมก่อนจำลอง:** วางบอร์ด GoGo-IoT ในจุดแห้งที่รับแรงสั่นจากปั๊มหรือท่อได้ **ห้ามจุ่มบอร์ดลงน้ำ** ลองสั่ง On–Off ตรวจว่า `ปั๊มกำลังทำงาน` เปลี่ยนตาม หากไม่เปลี่ยน ให้ขยับตำแหน่งหรือเพิ่ม **ความไวตรวจจับปั๊ม**

**จำลอง:** สั่ง Off และถอดปลั๊กอะแดปเตอร์ก่อนถอดสายปั๊มที่จุดต่อจาก NO เก็บปลายสายไม่ให้แตะขั้วอื่น เสียบปลั๊ก รอให้บอร์ดเชื่อมต่อ แล้วสั่ง On

**สังเกต:** รีเลย์เป็น On แต่ปั๊มไม่เดินและน้ำไม่ไหล สถานะรีเลย์ยืนยันได้เพียงว่าสวิตช์เปิดอยู่

**เพิ่มกฎ:** ตรวจแรงสั่นหลังสั่งเปิดปั๊ม หากไม่พบให้หยุดและแจ้งเตือน การสั่นเป็นหลักฐานประกอบ ไม่ได้ยืนยันว่าน้ำไหลถึงแปลง

| entity | บอกอะไร |
|---|---|
| `ความสั่นสะเทือน (vibration)` | ความแรงของการสั่น หน่วย **mg** (มิลลิจี) |
| `ปั๊มกำลังทำงาน (pump running)` | ผลการตรวจจับ เดิน / ไม่เดิน |

1. สร้าง automation ชื่อ `Fail-safe - สั่งแล้วไม่เดิน`
2. Trigger: **Entity → State** เลือกสวิตช์ปั๊ม ช่อง **To** ใส่ `On` ช่อง **For** ใส่ **15 วินาที** (ก่อนกฎจำกัดเวลา 30 วินาที)
3. Condition: **Entity → State** เลือก `ปั๊มกำลังทำงาน` สถานะ **Off**
4. Action: **Switch → Turn off** สวิตช์ปั๊ม และแจ้งเตือน `สั่งปั๊มแล้วแต่ไม่มีการสั่น ตรวจสายและระดับน้ำ`

**ทดสอบซ้ำ:** เมื่อสายยังถอดอยู่ สั่ง On กฎต้องปิดรีเลย์และแจ้งเตือนหลังครบประมาณ 15 วินาที

**คืนสภาพ:** สั่ง Off ถอดปลั๊ก แล้วต่อสายกลับ ขันให้แน่น เสียบปลั๊กและรอให้บอร์ดพร้อม สั่ง On อีกครั้ง ปั๊มต้องเดินผ่าน 15 วินาทีได้ ถ้าถูกตัด ให้ตรวจตำแหน่งบอร์ดและความไว

> **บันทึกผล** จำลองปัญหาสำเร็จหรือไม่ {{r:s2.sab.4.ok|สำเร็จ|ไม่สำเร็จ}} · เกิดอะไรขึ้น {{f:s2.sab.4.what|24}}
>
> แก้ได้แล้วหรือไม่ {{r:s2.sab.4.fixed|แก้ได้|ยังไม่ได้}} · หมายเหตุ {{f:s2.sab.4.note|24}}

### 6.5 แล็ปท็อปหลุดจาก WiFi { #a6-5 }

**จำลอง:** สั่งปั๊ม On แล้วปิด WiFi ของแล็ปท็อปที่เปิด Home Assistant รอดูไม่เกิน 40 วินาที โดยมีคนเฝ้าปั๊ม

**สังเกต:** Home Assistant ติดต่อบอร์ดไม่ได้ แต่ปั๊มอาจยังเดินตามคำสั่งล่าสุด กฎที่อยู่บนแล็ปท็อปส่งคำสั่งไปหยุดไม่ได้

**หยุดและคืนสภาพ:** กดปุ่มบนบอร์ดรีเลย์ให้ปั๊มหยุด เปิด WiFi กลับ รอให้บอร์ดแสดงค่า และตรวจรีเลย์เป็น Off **อย่ารอให้กฎหยุดปั๊มเองหลังเชื่อมต่อกลับ**

กฎบน Home Assistant แก้การขาดการเชื่อมต่อนี้ไม่ได้ ต้องมีวิธีหยุดที่ตัวบอร์ดหรือวงจรควบคุม บันทึกข้อจำกัดนี้ไว้ในช่องหมายเหตุ

>
> แก้ได้แล้วหรือไม่ {{r:s2.sab.5.fixed|แก้ได้|ยังไม่ได้}} · หมายเหตุ {{f:s2.sab.5.note|24}}

### สาธิต: ตู้ควบคุมปั๊ม Auto / Off / Manual

ดูผู้สอนสลับ **Auto / Off / Manual** แล้วสังเกตว่าแต่ละโหมดให้ใครสั่งปั๊ม

| ตำแหน่ง | ใครสั่งปั๊ม | ใช้เมื่อไร |
|---------|-------------|------------|
| **Auto** | ระบบควบคุมอัตโนมัติของชุดสาธิต | ทำงานตามกฎ |
| **Off** | หยุดคำสั่งเดินปั๊ม | หยุดใช้งาน; ก่อนซ่อมต้องตัดแหล่งจ่ายไฟด้วย |
| **Manual** | คนผ่านสวิตช์ที่ตู้ | สั่งงานในพื้นที่เมื่อระบบอัตโนมัติขัดข้อง |

> การหยุดปั๊มจากตู้ช่วยให้คนควบคุมได้แม้ Home Assistant ใช้งานไม่ได้ การป้องกันด้วยวงจรต้องออกแบบและติดตั้งให้เหมาะกับปั๊มจริง

### สิ่งที่เราได้เรียนรู้

1. **automation = trigger + condition + action** และการทดสอบต้องทำให้ค่า **ข้าม** เกณฑ์จริง
2. **ใช้ hysteresis ลดการเปิด–ปิดถี่** กำหนดเกณฑ์เปิดและปิดให้ต่างกัน หลักนี้นำไปใช้ได้ทั้งกับหลอดไฟ ปั๊ม และอุปกรณ์อื่น
3. **ปัญหาเกิดได้ทั้งที่เซนเซอร์ เครือข่าย และระบบควบคุม** ในชุดทดลองนี้ เมื่อส่งคำสั่งใหม่ไม่ได้ ปั๊มจะคงสถานะตามคำสั่งล่าสุด
4. **fail-safe ต้องช่วยป้องกันความเสียหายได้จริง** นอกจากแจ้งเตือนแล้ว ต้องทำให้ระบบหยุดหรือทำงานในลักษณะที่ปลอดภัย และควรมีการป้องกันที่ทำงานได้แม้ระบบควบคุมหลักขัดข้อง
5. **กำหนดผู้ดูแลตั้งแต่เริ่มออกแบบ** ระบุให้ชัดว่าใครตรวจอะไร และต้องตรวจบ่อยเพียงใด
