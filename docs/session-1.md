# ช่วงที่ 1 — ระบบสมองกลฝังตัวในฟาร์ม: รับรู้ ตัดสินใจ สั่งการ

**Input → Logic → Output**

ช่วงนี้เราเริ่มจากอุปกรณ์ก่อน คุยกับบอร์ดเซนเซอร์และบอร์ดรีเลย์โดยตรงผ่านหน้าเว็บของบอร์ดเอง ต่อไฟและปั๊มด้วยมือ แล้วค่อยเอาทั้งสองบอร์ดมารวมกันใน Home Assistant ปลายช่วงเราจะเป็น Logic เองสักครู่ แล้วเขียน automation ข้อแรกให้ระบบตัดสินใจแทน

> **เมื่อจบช่วงนี้** เราจะอ่านค่าเซนเซอร์ทุกตัวได้ สั่งปั๊มน้ำได้จากแล็ปท็อปและโทรศัพท์ และมี automation หนึ่งข้อที่หยุดปั๊มเองเมื่อน้ำในถังหมด


## ก่อนเริ่ม

Home Assistant ทำงานอยู่บนแล็ปท็อปของทีมเอง ในโปรแกรม VirtualBox ที่นำเข้าไฟล์ที่ส่งให้ล่วงหน้า ตรวจสี่อย่างนี้ก่อนรับอุปกรณ์

- [ ] ดูบัตรประจำทีมว่าทีมเราอยู่ **โซนสีอะไร** (แดง / เขียว / น้ำเงิน) ทุกอย่างของทีมจะใช้สีนี้
- [ ] ต่อแล็ปท็อปเข้า WiFi **ของโซนเรา** ชื่อ `farm-laptop-สี` ตามบัตรประจำทีม ไม่ใช่ WiFi ทั่วไปของสถานที่
- [ ] เปิด VirtualBox กด **Start** ที่เครื่อง Farm Workshop รอจนหน้าจอแสดงที่อยู่ แล้วเปิด `http://homeassistant.local` ในเบราว์เซอร์ เข้าระบบด้วยชื่อผู้ใช้และรหัสบนบัตร เห็นหน้า **Overview** แล้ว **ปล่อยทิ้งไว้** เราจะกลับมาใช้ในกิจกรรมที่ 3
- [ ] แบ่งบทบาท และเขียนชื่อลงตารางในใบบันทึก

![หน้า Overview ของ Home Assistant บนแล็ปท็อป หลังเข้าระบบ เมนูด้านซ้ายมี Overview, History, Settings](images/placeholder.png){ width="60%" }

> หน้าจอตั้งเป็นภาษาอังกฤษไว้ เพื่อให้ชื่อเมนูตรงกับใบงานนี้ ถ้า Home Assistant เปิดไม่ขึ้น ให้ยกมือ **ตอนนี้** แม้เราจะยังไม่ใช้จนถึงกิจกรรมที่ 3 เพราะการแก้ใช้เวลา และกิจกรรมที่ 1–2 ทำต่อไปได้โดยไม่ต้องรอ

## กิจกรรมที่ 1 — Sense

**35 นาที** · บอร์ด GoGo-IoT, สวิตช์ลูกลอยพร้อมตัวแปลงและสาย Grove, แก้วน้ำ, สาย USB-C, แล็ปท็อป

อ่านค่าจากบอร์ดเซนเซอร์ของทีมผ่านหน้าเว็บของบอร์ดเอง แล้วหาว่าเซนเซอร์แต่ละตัววัดอะไร และตัวไหนที่เราจะใช้ตัดสินใจ

### รู้จักบอร์ด GoGo-IoT

บอร์ดตัวนี้มีคอนโทรลเลอร์ ESP32-C3 และเซนเซอร์ในตัวห้าอย่าง คือ **อุณหภูมิ ความชื้นอากาศ แสง ความกดอากาศ และความเร่ง** นอกจากนั้นมีช่องต่อเซนเซอร์เพิ่มแบบ Grove เราจะต่อ **สวิตช์ลูกลอย** เข้าที่ **ช่อง 1** ซึ่งตั้งค่าไว้แล้วให้อ่านเป็นสัญญาณดิจิทัล

![บอร์ด GoGo-IoT มีกรอบชี้ตำแหน่งเซนเซอร์ในตัว ช่อง Grove หมายเลข 1 ช่อง USB-C และช่องใส่ถ่าน 18650](images/placeholder.png){ width="55%" }

1. **Hardware** เสียบสาย Grove จากตัวแปลงของสวิตช์ลูกลอยเข้า **ช่อง 1** บนบอร์ด
2. เสียบสาย USB-C เข้าบอร์ด แล้วเสียบอีกปลายเข้าช่อง USB ของแล็ปท็อป
3. วางสวิตช์ลูกลอยลงแก้วน้ำที่มีน้ำครึ่งแก้ว ให้ลูกลอยลอยขึ้น

### อ่านชื่อและหมายเลข IP ของบอร์ด

บอร์ดทุกตัวในห้องใช้เฟิร์มแวร์ตัวเดียวกัน แต่ละตัวจึงตั้งชื่อตัวเองจากหมายเลขประจำเครื่อง ทำให้ชื่อไม่ซ้ำกัน และเมื่อต่อ WiFi ได้ บอร์ดจะได้รับ **หมายเลข IP** หนึ่งหมายเลข เราอ่านทั้งสองอย่างจากบอร์ดครั้งเดียว แล้วใช้ไปตลอด

1. **Driver** เปิด **Chrome** หรือ **Edge** ไปที่ **web.esphome.io** (Firefox ใช้ไม่ได้)
2. กด **Connect** เลือกพอร์ตที่ปรากฏขึ้น แล้วกดยืนยัน
3. กด **Logs & Console** แล้วกดปุ่ม **Reset device** ในหน้าเว็บ (ไม่ใช่ปุ่มบนบอร์ด) บอร์ดจะเริ่มใหม่และพิมพ์สองบรรทัดในกรอบ: `=====  DEVICE NAME: ...  =====` ในบรรทัดแรก ๆ หน้าตาแบบ `gogo-iot-red-a1b2c3` และ `=====  IP ADDRESS: ...  =====` หลังต่อ WiFi ได้ ราว 10–20 วินาทีต่อมา
4. **ตรวจสี** คำกลางในชื่อ (`red` / `green` / `blue`) ต้องตรงกับสีโซนของทีมเรา ถ้าไม่ตรง บอร์ดนี้จะไม่เห็น WiFi ของเรา ให้ยกมือขอเปลี่ยนบอร์ด
5. **จดชื่อและหมายเลข IP ลงใบบันทึก** แล้วปิดหน้าต่างนี้

![หน้าจอ web.esphome.io หลังกด Connect และกดปุ่ม Reset device ในหน้าเว็บ แสดง log ของบอร์ด มีกรอบเน้นแถบ DEVICE NAME และแถบ IP ADDRESS และกรอบเน้นปุ่ม Reset device ที่มุมล่างขวา](images/placeholder.png){ width="60%" }

> ถ้าหน้าต่าง log ว่างเปล่า หรือชื่อเลื่อนผ่านไปแล้ว ให้กดปุ่ม **Reset device** ในหน้าเว็บอีกครั้ง **อย่าถอดสาย USB และอย่ากดปุ่มบนบอร์ด** สองอย่างนั้นจะตัดการเชื่อมต่อของเบราว์เซอร์ และชื่อจะไม่ขึ้น
> ถ้าเห็นชื่อแต่ไม่เห็นหมายเลข IP ภายในหนึ่งนาที แปลว่าบอร์ดต่อ WiFi ไม่ได้ ตรวจสีในชื่ออีกครั้ง แล้วยกมือ

### เปิดหน้าเว็บของบอร์ด

บอร์ดตัวนี้เป็นเว็บเซิร์ฟเวอร์เล็ก ๆ ในตัว ใครก็ตามที่อยู่บน WiFi โซนเดียวกันเปิดดูค่าได้โดยตรง ไม่ต้องผ่านโปรแกรมอะไรทั้งสิ้น

1. **Driver** เปิดแท็บใหม่ พิมพ์ `http://` ตามด้วยหมายเลข IP ที่จดไว้ เช่น `http://192.168.10.57`
2. จะเห็นรายการค่าจากบอร์ด แต่ละบรรทัดคือหนึ่ง **entity** ค่าขยับเองโดยไม่ต้องรีเฟรช สังเกตว่าสวิตช์ลูกลอยไม่ได้แสดงเป็นตัวเลข แต่แสดงเป็นสถานะสองอย่าง

![หน้าเว็บของบอร์ด GoGo-IoT ในเบราว์เซอร์ แสดงรายการ entity อุณหภูมิ ความชื้นอากาศ แสง ความกดอากาศ ความเร่ง และสวิตช์ลูกลอย พร้อมค่าปัจจุบัน](images/placeholder.png){ width="60%" }

> ถ้าเปิดไม่ขึ้น ตรวจว่าแล็ปท็อปอยู่บน `farm-laptop-สีเดียวกัน` กับสีในชื่อบอร์ด เพราะหน้านี้อยู่บนตัวบอร์ด ไม่ได้อยู่บนอินเทอร์เน็ต

### หาว่าเซนเซอร์ตัวไหนวัดอะไร

**Hardware** ทำทีละอย่าง **Driver** ดูว่า entity ตัวไหนบนหน้าเว็บเปลี่ยน

| ทำอะไร | สังเกต |
|--------|--------|
| เป่าลมหายใจใส่บอร์ดช้า ๆ 5 วินาที | ความชื้นอากาศและอุณหภูมิ ขึ้นเท่าไร |
| ใช้มือครอบบอร์ดให้มืด | แสงลงเหลือเท่าไร แล้วเปิดมือ ค่ากลับมาเร็วแค่ไหน |
| เอียงบอร์ดไปมา | ความเร่งแกนไหนเปลี่ยน |
| ยกสวิตช์ลูกลอยขึ้นจากน้ำ แล้ววางกลับ | สถานะเปลี่ยนจากอะไรเป็นอะไร |

> **จดลงใบบันทึก** ค่าความชื้นอากาศปกติในห้องและตอนเป่า · ค่าแสงปกติและตอนครอบ · สถานะสวิตช์ลูกลอยตอนลอยและตอนยก ในช่วงที่ 2 เราจะใช้ค่าเหล่านี้ตั้งเกณฑ์

ครอบบอร์ดอีกครั้ง แล้วนับว่าค่าแสงบนหน้าเว็บเปลี่ยนภายในกี่วินาที บอร์ดส่งค่าใหม่เป็นระยะ ไม่ใช่ทันที **จดตัวเลขนี้ไว้** มันจะสำคัญในช่วงที่ 2

> สวิตช์ลูกลอยไม่ได้บอกว่าน้ำมีเท่าไร บอกได้อย่างเดียวว่าน้ำถึงระดับนี้หรือไม่ถึง เซนเซอร์แบบนี้เรียกว่าเซนเซอร์ **ดิจิทัล** ส่วนความชื้นและแสงที่ให้ตัวเลขต่อเนื่องเรียกว่า **แอนะล็อก** ความต่างนี้จะสำคัญมากในช่วงที่ 2

**คำถามของ Recorder** ในระบบรดน้ำของเรา ค่าไหนที่จะใช้ตัดสินใจว่าต้องรดน้ำ และสวิตช์ลูกลอยมีไว้บอกอะไร

## กิจกรรมที่ 2 — Act

**40 นาที** · บอร์ดรีเลย์, ตัวควบคุมการชาร์จ, adapter 12V, สายไฟ, แผงต่อสาย, ปั๊มตู้ปลา 12V พร้อมสายยาง, ภาชนะน้ำ 2 ใบ, ถาดรอง

> **สลับบทบาทก่อนเริ่ม**

สั่งรีเลย์จากหน้าเว็บของบอร์ดก่อน โดยยังไม่มีอะไรต่ออยู่ เพื่อให้เห็นว่ารีเลย์คือสวิตช์ ไม่ใช่ปั๊ม แล้วจึงต่อไฟ 12V และปั๊มด้วยมือ นี่คือครั้งเดียวในหลักสูตรที่เราต่อสายไฟด้วยมือ ทำช้า ๆ ตามลำดับ

### ส่วน ก — รีเลย์คือสวิตช์

#### รู้จักบอร์ดรีเลย์

บอร์ดรีเลย์เป็นบอร์ดคนละตัวกับบอร์ดเซนเซอร์ มีคอนโทรลเลอร์ของตัวเอง (ESP32-C6) และมีขั้วต่อสองกลุ่ม ดูตำแหน่งขั้วต่อจากแผนภาพนี้ก่อนต่อสาย

> **สำคัญ: บอร์ดนี้รับไฟทางเดียวเท่านั้น** จะเป็นสาย USB หรือขั้วไฟเข้า 7–60V อย่างใดอย่างหนึ่ง **ห้ามต่อพร้อมกัน** เราจึงใช้ USB แค่ในส่วน ก แล้วถอดออกก่อนต่อไฟ 12V

![แผนภาพบอร์ดรีเลย์ ESP32-C6 ชี้ตำแหน่งขั้ว NO COM NC ทางซ้าย ขั้วไฟเข้า 7-60 Input และ GND ทางขวา ช่อง USB Type-C ปุ่มบนบอร์ด ไฟ LED และไฟแสดงสถานะรีเลย์](images/relay-board-terminals.png){ width="100%" }

| ป้ายบนแผนภาพ | คือ | เราใช้ทำอะไร |
|--------------|-----|--------------|
| **NO / COM / NC** | ขั้วรีเลย์ (บล็อกเขียว 3 ช่อง) | ใช้ **COM** กับ **NO** ให้ไฟ 12V ไปปั๊ม |
| **7-60 Input / GND** | ขั้วไฟเข้า (บล็อกเขียว 2 ช่อง) | รับไฟ 12V จากกล่องจ่ายไฟมาเลี้ยงบอร์ด |
| **USB Type-c** | ช่อง USB | ใช้ในส่วน ก เท่านั้น แล้วถอด |
| **Relay Indicator** | ไฟแสดงสถานะรีเลย์ | ติดเมื่อรีเลย์ทำงาน นี่คือ "หลอดไฟ" ที่เราจะดูในช่วงที่ 2 |
| **LED** | ไฟแสดงการเชื่อมต่อ | ติดค้าง = ต่อ WiFi และ Home Assistant ได้ · กะพริบ = หลุด · ดับ = ไม่มีไฟ |
| **Programmable keys** | ปุ่มบนบอร์ด | กดสั่งรีเลย์ด้วยมือได้ แม้ไม่มี Home Assistant |

#### อ่านชื่อ หมายเลข IP แล้วลองสั่งรีเลย์ (ทำก่อนต่อสายใด ๆ)

1. **Hardware** เสียบสาย USB-C จากบอร์ดรีเลย์เข้าแล็ปท็อป (ยังไม่ต่ออย่างอื่นทั้งสิ้น)
2. **Driver** ทำเหมือนกิจกรรมที่ 1: web.esphome.io → **Connect** → เลือกพอร์ต → **Logs & Console** → กด **Reset device** ในหน้าเว็บ อ่านชื่อ หน้าตาแบบ `gogo-relay-red-a1b2c3` และหมายเลข IP ตรวจว่าสีในชื่อตรงกับโซนของทีม แล้ว **จดลงใบบันทึก** ปิดหน้าต่าง
3. เปิดแท็บใหม่ไปที่ `http://` ตามด้วยหมายเลข IP ของบอร์ดรีเลย์ จะเห็น entity ชื่อ **รีเลย์ (relay)** เป็นสวิตช์
4. **Driver** กดให้เป็น On หนึ่งวินาที แล้ว Off · **Hardware** ฟังเสียงคลิก และดูไฟ **Relay Indicator** ติดดับตาม
5. **Hardware** กด **ปุ่มบนบอร์ด** หนึ่งครั้ง รีเลย์คลิกและสวิตช์บนหน้าเว็บเปลี่ยนตาม กดอีกครั้งให้กลับเป็น Off
6. **ถอดสาย USB ออกจากบอร์ด** ตั้งแต่นี้บอร์ดจะกินไฟจากกล่องจ่ายไฟอย่างเดียว

> เสียงคลิกคือหน้าสัมผัสกลไกในรีเลย์กำลังปิดและเปิดวงจร ตอนนี้ยังไม่มีอะไรต่ออยู่ที่หน้าสัมผัสนั้น จึงไม่มีอะไรเกิดขึ้นนอกจากเสียง **รีเลย์เป็นแค่สวิตช์** ตัวบอร์ดไม่ได้จ่ายไฟให้โหลด โหลดต้องมีไฟของตัวเอง ซึ่งเราจะต่อในส่วน ข

### ส่วน ข — ต่อโหลด

#### กล่องจ่ายไฟ 12V

บอร์ดรีเลย์อยู่ปลายโต๊ะฝั่งน้ำ ห่างจากแล็ปท็อป และปั๊มต้องใช้ไฟ 12V อยู่แล้ว เราจึงจ่ายไฟให้ทั้งสองอย่างจากกล่องเดียว คือ **ตัวควบคุมการชาร์จ** ที่มี adapter 12V ต่ออยู่แทนแบตเตอรี่ ตอนนี้ให้มองเป็นกล่องจ่ายไฟที่มี **ขั้วออก 12V หนึ่งคู่** (สัญลักษณ์หลอดไฟ คู่ขวาสุด) และ **ช่อง USB** เราจะเปิดดูว่าข้างในทำอะไรในช่วงที่ 3

![ตัวควบคุมการชาร์จ เน้นขั้วคู่กลาง (สัญลักษณ์แบตเตอรี่) ที่ adapter ต่อเข้า ขั้วคู่ขวา (สัญลักษณ์หลอดไฟ) ที่จ่ายไฟออก และช่อง USB](images/placeholder.png){ width="50%" }

#### ต่อสาย

**ตรวจก่อนเริ่ม: สาย USB ของบอร์ดรีเลย์ถอดออกแล้ว** และ **adapter ต้องยังไม่เสียบปลั๊กจนถึงขั้นสุดท้าย** Hardware ต่อสาย Recorder อ่านทีละข้อและตรวจว่าทำครบก่อนอ่านข้อถัดไป

1. สาย adapter 12V เข้า **คู่กลาง** (สัญลักษณ์แบตเตอรี่) ของตัวควบคุม สายแดงเข้าบวก สายดำเข้าลบ
2. จาก **คู่ขวา** (สัญลักษณ์หลอดไฟ) ของตัวควบคุม เดินสายสองเส้นไปยัง **แผงต่อสาย** บวกเข้าแถวบวก ลบเข้าแถวลบ แผงนี้คือจุดกระจายไฟ 12V ของเรา
3. จากแถวบวกไป **ขั้วไฟเข้า +** ของบอร์ดรีเลย์ จากแถวลบไป **ขั้วไฟเข้า −** สองเส้นนี้เลี้ยงตัวบอร์ด
4. จากแถวบวกอีกเส้นไป **COM** ของรีเลย์ แล้วจาก **NO** ไปยังสายบวกของปั๊ม
5. สายลบของปั๊มเข้าแถวลบของแผงต่อสาย
6. ตรวจทุกสกรูแน่น ไม่มีปลายสายเปลือยแตะกัน ไม่มีสายเข้าขั้ว **NC**

![แผนภาพการต่อสายทั้งหมด: adapter → คู่แบตเตอรี่ของตัวควบคุม · คู่โหลดของตัวควบคุม → แผงต่อสาย · แถวบวกและลบ → ขั้วไฟเข้าของบอร์ดรีเลย์ · แถวบวก → COM · NO → ปั๊ม + · ปั๊ม − → แถวลบ](images/placeholder.png){ width="65%" }

> **ทำไมตัดวงจรที่สายบวกเส้นเดียว** วงจรจะเดินได้ต้องครบวง ตัดที่จุดเดียวก็พอ และเราเลือกตัดด้านบวก เพื่อให้สายลบทุกเส้นต่อถึงกันเป็นกราวด์ร่วม นี่คือวิธีที่ตู้ควบคุมปั๊มจริงทำเช่นกัน แค่แรงดันสูงกว่า

#### เปิดไฟและสั่งปั๊ม

1. วางภาชนะสองใบบนถาดรอง เติมน้ำใบ A ค่อนใบ ใบ B ว่าง จุ่มปั๊มลงใบ A ให้จมทั้งตัว วางปลายสายยางลงใบ B แล้วหนีบไว้ ปั๊มต้องอยู่ในน้ำก่อนมีโอกาสเดิน
2. ย้ายสวิตช์ลูกลอยจากแก้วมาไว้ในใบ A ด้วย ตั้งแต่นี้ใบ A คือ **ถังน้ำต้นทาง** ของระบบ และลูกลอยคอยบอกว่าน้ำในถังยังพอหรือไม่
3. **เสียบ adapter เข้ารางปลั๊ก** จอตัวควบคุมควรติดและแสดงแรงดัน ไฟบนบอร์ดรีเลย์ควรติด รอ 30 วินาทีให้บอร์ดต่อ WiFi
4. **Driver** เปิดหน้าเว็บของบอร์ดรีเลย์อีกครั้งที่หมายเลข IP เดิม (บอร์ดจะได้หมายเลขเดิมเมื่อกลับมาต่อ WiFi)
5. กดสวิตช์เป็น On นับ 10 วินาที แล้ว Off ดูว่าน้ำไหลจาก A ไป B หรือไม่ นี่คือหลักฐานว่า Output ของเราทำงานจริง
6. **Hardware** เทน้ำจากใบ B กลับใบ A แล้ว **ย้ายปลายสายยางมาลงใบ A** ตั้งแต่นี้น้ำจะวนอยู่ในถังเดียว ปั๊มจึงเดินได้นานเท่าไรก็ได้โดยน้ำไม่หมด ใบ B ไม่ใช้อีก

> **จดลงใบบันทึก** แรงดันที่จอตัวควบคุมแสดง

> ถ้าจอตัวควบคุมไม่ติด หรือบอร์ดรีเลย์ไม่ติด ให้ถอด adapter ก่อน แล้วตรวจการต่อสายข้อ 1 ถึง 6 ใหม่ ถ้าหน้าเว็บของบอร์ดเปิดไม่ขึ้นหลังรอหนึ่งนาที ให้กลับไปอ่านหมายเลข IP ใหม่ทาง USB โดย **ถอด adapter ออกก่อน** เสียบ USB

#### ตู้ควบคุมปั๊มในฟาร์มจริง

ฟังผู้สอน 2 นาที ไม่ต้องแตะอุปกรณ์ จุดที่เราเพิ่งต่อ — ไฟเข้า รีเลย์ ปั๊ม — ในฟาร์มจริงอยู่ในตู้ควบคุมปั๊ม แรงดันสูงกว่า และมีสิ่งหนึ่งที่ชุดของเราไม่มี คือสวิตช์เลือก **Auto / Off / Manual** ที่หน้าตู้

| ตำแหน่ง | ใครสั่งปั๊ม | ใช้เมื่อไร |
|---------|-------------|------------|
| **Auto** | ตัวควบคุม | ทำงานปกติ |
| **Off** | ไม่มีใคร ปั๊มเดินไม่ได้ | ซ่อมบำรุง เจอน้ำรั่ว |
| **Manual** | คน โดยไม่ผ่านตัวควบคุม | เซนเซอร์เสีย เครือข่ายล่ม แต่พืชยังต้องการน้ำ |

> คนที่อยู่หน้าแปลงต้องหยุดหรือเดินปั๊มได้โดยไม่ต้องมีแล็ปท็อป นี่คือมาตรฐาน ไม่ใช่ของแถม เราจะเห็นตู้จริงทำงานในช่วงที่ 2 · **12V คือแรงดันในห้องเรียนของเรา 220V ต้องให้ช่างไฟฟ้าต่อ**

**คำถามของ Recorder** ถ้าเปลี่ยนเป็นปั๊มบ่อ 220V ในฟาร์มจริง ต้องเปลี่ยนอะไรบ้างในสิ่งที่เราเพิ่งต่อ และใครควรเป็นคนต่อ

> ก่อนพัก สั่งสวิตช์รีเลย์เป็น **Off** จากหน้าเว็บของบอร์ด และดูว่าปั๊มหยุดจริง

## กิจกรรมที่ 3 — Logic

**40 นาที** · แล็ปท็อปที่เปิด Home Assistant ไว้, โทรศัพท์ 1 เครื่อง, อุปกรณ์ทั้งหมดจากกิจกรรมที่ 1–2 ยังต่ออยู่

> **สลับบทบาทก่อนเริ่ม**

จนถึงตอนนี้เราคุยกับบอร์ดทีละตัว ตอนนี้เอาทั้งสองบอร์ดมารวมที่ Home Assistant ซึ่งจะเป็น Logic ของระบบ ลองเป็น Logic เองสักครู่ แล้วเขียน automation ข้อแรกให้มันทำแทน

### เพิ่มบอร์ดทั้งสองเข้า Home Assistant

1. **Driver** ไปที่ **Settings → Devices & services** บอร์ดในโซนของเราจะปรากฏเป็น card ที่ระบบค้นพบเองอยู่แล้ว ของทุกทีมในโซน
2. **หา card ที่ชื่อลงท้ายด้วยหกตัวอักษรของบอร์ด GoGo-IoT** ที่จดไว้ (เช่น `a1b2c3`) ตรวจสีในชื่ออีกครั้ง แล้วกดเพิ่ม ไม่ต้องพิมพ์อะไร ไม่มีรหัสให้ใส่
3. ทำซ้ำกับ **บอร์ดรีเลย์**
4. เปลี่ยนชื่ออุปกรณ์ทั้งสองเป็นชื่อทีมของเรา เพื่อให้หาเจอง่าย

![หน้า Settings → Devices & services ของ Home Assistant แสดง card ของบอร์ดที่ระบบค้นพบเองโดยไม่ต้องพิมพ์ชื่อ มีกรอบเน้นหกตัวอักษรท้ายของชื่อบอร์ดบน card](images/placeholder.png){ width="55%" }

> **ถ้าไม่เห็น card ของเรา** กด **+ Add integration** มุมล่างขวา → ค้นหา **ESPHome** → กด **Add device** → เลือก **Setup another instance of ESPHome** → พิมพ์ชื่อบอร์ดที่จดไว้ **โดยไม่ต้องมี `.local`** เช่น `gogo-iot-red-a1b2c3` แล้วกด Submit
> ในรายการจะเห็น card ของบอร์ดทีมอื่นในโซนเดียวกันด้วย **ห้ามกดมั่ว** card ของทีมอื่นก็เพิ่มได้และดูเหมือนใช้งานได้ปกติ แต่เราจะเห็นค่าของทีมอื่น และ automation ของเราจะไปสั่งปั๊มของทีมอื่น ตรวจหกตัวท้ายให้ตรงเสมอ

### ดูค่าและประวัติ

1. กดเข้าไปที่บอร์ด GoGo-IoT จะเห็นรายการ entity เดียวกับบนหน้าเว็บของบอร์ด
2. กดที่ **ความชื้นอากาศ** หน้าต่างที่เปิดขึ้นมีกราฟย้อนหลัง Home Assistant เริ่มจดค่าตั้งแต่วินาทีที่เราเพิ่มบอร์ด และจะจดต่อไปเรื่อย ๆ นี่คือสิ่งที่หน้าเว็บของบอร์ดทำไม่ได้ บอร์ดรู้แค่ค่าปัจจุบัน
3. **Hardware** ครอบบอร์ด แล้วดูกราฟ **แสง** ในหน้าต่างแบบเดียวกัน
4. กดเข้าไปที่บอร์ดรีเลย์ กดสวิตช์ **รีเลย์ (relay)** เป็น On แล้ว Off **Hardware** ฟังเสียงคลิก
5. สมาชิกอีกคนต่อโทรศัพท์เข้า WiFi ของโซนเรา `farm-laptop-สี` (**ต้องใช้ WiFi นี้ ไม่ใช่อินเทอร์เน็ตมือถือ** เพราะ Home Assistant อยู่ในแล็ปท็อป ไม่ได้อยู่บนอินเทอร์เน็ต) เปิด `http://homeassistant.local` → **Settings → Devices & services** → บอร์ดรีเลย์ → กดสวิตช์จากโทรศัพท์
6. สั่งสลับกันจากสองเครื่อง สังเกตว่าทั้งสองจอแสดงสถานะเดียวกันเสมอ

![หน้าต่าง entity ความชื้นอากาศใน Home Assistant แสดงค่าปัจจุบันและกราฟย้อนหลังที่เริ่มเมื่อไม่กี่นาทีก่อน](images/placeholder.png){ width="55%" }

> สถานะจริงอยู่ที่ Home Assistant ไม่ได้อยู่ที่หน้าจอ แล็ปท็อปและโทรศัพท์เป็นเพียงหน้าต่างมองเข้าไป
> ถ้าโทรศัพท์เปิดไม่ได้ มักเป็นเพราะไฟร์วอลล์ของแล็ปท็อป ให้ข้ามข้อนี้ไปก่อนแล้วบอกผู้สอน
> แดชบอร์ด **Overview** ของทีมเรายังว่างอยู่ เราจะออกแบบและสร้างในช่วงที่ 3 วันนี้ใช้หน้าอุปกรณ์แทน

### เป็น Logic ด้วยตัวเอง

ระบบมี Input และ Output ครบแล้ว แต่ Logic ยังเป็น **คน** ลองเป็น Logic เองห้านาที

ในห้องนี้เราจำลองสถานการณ์: **ความชื้นอากาศต่ำ = อากาศแห้ง แปลงต้องการน้ำ** เซนเซอร์ความชื้นอากาศทำหน้าที่แทนเซนเซอร์ความชื้นดินที่ฟาร์มจริงจะใช้ และ **สวิตช์ลูกลอยอยู่ในถังน้ำต้นทาง** บอกว่าน้ำเหลือพอให้ปั๊มดูดหรือไม่

1. ทีมตกลง **ค่าเกณฑ์** ความชื้นอากาศที่ถือว่าแห้ง ตั้งให้ **สูงกว่าค่าปกติในห้องเล็กน้อย** (ราว 2–3 %) เพื่อให้อากาศในห้องนับว่า "แห้ง" และการเป่าลมนับว่า "ชื้นพอแล้ว" ไม่อย่างนั้นจะไม่มีอะไรให้ตัดสินใจ
2. **Driver** เฝ้าค่าความชื้นในหน้าอุปกรณ์ ตราบใดที่ค่าต่ำกว่าเกณฑ์ ให้เปิดปั๊ม 5 วินาทีแล้วปิด รอ 10 วินาที แล้วดูใหม่
3. **Hardware** เป่าลมใส่บอร์ดเป็นระยะ เพื่อจำลองอากาศชื้น แล้วดูว่า Driver หยุดรดน้ำหรือไม่ และกลับมารดอีกเมื่อค่าตกลง
4. ขณะปั๊มเดิน **Hardware** ยกสวิตช์ลูกลอยขึ้นจากน้ำ (น้ำหมด) แล้วดูว่า Driver สั่งอะไร

> **จดลงใบบันทึก** ค่าเกณฑ์ที่เลือก · Driver ตัดสินใจถูกกี่ครั้งใน 5 นาที · ตอนยกลูกลอย Driver ปิดปั๊มภายในกี่วินาที

ถ้าอากาศแห้งตอนตีสาม ใครจะเป็นคนเปิดปั๊ม เราเพิ่งทำหน้าที่ Logic เอง กฎในหัวของเราคืออะไร **Recorder** เขียนเป็นประโยค **"ถ้า ... ให้ ..."** สองข้อลงใบบันทึก ข้อหนึ่งเรื่องความชื้น อีกข้อเรื่องลูกลอย ข้อเรื่องลูกลอยเราจะย้ายเข้า Home Assistant เดี๋ยวนี้ ข้อเรื่องความชื้นรอช่วงที่ 2

### automation ข้อแรก: น้ำหมด หยุดปั๊ม

automation หนึ่งข้อใน Home Assistant มีสามส่วน **trigger** (เมื่อไร) · **condition** (ถ้า ไม่บังคับใส่) · **action** (ให้ทำอะไร) กฎเรื่องลูกลอยใช้แค่สองส่วน

1. **Driver** ไปที่ **Settings → Automations & scenes → + Create automation → Create new automation**
2. ใต้ **When** กด **+ Add trigger → Entity → State** เลือก Entity เป็น **สวิตช์ลูกลอย** ของบอร์ดเรา ช่อง **To** เลือก **Off** (Off คือไม่มีน้ำ ดูค่าที่จดไว้ในกิจกรรมที่ 1)
3. ใต้ **Then do** กด **+ Add action → Switch → Turn off** เลือก **รีเลย์ (relay)** ของบอร์ดเรา
4. กด **Save** ตั้งชื่อ `น้ำหมด หยุดปั๊ม`

![หน้าแก้ไข automation ใน Home Assistant มี trigger เป็นสถานะสวิตช์ลูกลอยเปลี่ยนเป็น Off และ action เป็นปิดสวิตช์รีเลย์](images/placeholder.png){ width="60%" }

ทดสอบ: ลูกลอยลอยอยู่ในใบ A · **Driver** เปิดปั๊มจากหน้าอุปกรณ์ · **Hardware** ยกลูกลอยขึ้น · ปั๊มต้องหยุดเองภายในราว 1 วินาที โดยไม่มีใครกดอะไร วางลูกลอยกลับ ปั๊มไม่เดินกลับมาเอง เพราะกฎบอกแค่ให้ปิด

> **เกณฑ์ผ่าน** ทำสามครั้ง ปั๊มหยุดเองทั้งสามครั้ง ถ้าไม่หยุด ดูที่ **Settings → Automations** ว่า automation เปิดใช้อยู่ และ trigger กับ action ชี้ที่ entity ของบอร์ด **เรา** ไม่ใช่ของทีมข้าง ๆ

ลองอีกอย่างก่อนไปต่อ: **ยกลูกลอยค้างไว้ก่อน** แล้วค่อยเปิดปั๊ม เกิดอะไรขึ้น

**คำถามของ Recorder** เมื่อลูกลอยยกอยู่ก่อนแล้วจึงเปิดปั๊ม ปั๊มเดินหรือไม่ และทำไมกฎของเราจึงไม่ทำงานในกรณีนี้ (คำตอบเต็มอยู่ในช่วงที่ 2)

## กิจกรรมที่ 4 — Spec

**15 นาที** · บัตรสถานการณ์จากผู้สอน, สเปกที่แจก (เซนเซอร์ความชื้นและอุณหภูมิ สวิตช์ลูกลอย ปั๊ม), บอร์ดรีเลย์ ไม่ต้องแตะอุปกรณ์ที่ต่ออยู่

> **สลับบทบาทก่อนเริ่ม**

ชุดของเราทำงานได้แล้ว คำถามต่อไปคือ ทำงานได้ **สำหรับงานไหน** ทีมรับบัตรสถานการณ์หนึ่งใบ แล้วตัดสินจากสเปกว่าชุดนี้รับงานนั้นได้หรือไม่

### อ่านสเปกของชุดเรา

- **เซนเซอร์ความชื้นอากาศและอุณหภูมิ** ช่วงการวัด · ความแม่นยำ (± กี่ %RH และ ± กี่ °C) · ค่าที่เราเห็นแกว่งอยู่ในช่วงความแม่นยำนั้นหรือไม่
- **สวิตช์ลูกลอย** ทนกระแสและแรงดันได้เท่าไร · วัสดุ · ปิดวงจรเมื่อลอยขึ้นหรือลง
- **รีเลย์** อ่านตัวเลขที่พิมพ์บนตัวรีเลย์สีน้ำเงินบนบอร์ด จะเห็นสี่บรรทัด เช่น `10A 250VAC` และ `10A 30VDC` จดค่าฝั่ง DC ไว้
- **ปั๊มของเรา** กระแสที่ใช้ตามสเปก เทียบกับพิกัดรีเลย์

### ตัดสิน

บัตรสถานการณ์บอกงานหนึ่งอย่างพร้อมตัวเลขที่งานนั้นต้องการ เช่น ความแม่นยำของอุณหภูมิ หรือกระแสของปั๊ม เทียบทีละข้อกับสเปกที่อ่านได้ แล้วกรอกตารางในใบบันทึก

| งานต้องการ | ชุดเราให้ได้ | ผ่าน / ไม่ผ่าน |
|-----------|-------------|---------------|
| (จากบัตร) | (จากสเปก) | |

ถ้าไม่ผ่าน ตอบให้ได้ว่าต้องเปลี่ยน **ชิ้นไหน** ชิ้นเดียว ไม่ใช่ทั้งชุด

> ตัวเลขบนสเปกไม่ใช่ตัวเลขการตลาด เป็นสัญญาว่าอุปกรณ์ทำได้แค่นี้ งานที่ต้องการเกินกว่านั้น อุปกรณ์ทำไม่ได้ ไม่ว่าจะเขียน Logic ดีแค่ไหน

**คำถามของ Recorder** ชุดเรารับงานในบัตรได้หรือไม่ เพราะสเปกข้อไหน

ผู้สอนสรุปห้าอย่างที่ต้องอ่านบนสเปกทุกครั้ง: ช่วงการวัด · ความแม่นยำ · อินเทอร์เฟซ · แรงดันและกระแส · IP rating

## ก่อนออกจากห้อง

Home Assistant บนแล็ปท็อปจะกลับบ้านไปกับเรา แต่บอร์ดเซนเซอร์ของทีม **อยู่ในห้องต่อ** และยังอ่านค่าทั้งคืน เพื่อให้พรุ่งนี้เช้าเปิดมาก็พร้อมใช้ทันที ไม่ต้องต่อใหม่

บอร์ดเซนเซอร์ตอนนี้กินไฟจากแล็ปท็อป จึงต้องย้ายไปใช้ไฟจากกล่องจ่ายไฟแทน

- [ ] สั่งสวิตช์รีเลย์เป็น **Off** และตรวจในหน้าอุปกรณ์ว่าเป็น Off จริง
- [ ] ยกปั๊มขึ้นจากน้ำ วางบนถาด เช็ดน้ำบนโต๊ะ สวิตช์ลูกลอยยังอยู่ในใบ A
- [ ] ถอดสาย USB-C ของบอร์ด GoGo-IoT ออกจากแล็ปท็อป แล้วเสียบเข้า **ช่อง USB ของตัวควบคุมการชาร์จ** รอให้ไฟบอร์ดติดและค่ากลับมาขึ้นในหน้าอุปกรณ์ บอร์ดจะอยู่ที่ช่องนี้ไปตลอดหลักสูตร
- [ ] **adapter ยังเสียบอยู่** กล่องจ่ายไฟต้องทำงานทั้งคืน บอร์ดรีเลย์จะติดไฟด้วยแต่ไม่มีใครสั่ง ปั๊มจึงไม่เดิน
- [ ] แล็ปท็อปปิดได้ตามปกติ

## สรุปช่วงที่ 1

1. **ระบบอัตโนมัติมีสามส่วนเสมอ** Input รับรู้ Logic ตัดสินใจ Output สั่งการ ถังน้ำลูกลอยก็ครบสามส่วน เพียงแต่ Logic เป็นกลไก
2. **เซนเซอร์มีสองแบบ** แอนะล็อกให้ตัวเลขต่อเนื่อง ดิจิทัลบอกได้แค่ถึงหรือไม่ถึง ทั้งสองแบบมีที่ใช้
3. **บอร์ดสั่งโหลดตรงไม่ได้** รีเลย์เป็นแค่สวิตช์ และโหลดต้องมีไฟของตัวเอง
4. **ทุก actuator ต้องมี manual override** สวิตช์ Auto / Off / Manual คือมาตรฐาน ไม่ใช่ของแถม
5. **สถานะจริงอยู่ที่ Logic** ไม่ได้อยู่ที่หน้าจอ
6. **กฎที่พูดเป็นประโยค "ถ้า ... ให้ ..." ได้ ย้ายเข้า Home Assistant ได้** automation = trigger + action และมันทำงานตอนตีสาม
7. **สเปกคือสัญญา** งานที่ต้องการเกินสเปก อุปกรณ์ทำไม่ได้ ไม่ว่า Logic จะดีแค่ไหน
