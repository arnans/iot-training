### 1.1 รู้จักบอร์ด GoGo-IoT { #a1-1 }

บอร์ดตัวนี้มีคอนโทรลเลอร์ ESP32-C3 และเซนเซอร์ในตัวสำหรับวัดห้าค่า ได้แก่ **อุณหภูมิ ความชื้นอากาศ แสง ความกดอากาศ และความเร่ง** (บอร์ดแปลงความเร่งเป็นค่า **ความสั่นสะเทือน** ให้เราแล้ว) นอกจากนั้นมีช่องต่อเซนเซอร์เพิ่มแบบ Grove เราจะต่อ **สวิตช์ลูกลอย** เข้าที่ **ช่อง 1** ซึ่งตั้งค่าไว้แล้วให้อ่านเป็นสัญญาณดิจิทัล

![ส่วนประกอบหลักของบอร์ด GoGo-IoT: ช่อง USB-C สวิตช์ ON/OFF ช่อง Grove 1 คอนโทรลเลอร์ ESP32-C3 ปุ่ม BOOT และกลุ่มเซนเซอร์ในตัว](images/gogo-iot-main-parts.png){ width="100%" }

ภาพเรนเดอร์ด้านบนของบอร์ด: **USB-C** ใช้จ่ายไฟและเชื่อมต่อคอมพิวเตอร์ · **ON / OFF** คือสวิตช์เปิด–ปิดบอร์ด · **Grove port 1** ใช้ต่อสวิตช์ลูกลอย · กรอบสีแดงด้านขวาคือกลุ่มเซนเซอร์ในตัว · ช่องใส่ถ่าน **18650 อยู่ด้านใต้บอร์ด** จึงไม่ปรากฏในภาพ

![ชุดสวิตช์ลูกลอยที่ต่อกับบอร์ด GoGo-IoT แล้ว: สาย Grove ออกจากบอร์ดไปเข้าตัวแปลงซึ่งเป็นบอร์ดเล็กมีขั้วสกรู และสายสีเหลืองสองเส้นจากตัวแปลงไปยังตัวลูกลอยสีขาว](images/gogo-iot-float-switch.jpg){ width="75%" }

ชุดสวิตช์ลูกลอยมีสามส่วนต่อกันมาให้แล้วตามภาพ คือ **สาย Grove** → **ตัวแปลง** (บอร์ดเล็กที่มีขั้วสกรู) → **ตัวลูกลอย** สิ่งที่เราต้องต่อเองมีเพียงปลายสาย Grove อีกด้านหนึ่งเท่านั้น

1. เสียบสาย Grove จากตัวแปลงของสวิตช์ลูกลอยเข้า **ช่อง 1** บนบอร์ด
2. เสียบสาย USB-C เข้าบอร์ด แล้วเสียบอีกปลายเข้าช่อง USB ของแล็ปท็อป
3. วางสวิตช์ลูกลอยลงแก้วน้ำที่มีน้ำครึ่งแก้ว ให้ลูกลอยลอยขึ้น

### 1.2 อ่านชื่อและหมายเลข IP ของบอร์ด { #a1-2 }

บอร์ดแต่ละตัวมีชื่อเฉพาะที่สร้างจากหมายเลขประจำเครื่อง จึงไม่ซ้ำกับบอร์ดของกลุ่มอื่น เมื่อเชื่อมต่อ WiFi แล้ว บอร์ดจะได้รับ **หมายเลข IP** สำหรับติดต่อผ่านเครือข่าย ให้จดทั้งชื่อและหมายเลข IP ไว้ใช้ในกิจกรรมต่อ ๆ ไป

1. เปิด **Chrome** หรือ **Edge** ไปที่ **[web.esphome.io](https://web.esphome.io)** (Firefox ใช้ไม่ได้)
2. กด **Connect** เลือกพอร์ตที่ปรากฏขึ้น แล้วกดยืนยัน
3. กด **Logs & Console** แล้วกดปุ่ม **Reset device** ในหน้าเว็บ (ไม่ใช่ปุ่มบนบอร์ด) บอร์ดจะเริ่มทำงานใหม่ แล้วพิมพ์ข้อความสำคัญสองบรรทัดลงในกรอบ บรรทัดแรก ๆ คือ `=====  DEVICE NAME: ...  =====` ตัวอย่างชื่อคือ `gogo-iot-red-a1b2c3` และอีกราว 10–20 วินาทีต่อมา หลังบอร์ดต่อ WiFi ได้ จะมี `=====  IP ADDRESS: ...  =====` ตามมา
4. **ตรวจสี** คำกลางในชื่อ (`red` / `green` / `blue`) ต้องตรงกับสีโซนของกลุ่มเรา ถ้าไม่ตรง บอร์ดนี้จะไม่เห็น WiFi ของเรา ให้ยกมือขอเปลี่ยนบอร์ด
5. **จดชื่อและหมายเลข IP** ชื่อบอร์ด {{f:board.iot.name|22}} IP {{f:board.iot.ip|15}} แล้วปิดหน้าต่างนี้

![หน้าจอ web.esphome.io หลังกด Connect และกดปุ่ม Reset device ในหน้าเว็บ แสดง log ของบอร์ด มีกรอบเน้นแถบ DEVICE NAME และแถบ IP ADDRESS และกรอบเน้นปุ่ม Reset device ที่มุมล่างขวา](images/placeholder.png){ width="60%" }

> ถ้าหน้าต่าง log ว่างเปล่า หรือชื่อเลื่อนผ่านไปแล้ว ให้กดปุ่ม **Reset device** ในหน้าเว็บอีกครั้ง **อย่าถอดสาย USB และอย่ากดปุ่มบนบอร์ด** สองอย่างนั้นจะตัดการเชื่อมต่อของเบราว์เซอร์ และชื่อจะไม่ขึ้น
> ถ้าเห็นชื่อแต่ไม่เห็นหมายเลข IP ภายในหนึ่งนาที แปลว่าบอร์ดต่อ WiFi ไม่ได้ ตรวจสีในชื่ออีกครั้ง แล้วยกมือ

### 1.3 เปิดหน้าเว็บของบอร์ด { #a1-3 }

บอร์ดมีหน้าเว็บสำหรับแสดงค่าในตัว เรียกว่า **เว็บเซิร์ฟเวอร์** เราจึงเปิดดูค่าผ่านเบราว์เซอร์ได้โดยตรงเมื่อเชื่อมต่อ WiFi โซนเดียวกัน โดยยังไม่ต้องใช้ Home Assistant

1. เปิดแท็บใหม่ พิมพ์ `http://` ตามด้วยหมายเลข IP ที่จดไว้ เช่น `http://192.168.10.57`
2. จะเห็นรายการค่าจากบอร์ด แต่ละบรรทัดคือ **entity** หนึ่งตัว ค่าจะอัปเดตเองโดยไม่ต้องรีเฟรช สังเกตว่าสวิตช์ลูกลอยไม่ได้แสดงเป็นตัวเลข แต่แสดงเป็นสถานะสองอย่าง รายการที่เกี่ยวกับ **ปั๊ม** (ปั๊มกำลังทำงาน และความไวตรวจจับปั๊ม) ปล่อยไว้ก่อน เราจะใช้ในช่วงที่ 2

![หน้าเว็บของบอร์ด GoGo-IoT ในเบราว์เซอร์ แสดงรายการ entity อุณหภูมิ ความชื้นอากาศ แสง ความกดอากาศ ความสั่นสะเทือน และสวิตช์ลูกลอย พร้อมค่าปัจจุบัน](images/placeholder.png){ width="60%" }

> ถ้าเปิดไม่ขึ้น ตรวจว่าแล็ปท็อปอยู่บน `farm-laptop-สีเดียวกัน` กับสีในชื่อบอร์ด เพราะหน้านี้อยู่บนตัวบอร์ด ไม่ได้อยู่บนอินเทอร์เน็ต

### 1.4 ทดลองดูว่าเซนเซอร์แต่ละตัววัดอะไร { #a1-4 }

ให้คนหนึ่งทำทีละอย่าง อีกคนดูว่า entity รายการใดบนหน้าเว็บเปลี่ยน

| ทำอะไร | สังเกต |
|--------|--------|
| เป่าลมหายใจใส่บอร์ดช้า ๆ 5 วินาที | ความชื้นอากาศและอุณหภูมิ ขึ้นเท่าไร |
| ใช้มือครอบบอร์ดให้มืด | แสงลงเหลือเท่าไร แล้วเอามือออก ค่ากลับมาเร็วแค่ไหน |
| เคาะโต๊ะข้างบอร์ด หรือเขย่าบอร์ดเบา ๆ | ความสั่นสะเทือน ขึ้นถึงเท่าไร แล้ววางนิ่ง ลงเหลือเท่าไร (หน่วย mg) |
| ยกสวิตช์ลูกลอยขึ้นจากน้ำ แล้ววางกลับ | สถานะเปลี่ยนจากอะไรเป็นอะไร (หน้าเว็บของบอร์ดใช้คำว่า **ON** = มีน้ำ **OFF** = น้ำหมด) |

> **บันทึกผล** ค่าที่อ่านได้จากหน้าเว็บของบอร์ด ค่าแสงจะใช้ตั้งเกณฑ์ในกิจกรรมที่ 3 ส่วนค่าความชื้นอากาศจะใช้ในช่วงที่ 2

| เซนเซอร์ | ค่าปกติในห้อง | ค่าเมื่อทดสอบ | ทดสอบด้วยวิธี |
|----------|---------------|---------------|---------------|
| ความชื้นอากาศ | {{n:s1.hum.room}} % | {{n:s1.hum.test}} % | เป่าลม |
| อุณหภูมิ | {{n:s1.temp.room}} °C | {{n:s1.temp.test}} °C | เป่าลม |
| แสง | {{n:s1.light.room}} | {{n:s1.light.test}} | ใช้มือครอบบอร์ด |
| ความสั่นสะเทือน | {{n:s1.vib.room}} mg | {{n:s1.vib.test}} mg | เคาะโต๊ะ / เขย่า |
| สวิตช์ลูกลอย | ลอยอยู่: {{f:s1.float.rest|4}} | ยกขึ้น: {{f:s1.float.lift|4}} | ยกขึ้นจากน้ำ |

ครอบบอร์ดอีกครั้ง แล้วนับว่าค่าแสงบนหน้าเว็บเปลี่ยนภายในกี่วินาที บอร์ดส่งค่าใหม่เป็นระยะ ไม่ใช่ทันที **เปลี่ยนภายใน** {{n:s1.light.delay|3}} **วินาที** จะได้ใช้ในกิจกรรมที่ 3 และช่วงที่ 2
{: #a1-4b }

> สวิตช์ลูกลอยไม่ได้บอกว่าน้ำมีเท่าไร บอกได้อย่างเดียวว่าน้ำถึงระดับนี้หรือไม่ถึง เซนเซอร์แบบนี้เรียกว่าเซนเซอร์ **ดิจิทัล** (ตอนเข้า Home Assistant ในกิจกรรมที่ 3 สถานะเดียวกันนี้จะเรียกว่า **Wet** = มีน้ำ และ **Dry** = น้ำหมด แทน ON/OFF) ส่วนความชื้นและแสงที่ให้ตัวเลขต่อเนื่องเรียกว่า **แอนะล็อก** ความต่างนี้จะสำคัญมากในช่วงที่ 2

## กิจกรรมที่ 2 — ต่อวงจรและสั่งงานหลอดไฟ (Act)

**40 นาที**

**อุปกรณ์ที่ใช้** บอร์ดรีเลย์, charge controller, อะแดปเตอร์ 12V, สายไฟ, แผงต่อสาย, หลอด LED 12V, ไขควง

เริ่มจากสั่งรีเลย์ผ่านหน้าเว็บ โดยยังไม่ต่ออะไรที่ขั้วรีเลย์ เพื่อดูว่ารีเลย์เปิด–ปิดวงจรอย่างไร จากนั้นจึงต่อแหล่งจ่ายไฟ 12V และหลอด LED เข้าด้วยกัน เราใช้หลอดไฟเป็นอุปกรณ์ปลายทางตัวแรก เพราะมองเห็นผลได้ทันทีจากทั้งโต๊ะ ส่วนปั๊มน้ำจะต่อในช่วงที่ 2 ขั้นตอนนี้ต้องต่อสายเอง ให้ค่อย ๆ ทำและตรวจทีละจุดตามใบงาน

### 2.1 ส่วน ก — รีเลย์คือสวิตช์ { #a2-1 }

#### รู้จักบอร์ดรีเลย์

บอร์ดรีเลย์เป็นบอร์ดคนละตัวกับบอร์ดเซนเซอร์ มีคอนโทรลเลอร์ของตัวเอง (ESP32-C6) และมีขั้วต่อสองกลุ่ม ดูตำแหน่งขั้วต่อจากแผนภาพนี้ก่อนต่อสาย

> **บอร์ดนี้รับไฟทางสาย USB ตลอดหลักสูตร** ในส่วน ก เสียบกับแล็ปท็อป ตั้งแต่ส่วน ข เสียบกับช่อง USB ของกล่องจ่ายไฟ ขั้วไฟเข้า 7–60V บนบอร์ด **ไม่ใช้และห้ามต่อสายเข้า** ไฟ 12V จากกล่องจ่ายไฟจึงไปที่หลอดไฟทางเดียว ไม่ต้องแยกสายมาเลี้ยงบอร์ด

![แผนภาพบอร์ดรีเลย์ ESP32-C6 ชี้ตำแหน่งขั้ว NO COM NC ทางซ้าย ขั้วไฟเข้า 7-60 Input และ GND ทางขวา ช่อง USB Type-C ปุ่มบนบอร์ด ไฟ LED และไฟแสดงสถานะรีเลย์](images/relay-board-terminals.png){ width="100%" }

| ป้ายบนแผนภาพ | คือ | เราใช้ทำอะไร |
|--------------|-----|--------------|
| **NO / COM / NC** | ขั้วรีเลย์ (บล็อกเขียว 3 ช่อง) | ใช้ **COM** กับ **NO** ให้ไฟ 12V ไปหลอดไฟ (ช่วงที่ 2 ไปปั๊ม) |
| **7-60 Input / GND** | ขั้วไฟเข้า (บล็อกเขียว 2 ช่อง) | **ไม่ใช้** ปล่อยว่างไว้ ห้ามต่อสายเข้า |
| **USB Type-c** | ช่อง USB | ไฟเลี้ยงบอร์ด ส่วน ก จากแล็ปท็อป ตั้งแต่ส่วน ข จากช่อง USB ของกล่องจ่ายไฟ |
| **Relay Indicator** | ไฟแสดงสถานะรีเลย์ | ติดเมื่อรีเลย์ทำงาน ตั้งแต่ส่วน ข เราจะดูไฟดวงนี้คู่กับหลอดไฟ |
| **LED** | ไฟแสดงการเชื่อมต่อ WiFi | ติดค้าง = ต่อ WiFi ได้ · กะพริบ = หลุด WiFi · ดับ = ไม่มีไฟ |
| **Programmable keys** | ปุ่มบนบอร์ด | กดสั่งรีเลย์ด้วยมือได้ แม้ไม่มี Home Assistant |

#### อ่านชื่อ หมายเลข IP แล้วลองสั่งรีเลย์ (ทำก่อนต่อสายใด ๆ) { #a2-1b }

1. เสียบสาย USB-C จากบอร์ดรีเลย์เข้าแล็ปท็อป (ยังไม่ต่ออย่างอื่นทั้งสิ้น)
2. ทำเหมือนกิจกรรมที่ 1: [web.esphome.io](https://web.esphome.io) → **Connect** → เลือกพอร์ต → **Logs & Console** → กด **Reset device** ในหน้าเว็บ อ่านชื่อบอร์ด เช่น `gogo-relay-red-a1b2c3` และหมายเลข IP ตรวจว่าสีในชื่อตรงกับโซนของกลุ่ม แล้วจดไว้ ชื่อบอร์ด {{f:board.relay.name|22}} IP {{f:board.relay.ip|15}} ปิดหน้าต่าง
3. เปิดแท็บใหม่ไปที่ `http://` ตามด้วยหมายเลข IP ของบอร์ดรีเลย์ จะเห็น entity ชื่อ **รีเลย์ (relay)** เป็นสวิตช์
4. กดให้เป็น On หนึ่งวินาที แล้ว Off ฟังเสียงคลิก และดูไฟ **Relay Indicator** ติดดับตาม
5. กด **ปุ่มบนบอร์ด** หนึ่งครั้ง รีเลย์คลิกและสวิตช์บนหน้าเว็บเปลี่ยนตาม กดอีกครั้งให้กลับเป็น Off
6. **ถอดปลายสาย USB ออกจากแล็ปท็อป** ปลายฝั่งบอร์ดเสียบไว้ตามเดิม ในส่วน ข เราจะย้ายปลายนี้ไปเสียบช่อง USB ของกล่องจ่ายไฟ

> เสียงคลิกเกิดจากหน้าสัมผัสของรีเลย์เปลี่ยนตำแหน่งเพื่อเปิดหรือปิดวงจร ขณะนี้ยังไม่ได้ต่ออุปกรณ์ที่ขั้วรีเลย์ จึงได้ยินเพียงเสียงคลิก **รีเลย์ทำหน้าที่เป็นสวิตช์** ไม่ได้จ่ายไฟให้หลอดไฟเอง เราจะต่อแหล่งจ่ายไฟและหลอดไฟในส่วน ข

### 2.2 ส่วน ข — ต่อแหล่งจ่ายไฟและหลอดไฟ { #a2-2 }

#### กล่องจ่ายไฟ 12V

บอร์ดรีเลย์และหลอดไฟอยู่ปลายโต๊ะฝั่งอุปกรณ์ ห่างจากแล็ปท็อป เราจะใช้ **charge controller** ที่ต่ออะแดปเตอร์ 12V แทนแบตเตอรี่เป็นแหล่งจ่ายไฟร่วมกัน ในช่วงนี้ให้ดูเฉพาะ **ขั้วจ่ายไฟ 12V คู่ขวาสุด** ซึ่งมีสัญลักษณ์หลอดไฟ และ **ช่อง USB สองช่อง** ขั้ว 12V จ่ายไฟให้หลอดไฟ (และปั๊มในช่วงที่ 2) ช่อง USB ช่องหนึ่งเลี้ยงบอร์ดรีเลย์ อีกช่องเก็บไว้ให้บอร์ด GoGo-IoT ตอนท้ายวัน ส่วนหน้าที่อื่นของ charge controller จะเรียนในช่วงที่ 3

#### ต่อสาย { #a2-2b }

**ตรวจก่อนเริ่ม: สาย USB ของบอร์ดรีเลย์ถอดออกจากแล็ปท็อปแล้ว** และ **ยังไม่เสียบปลั๊กอะแดปเตอร์จนกว่าจะถึงขั้นสุดท้าย** ให้คนหนึ่งต่อสาย อีกคนอ่านทีละข้อและตรวจว่าทำครบก่อนอ่านข้อถัดไป

1. ต่อสายอะแดปเตอร์ 12V เข้า **คู่กลาง** (สัญลักษณ์แบตเตอรี่) ของ charge controller สายแดงเข้าบวก สายดำเข้าลบ
2. จาก **คู่ขวา** (สัญลักษณ์หลอดไฟ) ของ charge controller เดินสายสองเส้นไปยัง **แผงต่อสาย** บวกเข้าแถวบวก ลบเข้าแถวลบ แผงนี้คือจุดกระจายไฟ 12V ของเรา
3. จากแถวบวกไป **COM** ของรีเลย์ แล้วจาก **NO** ไปยัง **สายแดง** ของหลอด LED สายแดงคือขาบวก ถ้าต่อกลับขั้ว หลอดจะไม่ติดแต่ไม่เสีย
4. **สายดำ** ของหลอด LED เข้าแถวลบของแผงต่อสาย
5. เสียบปลายสาย USB-C ของบอร์ดรีเลย์เข้า **ช่อง USB ของ charge controller** ช่องใดก็ได้ สายเส้นนี้เลี้ยงตัวบอร์ด ขั้วไฟเข้า 7–60V จึงปล่อยว่างไว้
6. ตรวจทุกสกรูแน่น ไม่มีปลายสายเปลือยแตะกัน ไม่มีสายเข้าขั้ว **NC** และไม่มีสายเข้าขั้ว **7-60 Input / GND**

![ตัวอย่างวงจรที่ต่อหลอด LED เสร็จแล้ว: อะแดปเตอร์ 12V ต่อเข้าคู่แบตเตอรี่ของ charge controller แทนแบตเตอรี่ จอแสดง 12.0V สายบวกจากคู่โหลดของ charge controller เข้า COM ของบอร์ดรีเลย์ แล้วออกจาก NO ไปแผงต่อสายสีขาว สายลบจากคู่โหลดไปแผงต่อสายโดยตรง หลอด LED ต่อออกจากแผงต่อสาย บอร์ดรีเลย์รับไฟจากช่อง USB ของ charge controller ทางสาย USB-C](images/session2-relay-led-wiring.jpg){ width="85%" }

*ตัวอย่างวงจรเมื่อต่อหลอด LED เสร็จ* อะแดปเตอร์ 12V ต่อเข้า **คู่แบตเตอรี่** ของ charge controller แทนแบตเตอรี่ จอจึงติดและแสดง 12.0V · สายบวก 12V จาก **คู่โหลด** เข้า **COM** ของรีเลย์ แล้วออกจาก **NO** ไปแผงต่อสายสีขาว · สายลบจากคู่โหลดไปแผงต่อสายโดยตรง · หลอด LED รับไฟจากแผงต่อสาย · บอร์ดรีเลย์รับไฟทางสาย USB-C จาก **ช่อง USB** ของ charge controller ขั้วไฟเข้า 7–60V จึงว่าง (ในภาพใช้คีมหนีบแทนสายอะแดปเตอร์)

> **ทำไมตัดวงจรที่สายบวกเส้นเดียว** ไฟจะไหลได้ต้องครบวงจร ตัดที่จุดเดียวก็พอ และเราเลือกตัดด้านบวก เพื่อให้สายลบทุกเส้นต่อถึงกันเป็นกราวด์ร่วม ตู้ควบคุมปั๊มจริงก็ทำแบบเดียวกัน แค่แรงดันสูงกว่า

#### จ่ายไฟและสั่งหลอดไฟ { #a2-2c }

1. วางหลอด LED ให้เลนส์หันออกจากบอร์ด GoGo-IoT และห่างจากบอร์ดอย่างน้อยหนึ่งช่วงแขน (ราว 30 ซม.) ไม่อย่างนั้นแสงจากหลอดจะย้อนเข้าเซนเซอร์แสงของบอร์ด และทำให้กฎในกิจกรรมที่ 3 สับสน
2. **เสียบอะแดปเตอร์เข้ารางปลั๊ก** จอ charge controller ควรติดและแสดงแรงดัน ไฟบนบอร์ดรีเลย์ควรติด รอ 30 วินาทีให้บอร์ดต่อ WiFi
3. เปิดหน้าเว็บของบอร์ดรีเลย์อีกครั้งที่หมายเลข IP เดิม (บอร์ดจะได้หมายเลขเดิมเมื่อกลับมาต่อ WiFi)
4. กดสวิตช์เป็น On หลอดต้องติด กด Off หลอดต้องดับ ทำซ้ำสองสามครั้ง สังเกตว่าไฟ **Relay Indicator** ติดดับพร้อมหลอด หลอดที่ติดคือหลักฐานว่า Output ของเราทำงานจริง
5. ถ้าหลอดไม่ติดแต่รีเลย์คลิก ให้สั่ง Off ถอดอะแดปเตอร์ แล้วสลับสายแดงกับสายดำของหลอด

> **บันทึกผล** จอ charge controller แสดง {{n:s1.psu.volt|5}} V · กลุ่มต่อสายครบและถูกต้องในครั้งแรกหรือไม่ {{r:s1.wiring.first|ใช่|ไม่ใช่}} ข้อที่ต้องแก้ {{f:s1.wiring.fix|20}}

> ถ้าจอ charge controller ไม่ติด ให้ถอดอะแดปเตอร์ก่อน แล้วตรวจการต่อสายข้อ 1 ถึง 6 ใหม่ ถ้าจอติดแต่บอร์ดรีเลย์ไม่ติด ให้เสียบสาย USB ให้แน่นหรือลองช่อง USB อีกช่อง ถ้าหน้าเว็บของบอร์ดเปิดไม่ขึ้นหลังรอหนึ่งนาที ให้ย้ายปลายสาย USB จาก charge controller มาเสียบแล็ปท็อปชั่วคราวเพื่ออ่านหมายเลข IP ใหม่ (บอร์ดจะเริ่มใหม่และรีเลย์เป็น Off) แล้วย้ายกลับ

#### ตู้ควบคุมปั๊มในฟาร์มจริง { #a2-2d }

ฟังผู้สอน 2 นาที ไม่ต้องแตะอุปกรณ์ จุดที่เราเพิ่งต่อ (แหล่งจ่ายไฟ รีเลย์ อุปกรณ์ปลายทาง) ในฟาร์มจริงจะอยู่ในตู้ควบคุมปั๊ม แรงดันสูงกว่า และมีสิ่งหนึ่งที่ชุดของเราไม่มี คือสวิตช์เลือก **Auto / Off / Manual** ที่หน้าตู้

| ตำแหน่ง | ใครสั่งปั๊ม | ใช้เมื่อไร |
|---------|-------------|------------|
| **Auto** | charge controller | ทำงานปกติ |
| **Off** | ไม่มีใคร ปั๊มเดินไม่ได้ | ซ่อมบำรุง เจอน้ำรั่ว |

### 3.1 เพิ่มบอร์ดทั้งสองเข้า Home Assistant { #a3-1 }

1. ที่แล็ปท็อปของตัวแทนกลุ่ม กลับไปที่หน้า Login ของ Home Assistant ที่เปิดไว้ตอนก่อนเริ่ม ใส่ **ชื่อผู้ใช้และรหัสผ่านที่ผู้สอนแจ้ง** แล้วกด **Log in** (ถ้าหน้าเปิดไม่ขึ้น ให้อ่านที่อยู่ IP จากหน้าจอเครื่อง Farm Workshop ใหม่)
2. ไปที่ **Settings → Devices & services** จะเห็นการ์ดของบอร์ดที่ระบบค้นพบเองอยู่แล้ว ซึ่งมีของทุกกลุ่มในโซนเราปนกันอยู่
3. **หาการ์ดที่ชื่อลงท้ายด้วยหกตัวอักษรของบอร์ด GoGo-IoT** ที่จดไว้ (เช่น `a1b2c3`) ตรวจสีในชื่ออีกครั้ง แล้วกดเพิ่ม ไม่ต้องพิมพ์อะไร ไม่มีรหัสให้ใส่
4. ทำซ้ำกับ **บอร์ดรีเลย์**
5. เปลี่ยนชื่ออุปกรณ์ทั้งสองเป็นชื่อกลุ่มของเรา เพื่อให้หาเจอง่าย

![หน้า Settings → Devices & services ของ Home Assistant แสดงการ์ดของบอร์ดที่ระบบค้นพบเองโดยไม่ต้องพิมพ์ชื่อ มีกรอบเน้นหกตัวอักษรท้ายของชื่อบอร์ดบนการ์ด](images/placeholder.png){ width="55%" }

> **ถ้าไม่เห็นการ์ดของเรา** กด **+ Add integration** มุมล่างขวา → ค้นหา **ESPHome** → กด **Add device** → เลือก **Setup another instance of ESPHome** → พิมพ์ชื่อบอร์ดที่จดไว้ **โดยไม่ต้องมี `.local`** เช่น `gogo-iot-red-a1b2c3` แล้วกด Submit
> ในรายการจะเห็นการ์ดของบอร์ดกลุ่มอื่นในโซนเดียวกันด้วย **ตรวจชื่อก่อนกดเพิ่มทุกครั้ง** การ์ดของกลุ่มอื่นก็เพิ่มได้และดูเหมือนใช้งานได้ปกติ แต่เราจะเห็นค่าของกลุ่มอื่น และ automation ของเราจะไปสั่งรีเลย์ของกลุ่มอื่น ตรวจหกตัวท้ายให้ตรงเสมอ

### 3.2 ดูค่าปัจจุบันและข้อมูลย้อนหลัง { #a3-2 }

1. กดเข้าไปที่บอร์ด GoGo-IoT จะเห็นรายการ entity เดียวกับบนหน้าเว็บของบอร์ด
2. กดที่ **ความสว่าง** หน้าต่างที่เปิดขึ้นมีกราฟย้อนหลัง Home Assistant เริ่มจดค่าตั้งแต่วินาทีที่เราเพิ่มบอร์ด และจะจดต่อไปเรื่อย ๆ หน้าเว็บของบอร์ดทำแบบนี้ไม่ได้ เพราะบอร์ดรู้แค่ค่าปัจจุบัน ครอบบอร์ดสักครู่แล้วเอามือออก ดูรอยหยักที่เกิดบนกราฟ
3. ดูกราฟ **ความชื้นอากาศ** ในหน้าต่างแบบเดียวกัน ค่านี้จะใช้ควบคุมปั๊มในช่วงที่ 2
4. กดเข้าไปที่บอร์ดรีเลย์ กดสวิตช์ **รีเลย์ (relay)** เป็น On หลอดไฟต้องติด แล้ว Off หลอดดับ
5. สมาชิกอีกคนต่อโทรศัพท์เข้า WiFi ของโซนเรา `farm-laptop-สี` (**ต้องใช้ WiFi นี้ ไม่ใช่อินเทอร์เน็ตมือถือ** เพราะ Home Assistant อยู่ในแล็ปท็อป ไม่ได้อยู่บนอินเทอร์เน็ต) เปิด **ที่อยู่เดียวกับที่จดไว้ตอนก่อนเริ่ม** เข้าระบบด้วยชื่อผู้ใช้และรหัสผ่านเดียวกัน → **Settings → Devices & services** → บอร์ดรีเลย์ → กดสวิตช์จากโทรศัพท์
6. สั่งสลับกันจากสองเครื่อง สังเกตว่าทั้งสองจอแสดงสถานะเดียวกันเสมอ

![หน้าต่าง entity ความสว่างใน Home Assistant แสดงค่าปัจจุบันและกราฟย้อนหลังที่เริ่มเมื่อไม่กี่นาทีก่อน มีรอยหยักตอนใช้มือครอบบอร์ด](images/placeholder.png){ width="55%" }

> ทั้งสองหน้าจอแสดงข้อมูลจาก Home Assistant เครื่องเดียวกัน จึงเห็นสถานะเดียวกันเมื่อข้อมูลอัปเดต
> ถ้าโทรศัพท์เปิดไม่ได้ ตรวจว่าโทรศัพท์อยู่บน WiFi โซนเดียวกับแล็ปท็อป และพิมพ์ที่อยู่ตรงกับที่จดไว้ ถ้ายังไม่ได้ ให้ข้ามข้อนี้ไปก่อนแล้วบอกผู้สอน เพื่อให้ผู้สอนช่วยตรวจการเชื่อมต่อเครือข่าย
> แดชบอร์ด **Overview** ของกลุ่มเรายังว่างอยู่ เราจะออกแบบและสร้างในช่วงที่ 3 ตอนนี้ใช้หน้าอุปกรณ์แทน

### 3.3 ลองตัดสินใจและสั่งงานด้วยตัวเอง { #a3-3 }

ตอนนี้เรามีเซนเซอร์รับข้อมูล (Input) และหลอดไฟที่พร้อมทำงาน (Output) แล้ว ส่วนการตัดสินใจ (Logic) ยังเป็นหน้าที่ของเรา ลองควบคุมระบบเองเป็นเวลา 3 นาที

**สถานการณ์: ไฟกลางคืนสำหรับแปลงไม้ดอก** ไม้ดอกหลายชนิด เช่น เบญจมาศ ต้องได้รับแสงนานกว่าช่วงกลางวันตามธรรมชาติ สวนจึงเปิดหลอดไฟเมื่อฟ้ามืด ระบบนี้ต้องตัดสินใจจาก **เซนเซอร์แสง** และสั่ง **หลอดไฟ** ผ่านรีเลย์ ซึ่งดีกว่าการตั้งเวลาเปิด–ปิดตายตัว เพราะแต่ละฤดูฟ้ามืดและสว่างไม่ตรงเวลากัน ในห้องนี้หลอด LED 12V ที่เพิ่งต่อคือหลอดไฟในสวน และมือที่ครอบบอร์ดคือฟ้ามืด

![หลอด LED 12V แบบแผงเลนส์สามดวง มีสายแดงและสายดำออกจากตัวแผง](images/led-module-12v.jpg){ width="45%" }

1. กลุ่มตกลง **ค่าเกณฑ์** ความสว่างที่ถือว่ามืด จากค่าตอนเปิดโล่งและตอนครอบที่จดไว้ในกิจกรรมที่ 1 ตอนเปิดโล่ง {{n:s1.light.room}} ตอนครอบ {{n:s1.light.test}} (แสงในห้องอาจต่างจากก่อนพัก ดูค่าปัจจุบันในหน้าอุปกรณ์แล้วแก้ตัวเลขถ้าเปลี่ยนไป) เลือกค่ากลาง ๆ ระหว่างสองค่านั้น เช่น ตอนสว่างได้ 80 ตอนมืดได้ 7 เกณฑ์อาจเป็น 40 หรือ 50
2. คนที่ใช้แล็ปท็อปเฝ้าค่าความสว่างในหน้าอุปกรณ์ เมื่อค่าต่ำกว่าเกณฑ์ ให้สั่งหลอดไฟ On เมื่อค่าสูงกว่าเกณฑ์ ให้สั่ง Off
3. อีกคนค่อย ๆ เอามือครอบบอร์ดแล้วเอาออก สลับกันหลายรอบ บางรอบครอบมิด บางรอบครอบแค่ครึ่ง เพื่อจำลองฟ้ามืด ฟ้าครึ้ม และฟ้าสว่าง สมาชิกอีกคนนับว่ารวมกี่รอบ และคนใช้แล็ปท็อปสั่งถูกกี่รอบ

> **บันทึกผล** ค่าเกณฑ์ความสว่างที่เลือก {{n:s1.light.on|4}} · ครอบและเอามือออกรวม {{n:s1.manual.rounds|2}} รอบ · สั่งถูก {{n:s1.manual.correct|2}} รอบ

ถ้าฟ้ามืดตอนหนึ่งทุ่มทุกวัน เราคงไม่อยากนั่งเฝ้าหน้าจอ ลองทบทวนว่าเมื่อครู่ใช้ข้อมูลใดตัดสินใจเปิดหรือปิดไฟ แล้วช่วยกันเขียนกฎเป็นประโยค **“ถ้า ... ให้ ...”** สองข้อ ข้อแรกสำหรับตอนมืด อีกข้อสำหรับตอนสว่าง เราจะสร้างกฎทั้งสองข้อใน Home Assistant ในข้อถัดไป
{: #a3-3b }

> **บันทึกผล** กฎที่เราใช้ตัดสินใจ
>

>
> สว่าง: ถ้า {{f:s1.rule.bright.if|24}} ให้ {{f:s1.rule.bright.then|24}}

### 3.4 automation สองข้อ: มืดเปิดไฟ สว่างปิดไฟ { #a3-4 }

automation หนึ่งข้อใน Home Assistant มีสามส่วน **trigger** (เมื่อไร) · **condition** (เงื่อนไขเพิ่มเติม ใส่หรือไม่ก็ได้) · **action** (ให้ทำอะไร) กฎเรื่องแสงใช้แค่สองส่วน

**ก่อนเริ่ม** ให้เซนเซอร์เปิดโล่งจนค่าความสว่างอยู่เหนือเกณฑ์ และสั่งหลอดไฟ Off ไว้

วางเมาส์บนป้าย 📷 ท้ายข้อเพื่อดูภาพหน้าจอของขั้นนั้น (บนหน้าจอสัมผัสให้แตะ)

1. **Settings → Automations & scenes** [📷](images/steps/s2-a5-01-settings-automations.png){ .glightbox data-title="Settings → Automations & scenes" }
2. กด **+ Create automation** ที่มุมล่างขวา [📷](images/steps/s2-a5-02-create-automation.png){ .glightbox data-title="ปุ่ม Create automation" } แล้วเลือก **Create new automation** [📷](images/steps/s2-a5-03-create-new.png){ .glightbox data-title="เลือก Create new automation" }
3. ในส่วน **When** กด **+ Add trigger** [📷](images/steps/s2-a5-04-add-trigger.png){ .glightbox data-title="ส่วน When กด Add trigger" }
4. พิมพ์ **ความสว่าง** ในช่องค้นหา แล้วกดที่ **ความสว่าง (light)** [📷](images/steps/s2-a5-05-search-light.png){ .glightbox data-title="ค้นหา ความสว่าง แล้วกดที่ entity" }
5. รายการทางขวาจะแสดง trigger ที่ใช้กับเซนเซอร์แสงได้ เลือก **Illuminance crossed threshold** [📷](images/steps/s2-a5-06-pick-crossed-threshold.png){ .glightbox data-title="เลือก Illuminance crossed threshold" }
6. แผงตั้งค่า trigger จะเปิดทางขวา ที่ **Threshold type** เลือก **Below** [📷](images/steps/s2-a5-07-threshold-below.png){ .glightbox data-title="Threshold type เลือก Below" } แล้วพิมพ์ค่าเกณฑ์ของกลุ่มในช่อง **Below** (หน่วย lx) [📷](images/steps/s2-a5-08-value-50.png){ .glightbox data-title="พิมพ์ค่าเกณฑ์ในช่อง Below" }
7. ในส่วน **Then do** กด **+ Add action** [📷](images/steps/s2-a5-09-add-action.png){ .glightbox data-title="ส่วน Then do กด Add action" }
8. พิมพ์ **รีเลย์** ในช่องค้นหา แล้วกดที่ **รีเลย์ (relay)** [📷](images/steps/s2-a5-10-search-relay.png){ .glightbox data-title="ค้นหา รีเลย์ แล้วกดที่ entity" } จากรายการทางขวาเลือก **Turn on switch** [📷](images/steps/s2-a5-11-turn-on-switch.png){ .glightbox data-title="เลือก Turn on switch" }
9. กด **Save** ที่มุมล่างขวา [📷](images/steps/s2-a5-12-save.png){ .glightbox data-title="ปุ่ม Save" } ตั้งชื่อ `มืด-เปิดไฟ` แล้วกด **Save** อีกครั้ง [📷](images/steps/s2-a5-13-save-name.png){ .glightbox data-title="ตั้งชื่อ automation แล้ว Save" }
10. หน้าจอจะกลับมาที่กฎที่สร้างเสร็จ มี trigger หนึ่งข้อและ action หนึ่งข้อ [📷](images/steps/s2-a5-15-editor-done.png){ .glightbox data-title="กฎที่สร้างเสร็จ" } กดลูกศรย้อนกลับด้านบนจะเห็นกฎใหม่ในรายการ Automations พร้อมสวิตช์เปิดอยู่ [📷](images/steps/s2-a5-14-list.png){ .glightbox data-title="รายการ Automations" }

![ตัวแก้ไข automation แสดง trigger แบบ Illuminance crossed threshold ของ ความสว่าง (light) และ action แบบ Turn on switch ของ รีเลย์ (relay)](images/steps/s2-a5-15-editor-done.png){ width="70%" }

**ทดสอบ** เอามือครอบเซนเซอร์แสงบนบอร์ดให้มิด ค้างไว้สองวินาที หลอดไฟต้องติดเอง เอามือออก หลอดยังไม่ดับ เพราะยังไม่มีกฎสั่งปิด สั่ง Off จากหน้าอุปกรณ์ก่อนไปต่อ

> trigger แบบ crossed threshold ทำงานเฉพาะตอนค่า **ข้าม** เส้นเกณฑ์ ถ้าค่าอยู่ใต้เกณฑ์อยู่แล้วตั้งแต่ก่อนสร้างกฎ จะยังไม่มีอะไรเกิดขึ้น ต้องทำให้ค่าขึ้นเหนือเกณฑ์ก่อนแล้วค่อยลดลงมาใหม่ บอร์ดส่งค่าแสงราววินาทีละครั้ง จึงต้องครอบค้างไว้สักครู่

**กฎข้อที่สอง** สร้าง automation อีกข้อด้วยวิธีเดิมตั้งแต่ข้อ 2 แต่ที่ **Threshold type** เลือก **Above** แล้วป้อน **ค่าเดียวกับเกณฑ์เปิด** และ action เลือก **Turn off switch** ตั้งชื่อ `สว่าง-ปิดไฟ`

**ทดสอบ** ครอบมิดสองวินาที ไฟติด · เอามือออก ไฟดับ ทำสามรอบ โดยไม่มีใครกดอะไร

> **เกณฑ์ผ่าน** ติดและดับเองครบทั้งสามรอบ ผลของเรา ผ่าน {{n:s1.auto.pass|2}} จาก 3 รอบ ถ้าไม่ผ่าน ดูที่ **Settings → Automations** ว่ากฎทั้งสองเปิดใช้อยู่ trigger ชี้ที่ `ความสว่าง (light)` และ action ชี้ที่รีเลย์ของบอร์ด **เรา** ไม่ใช่ของกลุ่มข้าง ๆ ถ้าไฟกะพริบตอนมือขยับช้า ๆ ใกล้เกณฑ์ ไม่ใช่ความผิดพลาด ให้ครอบให้มิดและเร็ว เรื่องนี้คือบทเรียนแรกของช่วงที่ 2

### 3.5 โจทย์เสริม: ปิดไฟตามเวลา { #a3-5 }

สำหรับกลุ่มที่เสร็จก่อนเวลา สวนบางแห่งไม่อยากเปิดไฟทั้งคืน แต่อยากให้ดับเองตอนสี่ทุ่ม กฎแบบนี้ไม่ได้ดูเซนเซอร์เลย แต่ดูนาฬิกา ให้กลุ่มเลือกเวลาดับไฟเองแล้วทดสอบ

1. ดูนาฬิกาบนแล็ปท็อป เลือกเวลาที่จะให้ไฟดับ ประมาณ 2 นาทีข้างหน้า จดไว้ {{f:s1.timer.at|5}} น.
2. สร้าง automation ใหม่ ในส่วน **When** กด **+ Add trigger → Time** ตั้ง **At** เป็นเวลานั้น ในส่วน **Then do** กด **+ Add action** ค้นหา **รีเลย์ (relay)** เลือก **Turn off switch** กด **Save** ตั้งชื่อ `ปิดไฟตามเวลา`
3. ทดสอบ: ให้เซนเซอร์เปิดโล่ง แล้วสั่งหลอดไฟ **On จากหน้าอุปกรณ์** (กฎ `สว่าง-ปิดไฟ` จะไม่มาปิด เพราะค่าแสงไม่ได้ข้ามเกณฑ์) รอโดยไม่แตะอะไร ไฟต้องดับเองเมื่อถึงเวลาที่ตั้ง
4. **ปิดสวิตช์ของกฎนี้** ใน Settings → Automations & scenes ทันทีที่ทดสอบเสร็จ ไม่อย่างนั้นกฎจะทำงานทุกวันเวลาเดิม รวมถึงพรุ่งนี้ตอนที่รีเลย์ต่อกับปั๊ม

> **บันทึกผล** ผล {{r:s1.timer.ok|ดับตรงเวลา|ไม่ดับ|ไม่ได้ทำ}} ถ้าไม่ดับ ดูว่าเวลาที่ตั้งผ่านไปแล้วหรือยัง เวลาที่ผ่านไปแล้วจะไม่ย้อนกลับมาเกิดอีก ต้องตั้งเวลาใหม่ในอนาคต

[↑ กลับไปที่ใบงาน](#a3){ .ws-back }

**คำถามท้ายกิจกรรม** ถ้าค่าแสงแกว่งอยู่ใกล้เกณฑ์พอดี เช่น เมฆลอยผ่านตอนพลบค่ำ หรือมือครอบบอร์ดแค่ครึ่งเดียว กฎสองข้อของเราจะทำอะไร (ยังไม่ต้องทดลองตอนนี้ เราจะทดลองและแก้ในช่วงที่ 2)

## ก่อนออกจากห้อง

เมื่อจบช่วงนี้ แล็ปท็อปนำติดตัวไปได้ แต่เก็บชุดอุปกรณ์ไว้ในห้องอบรมและจ่ายไฟให้บอร์ดเซนเซอร์ต่อเนื่องจนถึงช่วงที่ 2 เพื่อให้เริ่มใช้งานต่อได้โดยไม่ต้องต่อวงจรใหม่

ขณะนี้บอร์ดเซนเซอร์รับไฟจากแล็ปท็อป ก่อนออกจากห้องให้ย้ายสายไปใช้ช่อง USB ของกล่องจ่ายไฟตามขั้นตอนต่อไปนี้

- [ ] สั่งสวิตช์รีเลย์เป็น **Off** และตรวจในหน้าอุปกรณ์ว่าเป็น Off จริง หลอดไฟดับ
- [ ] ถ้าสร้างกฎ `ปิดไฟตามเวลา` ไว้ ตรวจว่า**ปิด**สวิตช์ของกฎนั้นแล้ว ส่วนกฎ `มืด-เปิดไฟ` และ `สว่าง-ปิดไฟ` เปิดทิ้งไว้ได้ เพราะ Home Assistant อยู่ในแล็ปท็อปที่เรานำกลับไปด้วย คืนนี้จึงไม่มีใครสั่งรีเลย์
- [ ] ยกสวิตช์ลูกลอยขึ้นจากแก้ว เช็ดให้แห้ง เก็บไว้กับชุดอุปกรณ์ เทน้ำในแก้วทิ้ง
- [ ] ถอดสาย USB-C ของบอร์ด GoGo-IoT ออกจากแล็ปท็อป แล้วเสียบเข้า **ช่อง USB ที่ว่างอีกช่องของ charge controller** (ช่องแรกมีบอร์ดรีเลย์ใช้อยู่) รอให้ไฟบอร์ดติดและค่ากลับมาขึ้นในหน้าอุปกรณ์ บอร์ดจะอยู่ที่ช่องนี้ไปตลอดหลักสูตร
- [ ] **อะแดปเตอร์ยังเสียบอยู่** กล่องจ่ายไฟต้องทำงานทั้งคืน บอร์ดทั้งสองรับไฟจากช่อง USB ของกล่องนี้ บอร์ดรีเลย์มีไฟแต่ไม่มีใครสั่ง หลอดจึงไม่ติด
- [ ] แล็ปท็อปปิดได้ตามปกติ

## สรุปช่วงที่ 1

1. **ระบบอัตโนมัติประกอบด้วยการรับข้อมูล การตัดสินใจ และการทำงานตามคำสั่ง** หรือ Input → Logic → Output ระบบถังน้ำที่ใช้ลูกลอยก็อธิบายด้วยหลักนี้ได้ โดยใช้กลไกเป็นส่วนตัดสินใจ
2. **ค่าที่วัดได้มีทั้งค่าต่อเนื่อง (แอนะล็อก) และสถานะ (ดิจิทัล)** ในกิจกรรมนี้เราใช้ค่าความชื้นและความสว่างดูการเปลี่ยนแปลง ส่วนลูกลอยใช้บอกว่าน้ำถึงระดับที่กำหนดหรือไม่
3. **รีเลย์ทำหน้าที่เปิด–ปิดวงจร** อุปกรณ์ปลายทาง ไม่ว่าหลอดไฟหรือปั๊ม ต้องรับไฟจากแหล่งจ่ายที่เหมาะสม โดยต่อผ่านหน้าสัมผัสรีเลย์ รีเลย์ไม่ได้เป็นแหล่งจ่ายไฟเอง
4. **ต้องมีวิธีสั่งงานด้วยมือเมื่อจำเป็น** เช่น สวิตช์ Auto / Off / Manual สำหรับเลือกวิธีควบคุมหรือหยุดอุปกรณ์
5. **หน้าจอแสดงข้อมูลจากระบบควบคุม** โทรศัพท์และแล็ปท็อปจึงดูข้อมูลชุดเดียวกันได้
6. **เขียนกฎให้ชัดก่อนตั้งค่าในโปรแกรม** เริ่มจากประโยค “ถ้า ... ให้ ...” แล้วกำหนด trigger และ action ใน Home Assistant เพื่อให้ระบบทำงานแทนเรา กฎที่ดู**ค่า**ต้องรอให้ค่าข้ามเกณฑ์ ส่วนกฎที่ดู**เวลา**ทำงานเมื่อถึงเวลาโดยไม่สนใจเซนเซอร์
7. **เลือกอุปกรณ์ให้ตรงกับงาน** หากความต้องการเกินสเปก ต้องเปลี่ยนอุปกรณ์ให้เหมาะสม
