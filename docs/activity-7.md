**85 นาที** เลือกโจทย์ 5 · การสื่อสาร 20 · พลังงาน 15 · เติมแบบร่างให้ครบ 30 · แลกเปลี่ยนกับกลุ่มที่จับคู่กัน 10 · ปรับแก้และบันทึก 5

**อุปกรณ์ที่ใช้** แบบร่างระบบท้าย[ใบบันทึกของกลุ่ม](record-sheet.md) ใบราคาอุปกรณ์ที่แจก (ราคาเป็นตัวอย่าง ณ วันที่ระบุในใบ) ไฟล์ตั้งค่า ESPHome ที่แจก กล่องจ่ายไฟและแผงโซลาร์เซลล์ในชุด โทรศัพท์สำหรับค้นราคาเพิ่มถ้าต้องการ

> **ตกลงกันก่อนว่าใครจะเป็นผู้จดลงแบบร่าง** แล้วช่วยกันคิดและตัดสินใจทุกส่วน

ออกแบบการทดลอง **หนึ่งปัญหา หนึ่งจุดในฟาร์ม** ใช้ข้อมูลจริงเท่าที่มี หากยังไม่รู้ ให้บันทึกว่าจะถามใครหรือวัดอะไรเพิ่มก่อนซื้อ

เลือกวิธีสื่อสารและแหล่งจ่ายไฟก่อน แล้วเติมอุปกรณ์ กฎ งบประมาณ และแผนทดลอง

### 7.1 เลือกโจทย์ { #a7-1 }

**กำหนดโจทย์ของกลุ่ม**

1. เลือกสถานการณ์จากบัตรหนึ่งใบ หรือใช้ฟาร์มของสมาชิกในกลุ่ม เขียนข้อมูลฟาร์มและปัญหาที่ต้องการแก้ไว้ส่วนต้นของแบบร่าง

| บัตร | สถานการณ์ |
|------|-----------|
| **A โรงเรือนผัก** | โรงเรือน 6 × 20 เมตร ใกล้บ้าน มีไฟบ้านและ WiFi ถึง ปลูกผักสลัด ปัญหาคือร้อนจัดช่วงบ่ายและรดน้ำไม่สม่ำเสมอเมื่อเจ้าของไม่อยู่ |
| **B สวนผลไม้ 10 ไร่** | ลำไยหรือมะม่วง แปลงยาว 400 เมตรจากบ้าน มีไฟที่หัวแปลง ต้องการรู้ความชื้นดิน 3–4 จุดกระจายทั่วสวน และสั่งวาล์วน้ำหยดเป็นโซน |
| **C ไฮโดรโปนิกส์** (ขั้นสูง) | โต๊ะปลูก 8 โต๊ะในโรงเรือน ต้องเฝ้าระดับน้ำ อุณหภูมิน้ำ และค่า EC/pH ปั๊มหมุนเวียนจะหยุดนานเกิน 30 นาทีไม่ได้ |
| **D แปลงห่างไกล ไม่มีไฟ** (ขั้นสูง) | ข้าวโพดหรือมันสำปะหลัง 20 ไร่ ห่างบ้าน 3 กิโลเมตร ไม่มีไฟบ้าน สัญญาณมือถืออ่อน ต้องการรู้ความชื้นดินและระดับน้ำในบ่อ และสั่งปั๊มโซลาร์ |
| **E ฟาร์มของเราเอง** | หากมีสมาชิกทำฟาร์มและมีข้อมูลพื้นที่ชัดเจน ให้ใช้ฟาร์มนั้นเป็นโจทย์แทนบัตรได้ เริ่มจากปัญหาที่เขียนไว้ตอนเริ่มช่วงที่ 1 ระบุขนาดพื้นที่ ระยะจากบ้าน แหล่งจ่ายไฟ สัญญาณมือถือ และวิธีที่ใช้แก้ปัญหาอยู่ในปัจจุบัน |

> หากมีข้อมูลฟาร์มจริง ให้เลือก E บัตร C–D เหมาะกับกลุ่มที่คุ้นเคยกับอุปกรณ์เฉพาะทาง หากยังไม่รู้ ให้ระบุไว้ในช่อง “สิ่งที่ยังไม่แน่ใจ”

### 7.2 สำรวจเครือข่ายในห้อง { #a7-2 }


**อ่านการตั้งค่าเครือข่าย**

1. เปิดไฟล์ ESPHome ที่แจก หา **ssid** (ชื่อ WiFi), **name_add_mac_suffix** (เติมรหัสท้ายชื่อบอร์ด) และ **api** (เชื่อมกับ Home Assistant)

**เปิดหน้าเว็บผ่านเครือข่ายภายใน**

2. ใน **Settings → Devices & services → ESPHome** เปิดอุปกรณ์และอ่านค่า **หมายเลข IP**
3. เปิดแท็บใหม่ พิมพ์ `http://` ตามด้วย IP เพื่อเปิดหน้าเว็บของบอร์ด

> บอร์ดกับ Home Assistant สื่อสารผ่านเครือข่ายภายใน ไม่จำเป็นต้องผ่านอินเทอร์เน็ต ส่วนการดูจากนอกฟาร์มต้องมีช่องทางเพิ่ม

### 7.3 เลือกเครือข่ายในฟาร์ม { #a7-2b }

**เปรียบเทียบวิธีสื่อสาร**

1. พิจารณา **ระยะทาง → แหล่งจ่ายไฟ → ปริมาณข้อมูล → ค่าใช้จ่าย** ใช้ตารางนี้เลือกวิธีที่ควรนำไปทดสอบ ไม่ต้องจำทุกเทคโนโลยี

| วิธี | เหมาะกับงานแบบใด | พลังงานและข้อมูล | ค่าใช้จ่ายที่ต้องคิด |
|---|---|---|---|
| **WiFi** | จุดที่รับสัญญาณเราเตอร์ได้ | ส่งข้อมูลได้มาก; ต้องวางแผนไฟเลี้ยง | เราเตอร์และการขยายสัญญาณ |
| **ESP-NOW** | บอร์ด Espressif ส่งข้อมูลหากัน | ข้อมูลเป็นชุดเล็ก; การใช้ไฟขึ้นกับช่วงส่ง | บอร์ดและตัวเชื่อมเข้า Home Assistant |
| **Zigbee** | เซนเซอร์หลายจุดที่มีเครือข่ายส่งต่อถึงกัน | ข้อมูลน้อย; เซนเซอร์บางรุ่นใช้ถ่าน | ตัวรับและอุปกรณ์ส่งต่อที่มีไฟเลี้ยง |
| **LoRa / LoRaWAN** | ส่งค่าจำนวนน้อยระยะไกล | ใช้ไฟต่ำเมื่อส่งเป็นช่วง; ไม่เหมาะกับวิดีโอ | โมดูล ตัวรับ หรือเกตเวย์ตามระบบ |
| **เครือข่ายมือถือ / NB-IoT** | จุดที่มีสัญญาณและบริการรองรับ | ขึ้นกับโมดูลและความถี่ส่ง | โมดูล ซิม และค่าบริการ |
| **RS-485** | จุดที่เดินสายได้ | ข้อมูลเซนเซอร์หรือคำสั่งผ่านสาย | อุปกรณ์ สาย และค่าติดตั้ง |

**ตัวอย่างบัตร B:** จุดวัดอยู่ห่างบ้าน 400 เมตรและไม่มีไฟ ควรสำรวจเส้นทางสาย สัญญาณ และไฟเลี้ยงก่อนเลือก LoRa หรือวิธีอื่น อย่าตัดสินว่าใช้ได้จากระยะที่ระบุในโฆษณาเพียงอย่างเดียว

**เลือกวิธีสำหรับแต่ละจุด**

2. กรอกสองจุดเชื่อมต่อของกลุ่มในตาราง ถ้ายังไม่รู้ระยะหรือแหล่งจ่ายไฟ ให้ระบุว่าต้องสำรวจอะไร ช่อง “ตัดออก” ใส่เหตุผล หรือ “ยังต้องทดสอบ” ได้

| จุดเชื่อมต่อในโจทย์ของเรา | ระยะ (เมตร) | มีไฟที่ปลายทาง | ตัดออกเพราะระยะ | ตัดออกเพราะไม่มีไฟ | เหลือให้เลือก |
|---|---|---|---|---|---|
| เซนเซอร์ → ระบบควบคุม | {{n:s3.net.1.dist|4}} | {{r:s3.net.1.power|มี|ไม่มี}} | {{f:s3.net.1.out_dist|12}} | {{f:s3.net.1.out_power|12}} | {{f:s3.net.1.left|12}} |
| ระบบควบคุม → อุปกรณ์ปลายทาง | {{n:s3.net.2.dist|4}} | {{r:s3.net.2.power|มี|ไม่มี}} | {{f:s3.net.2.out_dist|12}} | {{f:s3.net.2.out_power|12}} | {{f:s3.net.2.left|12}} |

**บันทึกลงแบบร่าง**

3. เติมสองแถวแรกในตาราง **พลังงานและการสื่อสาร** ของแบบร่าง ระบุวิธีที่เลือกและเหตุผลจากปัจจัยทั้งสี่

### 7.4 เปรียบเทียบระบบในฟาร์มกับคลาวด์ { #a7-2c }

**เปรียบเทียบเมื่ออินเทอร์เน็ตดับ**

1. สมมติว่าอินเทอร์เน็ตของฟาร์มดับ แต่ไฟฟ้าและเครือข่ายภายในยังใช้ได้ เติมตารางเปรียบเทียบระบบของเรากับระบบที่เก็บข้อมูลและตัดสินใจบนคลาวด์ทั้งหมด โดยไม่มีการทำงานสำรองในฟาร์ม

| | ระบบของเรา | ระบบที่ประมวลผลและสั่งงานบนคลาวด์ |
|--|-----------|---------------------------|
| automation ยังทำงานหรือไม่ | {{f:s3.cloud.auto.ours|8}} | {{f:s3.cloud.auto.cloud|8}} |
| ดูแดชบอร์ดจากในฟาร์ม | {{f:s3.cloud.farm.ours|8}} | {{f:s3.cloud.farm.cloud|8}} |
| ดูข้อมูลปัจจุบันจากนอกฟาร์ม | {{f:s3.cloud.city.ours|8}} | {{f:s3.cloud.city.cloud|8}} |
| ข้อมูลใหม่ยังบันทึกหรือไม่ | {{f:s3.cloud.log.ours|8}} | {{f:s3.cloud.log.cloud|8}} |

**สำรวจทางเลือกการเข้าถึงจากภายนอก**

2. อ่านตารางแล้วเปรียบเทียบงานที่ทำได้ ค่าบริการ และผู้ดูแล ทุกวิธีต้องมีอินเทอร์เน็ตที่ฟาร์ม

| วิธี | ใช้ทำอะไร | ต้องเตรียมอะไร |
|---|---|---|

| **Home Assistant Cloud** | เปิดแดชบอร์ดและสั่งงานจากภายนอก | บัญชีและบริการสมัครสมาชิก |
| **VPN** | เชื่อมเข้าเครือข่ายส่วนตัวของฟาร์ม | ตั้งค่าการเชื่อมต่อและสิทธิ์ของผู้ใช้ |
| **ส่งข้อมูลขึ้นคลาวด์** | ดูข้อมูลหลายจุดบนเว็บของผู้ให้บริการ | บัญชีและการส่งข้อมูล; ตรวจว่ากฎทำงานอยู่ที่ใด |

### 7.5 ดูสาธิตการเข้าถึงจากนอกฟาร์ม { #a7-2d }

ใช้ชุดของผู้สอน กลุ่มดูและบันทึกผล

**ดูช่องทางเข้าถึงจากภายนอก**

1. ผู้สอนเปิด **Settings → Home Assistant Cloud** ให้ดูสวิตช์ **Remote access** และที่อยู่สำหรับเข้าถึงระบบจากภายนอก

**ทดสอบผ่านอินเทอร์เน็ตมือถือ**

2. ปิด WiFi บนโทรศัพท์ แล้วใช้อินเทอร์เน็ตมือถือเปิดที่อยู่นั้น สังเกตว่าเป็นแดชบอร์ดเดียวกับที่เปิดดูในเครือข่ายของห้องอบรม
3. เป่าลมใส่บอร์ด สังเกตค่าที่เปลี่ยนบนโทรศัพท์ แล้วทดลองสั่งปั๊มหนึ่งครั้ง

ในการสาธิตนี้ Home Assistant ที่ฟาร์มยังตัดสินใจและบันทึกข้อมูล บริการคลาวด์ช่วยให้เข้าถึงเครื่องเดิมจากภายนอก

**บันทึกผล**

4. โทรศัพท์ของผู้สอนดูแดชบอร์ดผ่าน {{r:s3.remote.conn|อินเทอร์เน็ตมือถือ|WiFi ของโซน}} · ส่วนที่ตัดสินใจและบันทึกข้อมูลอยู่ที่ {{r:s3.remote.where|ในฟาร์ม (แล็ปท็อป)|บนคลาวด์}}

### 7.7 สำรวจกล่องจ่ายไฟ { #a7-3 }

**Charge controller** ควบคุมการชาร์จแบตเตอรี่จากแผงโซลาร์เซลล์ และจ่ายไฟให้โหลดตามการตั้งค่า ชุดอบรมใช้อะแดปเตอร์ 12V ที่ขั้วแบตเตอรี่แทนแบตเตอรี่จริง

**ไม่ต่อแผงโซลาร์เซลล์ในชุดนี้** เพราะไม่มีแบตเตอรี่รับพลังงานจากการชาร์จ

**ไล่สายและตรวจขั้วต่อ**

ดูขั้วต่อด้านล่างของกล่องจ่ายไฟ แล้วไล่สายของกลุ่มจากซ้ายไปขวา:

1. ตรวจ **ขั้วแผงโซลาร์เซลล์:** ยังไม่ได้ต่อสาย
2. ตรวจ **ขั้วแบตเตอรี่:** ต่อกับอะแดปเตอร์ของชุดทดลอง
3. ตรวจ **ขั้วโหลด DC:** ต่อไปยังแผงต่อสาย แล้วผ่านรีเลย์ไปยังปั๊ม
4. ตรวจ **ช่อง USB สองช่อง:** จ่ายไฟให้บอร์ดทั้งสอง

> ไอคอนแบตเตอรี่ประเมินจากแรงดัน จึงอาจแสดง “ไม่เต็ม” แม้อะแดปเตอร์ยังจ่ายไฟอยู่ ไอคอนไม่ได้วัดพลังงานที่เก็บไว้จริง

**บันทึกผล**

5. จอแสดง {{n:s3.pwr.volt|5}} V · ไอคอนแบตเตอรี่แสดงว่า {{r:s3.pwr.icon|เต็ม|ไม่เต็ม}}

### 7.8 คำนวณพลังงานและจำนวนแผง { #a7-3b }

**โจทย์คำนวณเบื้องต้น:** สมมติว่าแผง 15 W ได้แดดเทียบเท่าเต็มกำลัง 4 ชั่วโมงต่อวัน จึงผลิตได้ **60 Wh/วัน** ยังไม่หักการสูญเสีย กำลังไฟในตารางเป็นค่าที่กำหนดให้ฝึกคำนวณ

**คำนวณพลังงานและจำนวนแผง**

1. คำนวณแต่ละแถวในตาราง: **พลังงานต่อวัน (Wh) = กำลังไฟ (W) × ชั่วโมงทำงาน**
2. คำนวณ **จำนวนแผง = พลังงานต่อวัน ÷ 60** ปัดขึ้นเป็นจำนวนเต็ม
3. เลือกว่าต้องมีแบตเตอรี่หรือไม่ ถ้าคำตอบขึ้นกับเวลาใช้งาน ให้ตกลงสมมติฐานกับกลุ่มก่อน

> จำนวนแผงจากพลังงานต่อวันยังไม่พอสำหรับเลือกซื้อ ต้องตรวจด้วยว่ากำลังขณะใช้งานและตอนเริ่มเดินเครื่องเพียงพอ เช่น แผง 15 W จ่ายให้ปั๊ม 18 W โดยตรงไม่พอ

| โหลด | กำลัง | ทำงานวันละ | ใช้ไฟต่อวัน (Wh) | แผง 15 W กี่แผง | ต้องมีแบตเตอรี่ไหม |
|---|---|---|---|---|---|
| บอร์ดเซนเซอร์ GoGo-IoT | 0.5 W | 24 ชั่วโมง | {{n:s3.pwr.size.node.wh|5}} | {{n:s3.pwr.size.node.panels|3}} | {{r:s3.pwr.size.node.bat|ต้องมี|ไม่ต้อง}} |
| เราเตอร์ + เครื่องที่รัน Home Assistant | 10 W | 24 ชั่วโมง | {{n:s3.pwr.size.ha.wh|5}} | {{n:s3.pwr.size.ha.panels|3}} | {{r:s3.pwr.size.ha.bat|ต้องมี|ไม่ต้อง}} |
| ปั๊มในชุดทดลอง 12V | 18 W | 2 ชั่วโมง | {{n:s3.pwr.size.kitpump.wh|5}} | {{n:s3.pwr.size.kitpump.panels|3}} | {{r:s3.pwr.size.kitpump.bat|ต้องมี|ไม่ต้อง}} |
| ปั๊มฟาร์ม (สมมติกินไฟ 750 W) | 750 W | 3 ชั่วโมง | {{n:s3.pwr.size.farmpump.wh|5}} | {{n:s3.pwr.size.farmpump.panels|3}} | {{r:s3.pwr.size.farmpump.bat|ต้องมี|ไม่ต้อง}} |

**คำนวณพลังงานสำรองกลางคืน**

4. คำนวณและกรอกพลังงานที่ต้องสำรอง อุปกรณ์ที่ต้องทำงานตอนกลางคืนต้องมีพลังงานสำรองอย่างน้อยหนึ่งคืน ในตัวอย่างนี้ให้คิดเป็น 12 ชั่วโมง บอร์ดเซนเซอร์ใช้ {{n:s3.pwr.size.night_node|4}} Wh ต่อคืน · ปั๊มฟาร์มถ้าจะเดินตอนกลางคืน 3 ชั่วโมง ใช้ {{n:s3.pwr.size.night_pump|5}} Wh ต่อคืน

**ตรวจคำตอบ**

5. เปิดเฉลยด้านล่างหลังคำนวณ แล้วทบทวนจุดที่ต่างจากคำตอบของกลุ่ม

<details markdown="1">
<summary>ตรวจคำตอบหลังคำนวณ</summary>

| อุปกรณ์ | Wh/วัน | จำนวนแผงขั้นต่ำตามสูตร |
|---|---:|---:|
| บอร์ดเซนเซอร์ | 12 | 1 |
| เราเตอร์ + Home Assistant | 240 | 4 |
| ปั๊มในชุดทดลอง | 36 | 1 |
| ปั๊มฟาร์ม | 2,250 | 38 |

หนึ่งคืน บอร์ดใช้ **6 Wh**; ปั๊มฟาร์มที่เดิน 3 ชั่วโมงใช้ **2,250 Wh** อุปกรณ์ที่ทำงานกลางคืนต้องมีพลังงานสำรอง ส่วนปั๊มที่ทำงานเฉพาะตอนแดดพออาจไม่ต้องมีแบตเตอรี่ แต่ต้องใช้แผงและชุดควบคุมที่จ่ายกำลังได้เพียงพอ

</details>

**นำไปใช้:** แยกคิดไฟเลี้ยงเซนเซอร์ ระบบควบคุม และปั๊ม อุปกรณ์ที่ต้องทำงานทั้งคืนต้องมีไฟต่อเนื่อง ส่วนปั๊มอาจเลือกสูบตอนมีแดดแล้วเก็บน้ำไว้ใช้

**เลือกแหล่งพลังงานในแบบร่าง**

6. เติม **แหล่งพลังงานของอุปกรณ์แต่ละจุด** ในแบบร่าง: เซนเซอร์ · ระบบควบคุมและเราเตอร์ · ปั๊ม ระบุไฟบ้าน / โซลาร์กลางวัน / โซลาร์พร้อมแบตเตอรี่ / แบตเตอรี่

> แผงที่โดนแสงมีแรงดันที่ขั้ว ห้ามให้ขั้วบวก–ลบแตะกัน การต่อระบบจริงต้องใช้แบตเตอรี่และอุปกรณ์ที่เข้ากัน และทำตามลำดับในคู่มือของรุ่นนั้น

### 7.9 เติมแบบร่างให้ครบ { #a7-4 }

เติมรายละเอียดส่วนที่เหลือให้ครบ โดยใช้ใบราคาอุปกรณ์ที่แจก หากมีเวลา สามารถค้นข้อมูลเพิ่มเติมจากโทรศัพท์ได้

**ระบุอุปกรณ์และกฎควบคุม**

1. เติม **Input:** เซนเซอร์ที่เลือก พร้อมสเปกและราคา
2. เติม **Output:** อุปกรณ์ที่รับคำสั่งไปทำงาน วงจรขับ และวิธีตรวจว่าทำงานจริง
3. เติม **Logic:** กฎควบคุมสามข้อ
**วางแผนป้องกันและดูแล**

4. เติม **fail-safe และ manual override:** วิธีรับมือเมื่อระบบขัดข้อง และวิธีสั่งงานด้วยตนเอง
5. เติม **การดูแลและงบประมาณ**
**เตรียมทดลองและตรวจข้อมูล**

6. เติม **แผนทดลองครั้งแรก**
7. เติม **สิ่งที่ยังไม่แน่ใจและต้องตรวจสอบเพิ่มเติม**

### 7.11 ตรวจแบบร่าง { #a7-6 }

**ตรวจความครบถ้วนก่อนส่ง**

1. ตรวจว่าอุปกรณ์มีสเปกและราคาอ้างอิงจากใบราคาหรือแหล่งที่ค้น ระบุวันที่และรายการที่ยังต้องเช็กราคา
2. ตรวจว่าระบุชนิดสัญญาณของเซนเซอร์จากสเปก ไม่ตัดสินจากการแสดงเป็นตัวเลขบนจอ
3. ตรวจว่าอธิบายวิธีสื่อสารจากระยะ พลังงาน ปริมาณข้อมูล และค่าใช้จ่าย
**ตรวจพลังงานและการป้องกัน**

4. ตรวจว่าระบุแหล่งจ่ายไฟของเซนเซอร์ ระบบควบคุม และปั๊ม
5. ตรวจว่ามี fail-safe อย่างน้อยหนึ่งข้อ พร้อมบอกว่าอยู่ที่ใด และมีวิธีสั่งงานด้วยมือ
**ตรวจแผนดูแลและทดลอง**

6. ตรวจว่าระบุผู้ดูแล งานตรวจประจำ และงบประมาณ
7. ตรวจว่ามีแผนทดลองหนึ่งจุด เกณฑ์วัดผล และสิ่งที่ต้องตรวจสอบก่อนซื้อ

- [ ] **Settings → Automations & scenes** ปิดสวิตช์ automation ทุกข้อที่สั่งรีเลย์ได้ (กฎรดน้ำสองข้อ fail-safe ทุกข้อ และตรวจซ้ำว่ากฎไฟสวนกับกฎตั้งเวลาปิดไว้)
- [ ] สั่งสวิตช์รีเลย์เป็น **Off** จากหน้าอุปกรณ์ แล้วดูว่าปั๊มหยุด
- [ ] ถอดอะแดปเตอร์ออกจากปลั๊ก ปิดสวิตช์บอร์ด GoGo-IoT แล้วถอด USB ของบอร์ดทั้งสอง ก่อนถอดสายโหลดและสายอะแดปเตอร์จากกล่องจ่ายไฟ
- [ ] เมื่อไม่มีไฟแล้ว ยกสวิตช์ลูกลอยออกจากแก้ว เช็ดให้แห้ง เทน้ำในแก้วทิ้ง
- [ ] ตรวจรายการอุปกรณ์ตาม [หน้าแรก](index.md) แล้วคืนทั้งชุดพร้อมบัตรประจำกลุ่ม
- [ ] **เก็บคำตอบของกลุ่มไว้** กด **ดาวน์โหลดคำตอบ** ที่หัวหน้านี้แล้วส่งไฟล์ให้ผู้สอน จากนั้นเปิด[ใบบันทึกของกลุ่ม](record-sheet.md) แล้วกด **พิมพ์ / บันทึก PDF** เก็บแบบร่างนี้ไว้ใช้วางแผนทดลองในฟาร์มต่อ
