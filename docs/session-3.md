# ช่วงที่ 3 — โครงสร้างระบบ IoT: การสื่อสาร คลาวด์ แดชบอร์ด และการออกแบบระบบ

**เข้าใจการเชื่อมต่อและพลังงาน ก่อนออกแบบระบบสำหรับฟาร์ม**

สองช่วงที่ผ่านมาเราใช้งานบอร์ดร่วมกับ Home Assistant ได้แล้ว ช่วงนี้จะมาดูว่าข้อมูลส่งถึงกันได้อย่างไร และอุปกรณ์ในแปลงที่ไม่มีไฟฟ้าจะใช้พลังงานจากที่ใด จากนั้นสร้างแดชบอร์ดสำหรับผู้ใช้จริง และออกแบบระบบสำหรับฟาร์มโดยพิจารณาทั้งอุปกรณ์ การสื่อสาร พลังงาน และงบประมาณ

> **เมื่อจบช่วงนี้** ทีมจะมีแดชบอร์ดที่ผู้อื่นใช้งานได้ ทดลองดูข้อมูลจากนอกฟาร์ม เข้าใจการจ่ายไฟให้อุปกรณ์ในแปลง และมีแบบร่างระบบสำหรับฟาร์มหนึ่งชุด


## ก่อนเริ่ม

- [ ] เปิด Home Assistant ของทีม ตรวจว่า entity ของบอร์ดทั้งสองแสดงค่า
- [ ] เปิดสวิตช์ automation `รดน้ำ - เปิดปั๊ม` กลับ (ปิดไว้ตอนจบช่วงที่ 2) ระบบรดน้ำจากช่วงที่ 2 ต้องครบ: automation รดน้ำสองข้อและ fail-safe เปิดอยู่ ปั๊มจมในใบ A น้ำวน ลูกลอยในใบ A

## บอร์ดกับ Home Assistant ติดต่อกันอย่างไร

**20 นาที บรรยาย**

**อุปกรณ์ที่ใช้** ไฟล์ตั้งค่า ESPHome ที่แจก (ดูส่วนบนของไฟล์)

![ไฟล์ YAML ของ ESPHome ส่วน esphome, wifi และ api เน้น name_add_mac_suffix, ssid และบล็อก api ที่ไม่มีบรรทัดเข้ารหัส](images/placeholder.png){ width="55%" }

เปิดไฟล์ตั้งค่าแล้วหาสามรายการ ได้แก่ **ssid** ซึ่งระบุชื่อ WiFi ที่บอร์ดใช้, **name_add_mac_suffix** ซึ่งทำให้ชื่อบอร์ดไม่ซ้ำกัน และ **api** ซึ่งกำหนดการเชื่อมต่อกับ Home Assistant รวมถึงการเข้ารหัส ทั้งบอร์ด GoGo-IoT และบอร์ดรีเลย์มีการตั้งค่าส่วนนี้

> ในไฟล์นี้ **ไม่ได้กำหนดหมายเลข IP ไว้** เพราะบอร์ดขอหมายเลขจากเราเตอร์เมื่อเชื่อมต่อ แล้วประกาศชื่อของตนเองบนเครือข่าย Home Assistant จึงค้นพบบอร์ดและแสดงรายการให้เลือกได้ โดยเราไม่ต้องกรอก IP เอง

จากนั้นไปที่ **Settings → Devices & services → ESPHome** กดที่อุปกรณ์ จะเห็น entity ชื่อ **หมายเลข IP** บอกว่าเราเตอร์ให้ IP อะไรกับบอร์ดตัวนี้ ลองเทียบกับของทีมข้าง ๆ เปิดแท็บใหม่ พิมพ์ `http://` ตามด้วย IP นั้น จะเจอหน้าเว็บของบอร์ดเอง เหมือนที่เราใช้ในช่วงที่ 1 ก่อนเพิ่มบอร์ดเข้า Home Assistant **บอร์ดตัวนี้เป็นเว็บเซิร์ฟเวอร์** อยู่ในเครือข่ายเดียวกับเรา และ Home Assistant ก็คุยกับบอร์ดผ่านเครือข่ายเดียวกันนี้เอง

> ในช่วงที่ 2 เมื่อทีมที่จับคู่กันปิด WiFi บนแล็ปท็อป บอร์ดทั้งสองและ Home Assistant ยังทำงานอยู่ แต่ติดต่อกันไม่ได้ เพราะการเชื่อมต่อเครือข่ายถูกตัด

## จ่ายไฟให้อุปกรณ์ในแปลงอย่างไร

**20 นาที**

**อุปกรณ์ที่ใช้** กล่องจ่ายไฟที่ต่ออยู่แล้วตั้งแต่ช่วงที่ 1, แผงโซลาร์เซลล์ 12V 15W, สายไฟ

> **สลับคนใช้แล็ปท็อปก่อนเริ่ม**

อุปกรณ์ที่ติดตั้งกลางแปลงอาจอยู่ไกลจากจุดจ่ายไฟ จึงต้องวางแผนแหล่งพลังงานด้วย ระบบโซลาร์เซลล์ขนาดเล็กมีส่วนสำคัญสามส่วน ได้แก่ **แผงโซลาร์เซลล์** ผลิตไฟ **แบตเตอรี่** เก็บพลังงานไว้ใช้ และ **charge controller** ควบคุมการชาร์จและการจ่ายไฟให้โหลด เพื่อไม่ให้แบตเตอรี่ชาร์จเกินหรือคายประจุมากเกินไป

อุปกรณ์ที่เราเรียกว่า “กล่องจ่ายไฟ” ตั้งแต่ช่วงที่ 1 คือ charge controller โดยชุดทดลองใช้ **อะแดปเตอร์ 12V ต่อแทนแบตเตอรี่** เพื่อจ่ายไฟให้ปั๊มและบอร์ด ในกิจกรรมนี้จะศึกษาหน้าที่ของขั้วต่อต่าง ๆ แล้วต่อแผงโซลาร์เซลล์เพิ่ม

![charge controller PWM ด้านหน้า: จอ LCD สามปุ่ม ช่อง USB สองช่อง และขั้วต่อหกขั้วด้านล่าง แบ่งเป็นสามคู่ พร้อมป้าย แผง แบตเตอรี่ โหลด สองคู่หลังมีสายต่ออยู่แล้ว](images/placeholder.png){ width="55%" }

### รู้จักขั้วต่อและอ่านค่าบนหน้าจอ

ขั้วต่อด้านล่างมีสามคู่ จากซ้ายไปขวา คือ **แผงโซลาร์เซลล์** (สัญลักษณ์แผง) **แบตเตอรี่** (สัญลักษณ์แบตเตอรี่) และ **โหลด DC** (สัญลักษณ์หลอดไฟ) ไล่สายที่ต่ออยู่แล้วให้ครบ

- คู่กลาง: ต่ออะแดปเตอร์แทนแบตเตอรี่เพื่อจ่ายไฟให้ชุดทดลอง
- คู่ขวา: ไปแผงต่อสาย แล้วผ่านรีเลย์ไปปั๊ม นี่คือโหลด 12V ของระบบ
- ช่อง USB สองช่อง: โหลด 5V อีกทางหนึ่ง บอร์ดรีเลย์ใช้ตั้งแต่ช่วงที่ 1 และบอร์ด GoGo-IoT ใช้ตั้งแต่จบช่วงที่ 1
- คู่ซ้าย: ยังว่างอยู่ เพราะยังไม่ได้ต่อแผงโซลาร์เซลล์

สังเกตว่าอุปกรณ์ทุกชิ้นของทีมเรา ยกเว้นแล็ปท็อป ใช้ไฟจากกล่องนี้กล่องเดียวมาตั้งแต่จบช่วงที่ 1

จอแสดงแรงดันของ "แบตเตอรี่" และไอคอนต่าง ๆ อ่านค่าแรงดันและดูไอคอนแบตเตอรี่ว่าบอกเต็มหรือไม่

> จอจะแสดงแรงดันประมาณ 12 V แต่ไอคอนแบตเตอรี่จะดู **ไม่เต็ม** แม้อะแดปเตอร์ยังจ่ายไฟอยู่ เพราะแบตเตอรี่ตะกั่วกรดที่ชาร์จเต็มมีแรงดันประมาณ 12.7–13.0 V charge controller ประเมินจากแรงดันที่วัดได้ จึงไม่รู้ว่าแหล่งจ่ายเป็นอะแดปเตอร์ ตัวอย่างนี้ช่วยให้เห็นว่าอุปกรณ์ตัดสินใจได้จากข้อมูลที่วัดได้เท่านั้น

### ตั้งชนิดแบตเตอรี่

กดปุ่มเมนู 5 ครั้ง แล้วกดค้าง 10 วินาที จอจะแสดง `b01` ใช้ปุ่ม + และ − ดูตัวเลือก: `b01` ตะกั่วกรด · `b02` ลิเธียมไอออน · `b03` ลิเธียมไอรอนฟอสเฟต (LiFePO4) แล้วกลับมาที่ `b01`

> charge controller ตัดโหลดเมื่อแบตเตอรี่ต่ำ และหยุดชาร์จเมื่อเต็ม แต่ "ต่ำ" กับ "เต็ม" ของแบตเตอรี่แต่ละชนิดเป็นแรงดันคนละค่า ถ้าตั้งผิดชนิด แบตเตอรี่จะเสื่อมเร็ว หรือโดนตัดไฟก่อนเวลา ถ้าใช้ถ่าน 18650 แบบเดียวกับที่อยู่ในบอร์ด GoGo-IoT ต่ออนุกรมเป็นแบตเตอรี่จริง ต้องเลือก `b02`

### ต่อแผง

ลำดับการต่อสำคัญมาก charge controller ต้องรู้แรงดันของระบบจากแบตเตอรี่ก่อน จึงจะรับไฟจากแผงได้ถูกต้อง ของเราต่อแบตเตอรี่ (อะแดปเตอร์) ไว้แล้ว จึงต่อแผงได้เลย

1. ต่อสายจากแผงเข้า **คู่ซ้าย** (สัญลักษณ์แผง) บวกเข้าบวก ลบเข้าลบ ห้ามให้ปลายสายสองเส้นแตะกัน
2. ดูไอคอนแผงและกระแสชาร์จบนจอ ในห้องจะได้เกือบศูนย์
3. ยกแผงไปใกล้หน้าต่างหรือโคมไฟ แล้วดูตัวเลขอีกครั้ง
4. **ดูผู้สอนสาธิตบนจอ ทีมไม่ต้องทำเอง** ผู้สอนถอดปลั๊กอะแดปเตอร์ของชุดผู้สอนออก 10 วินาทีขณะแผงยังต่ออยู่ ดูว่าจอดับ บอร์ดดับ หรือยังติด การสาธิตนี้ใช้เปรียบเทียบกับกรณีที่แผงผลิตไฟไม่ได้และระบบไม่มีแบตเตอรี่สำรอง แผงอย่างเดียวเลี้ยงระบบไม่ได้ ให้สังเกตจากชุดสาธิตของผู้สอนเท่านั้น เนื่องจากการถอดแบตเตอรี่ออกทั้งที่แผงยังต่ออยู่ผิดลำดับที่คู่มือ charge controller กำหนด ผู้เข้าอบรมจึงไม่ต้องทดลองถอดตาม

Home Assistant บันทึกข้อมูลมาตั้งแต่ต้นช่วงที่ 2 เราจะย้อนดูข้อมูลเหล่านี้ แล้วเชื่อมโยงการเปลี่ยนแปลงบนกราฟกับสิ่งที่ทีมทดลองทำ

**คำถามที่กราฟนี้ตอบไม่ได้** ช่วงพักหลังช่วงที่ 1 บอร์ดเซนเซอร์ยังเสียบไฟและยังอ่านค่าอยู่ในห้องนี้ แต่กราฟไม่มีข้อมูลของช่วงนั้นเลย เพราะอะไร {{f:s3.hist.why_gap|30}} ถ้าเป็นฟาร์มจริงต้องเปลี่ยนอะไร {{f:s3.hist.farm_change|30}}

> เพราะช่วงนั้นแล็ปท็อปที่ใช้ **รับและบันทึกข้อมูล** ถูกปิดหรือนำออกจากห้องไป แม้บอร์ดยังอ่านค่าอยู่ ก็ไม่มี Home Assistant คอยบันทึกไว้ หากต้องการเก็บข้อมูลต่อเนื่องที่ฟาร์ม จึงต้องมีเครื่องที่เปิดทำงานได้ตลอด ดูตัวเลือกได้ในหัวข้อ **นำไปใช้ที่ฟาร์มอย่างไร** ท้ายหน้านี้

## กิจกรรมที่ 7 — สร้างหน้าจอติดตามและควบคุมฟาร์ม (Dashboard)

### สร้าง

1. **Settings → Dashboards → + Add dashboard → New dashboard from scratch** ตั้งชื่อตามฟาร์ม เช่น `แปลง 1`
2. เปิดแดชบอร์ดใหม่จากเมนูด้านซ้าย กดไอคอนดินสอ แล้วเพิ่มการ์ดตามแผน
3. **Gauge** ของความชื้นอากาศ ตั้ง **Severity** ให้สีเปลี่ยนตามเกณฑ์เปิดและเกณฑ์ปิดปั๊มของทีม เพื่อให้คนที่ไม่รู้ตัวเลขเกณฑ์ก็อ่านออก
4. **History graph** ตั้ง Hours to show เป็น 24 จะเห็นข้อมูลที่เพิ่งอ่านไปอยู่ในนั้น
5. **Tile** ของสวิตช์ลูกลอย ตั้งชื่อให้คนอ่านเข้าใจ เช่น `น้ำในถัง` และเปลี่ยนไอคอน

## กิจกรรมที่ 8 — ออกแบบระบบสำหรับฟาร์ม (Design)

**45 นาที**

**อุปกรณ์ที่ใช้** แบบร่างระบบท้าย[ใบบันทึกของทีม](record-sheet.md) ใบราคาอุปกรณ์ที่แจก โทรศัพท์สำหรับค้นราคา

> **ตกลงกันก่อนว่าใครเป็นคนเขียนลงแบบร่าง**

เลือกสถานการณ์จากบัตรหนึ่งใบ หรือใช้ฟาร์มของสมาชิกในทีม แล้วจัดทำแบบร่างระบบหนึ่งหน้า แบ่งเวลาเป็น **ออกแบบ 30 นาที · แลกเปลี่ยนกับทีมที่จับคู่กัน 5 นาที · นำเสนอตัวอย่างหน้าห้อง 10 นาที**

| บัตร | สถานการณ์ |
|------|-----------|
| **A โรงเรือนผัก** | โรงเรือน 6 × 20 เมตร ใกล้บ้าน มีไฟบ้านและ WiFi ถึง ปลูกผักสลัด ปัญหาคือร้อนจัดช่วงบ่ายและรดน้ำไม่สม่ำเสมอเมื่อเจ้าของไม่อยู่ |

| **C ไฮโดรโปนิกส์** | โต๊ะปลูก 8 โต๊ะในโรงเรือน ต้องเฝ้าระดับน้ำ อุณหภูมิน้ำ และค่า EC/pH ปั๊มหมุนเวียนจะหยุดนานเกิน 30 นาทีไม่ได้ |

| **E ฟาร์มของเราเอง** | หากมีสมาชิกทำฟาร์มและมีข้อมูลพื้นที่ชัดเจน ให้ใช้ฟาร์มนั้นเป็นโจทย์แทนบัตรได้ เริ่มจากปัญหาที่เขียนไว้ตอนเริ่มช่วงที่ 1 ต้องบอกได้ว่า ขนาดพื้นที่ ระยะจากบ้าน มีไฟบ้านหรือไม่ สัญญาณมือถือเป็นอย่างไร และตอนนี้แก้ปัญหานั้นอย่างไร |

### นำเสนอ

1. **กับทีมที่จับคู่กัน** (ทีมเดียวกับรอบจำลองปัญหา) ทีมละ 1 นาที แล้วสลับ ทีมที่ฟังตอบสองข้อ: การตัดสินใจไหนมีเหตุผลชัดที่สุด และชิ้นใดที่ยังตอบไม่ได้ว่าถ้าเสียแล้วจะเกิดอะไรขึ้น
2. **หน้าห้อง** ผู้สอนเลือกสามถึงสี่ทีมที่ทีมที่จับคู่กันเสนอชื่อ ทีมละ 1 นาที ทุกทีมจะได้แลกเปลี่ยนกับทีมที่จับคู่กัน ส่วนการนำเสนอหน้าห้องใช้ยกตัวอย่างแนวคิดที่น่าสนใจร่วมกัน

### เกณฑ์ประเมินแบบร่าง

- เลือกเซนเซอร์และอุปกรณ์ที่รับคำสั่งไปทำงาน (actuator) โดยอ้างอิงสเปก และมี **ราคาจริง** ระบุว่าแอนะล็อกหรือดิจิทัล
- วิธีสื่อสารและแหล่งพลังงานเลือกโดยพิจารณาปัจจัยทั้งสี่ ไม่ใช่ "ใช้ WiFi เพราะในห้องอบรมใช้ WiFi"
- มี **fail-safe อย่างน้อยหนึ่งข้อ** และมี manual override ระบุว่าอยู่ที่ซอฟต์แวร์ บอร์ด หรือสายไฟตรง
- ระบุคนดูแลและความถี่
- งบประมาณรวมเหมาะสมกับขนาดและกำลังลงทุนของฟาร์ม

แบบร่างอยู่ท้าย[ใบบันทึกของทีม](record-sheet.md) กรอกในหน้านั้นได้เลย

## สรุปทั้งหลักสูตร

ทบทวนหน้าที่ของ **ส่วนรับข้อมูล (Input) ส่วนตัดสินใจ (Logic) และส่วนที่ทำงานตามคำสั่ง (Output)** โดยเชื่อมโยงกับกิจกรรมทั้งสามช่วง

1. **เลือกการสื่อสารและพลังงานให้เหมาะกับพื้นที่** จากระยะทาง พลังงาน ปริมาณข้อมูล และค่าใช้จ่าย
2. **ระบบที่ควบคุมภายในฟาร์มยังทำงานได้เมื่ออินเทอร์เน็ตขัดข้อง** การใช้คลาวด์ช่วยให้ดูข้อมูลจากระยะไกลได้ โดยระบบควบคุมหลักยังอยู่ที่ฟาร์ม
3. **charge controller ก็เป็นระบบ Input → Logic → Output** วัดแรงดัน ตัดสินใจ แล้วจ่ายหรือตัดไฟ และก็เห็นเฉพาะสิ่งที่วัดได้เช่นกัน
4. **ออกแบบแดชบอร์ดตามความต้องการของผู้ใช้** สิ่งสำคัญที่สุดอยู่บนสุด อ่านได้โดยไม่ต้องรู้ตัวเลข
5. **แบบร่างระบบต้องมีราคาและเหตุผล** ระบุเหตุผลที่เลือกอุปกรณ์แต่ละชิ้น ค่าใช้จ่าย และผลกระทบหากอุปกรณ์ขัดข้อง

## นำไปใช้ที่ฟาร์มอย่างไร

ซอฟต์แวร์ที่เราใช้เป็นโอเพนซอร์สทั้งหมด และอุปกรณ์หาซื้อได้จากร้านค้าออนไลน์ในไทย Home Assistant ก็ติดตั้งไว้บนแล็ปท็อปของเราแล้ว

| สิ่งที่ต้องมี | ตัวเลือกที่แนะนำ |
|---------------|------------------|
| เครื่องสำหรับเปิด Home Assistant ตลอดเวลา | Raspberry Pi 4/5 หรือ Home Assistant Green หรือคอมพิวเตอร์เก่าหนึ่งเครื่องที่เปิดทิ้งไว้ได้ ควรเลือกเครื่องที่เปิดทำงานต่อเนื่องได้และไม่ถูกปิดหรือนำไปใช้งานที่อื่น |
| บอร์ดเซนเซอร์ | GoGo-IoT หรือ ESP32 ทั่วไป + เซนเซอร์อุณหภูมิความชื้น + เซนเซอร์ความชื้นดินแบบ capacitive + สวิตช์ลูกลอย |
| บอร์ดรีเลย์ | โมดูลรีเลย์ ESP32 สำเร็จรูป (ค้นคำว่า ESP32 relay board) |
| ปั๊มและไฟ | ปั๊มจุ่ม 12V + อะแดปเตอร์ 12V 2A |
| พลังงานสำหรับพื้นที่ไม่มีไฟฟ้า | แผงโซลาร์เซลล์ 12V + charge controller PWM + แบตเตอรี่ 12V ขนาดคิดจากจำนวนชั่วโมงที่ระบบต้องอยู่ได้โดยไม่มีแดด |

![QR code ไปยังคู่มือติดตั้ง Home Assistant ที่บ้าน](images/placeholder.png){ width="25%" }

*สแกนเพื่อดูคู่มือติดตั้ง Home Assistant บนเครื่องของเราเอง*

**แหล่งเรียนรู้** home-assistant.io · esphome.io ซึ่งมีตัวอย่างไฟล์ตั้งค่าสำหรับเซนเซอร์แทบทุกตัวที่ขายในท้องตลาด · ไฟล์ตั้งค่าของบอร์ดทั้งสองในหลักสูตรนี้ ผู้สอนจะแจกในกลุ่ม

**หัวข้อที่ศึกษาเพิ่มเติมได้หลังการอบรม**

- เขียนไฟล์ตั้งค่า ESPHome เองตั้งแต่ต้น และแฟลชบอร์ดผ่านเบราว์เซอร์
- fail-safe ในตัวบอร์ดที่ยังทำงานได้แม้ Home Assistant หยุดทำงาน (เชื่อมโยงกับคำถามท้ายกิจกรรมที่ 6)
- MQTT broker ของเราเอง สำหรับเชื่อมอุปกรณ์หลายยี่ห้อ
- ทดลองใช้ LoRa สำหรับแปลงที่ WiFi ไปไม่ถึง
- แบตเตอรี่จริงบน charge controller และการคำนวณขนาดแผงกับแบตเตอรี่
