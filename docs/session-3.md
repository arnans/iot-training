# ช่วงที่ 3 — โครงสร้างระบบ IoT: การสื่อสาร คลาวด์ แดชบอร์ด และการออกแบบระบบ

**เปิดกล่อง แล้วออกแบบของเราเอง**

สองช่วงที่ผ่านมาบอร์ดกับ Home Assistant คุยกันโดยเราไม่ต้องรู้ว่าอย่างไร และทุกอย่างเสียบไฟบ้าน ช่วงนี้เราเปิดกล่องทั้งสองใบ คือเครือข่ายและพลังงาน แล้วปิดท้ายด้วยการออกแบบระบบสำหรับฟาร์มหนึ่งแห่งตั้งแต่เซนเซอร์ถึงงบประมาณ

> **เมื่อจบช่วงนี้** เราจะมีแดชบอร์ดที่คนอื่นใช้ได้ ดูข้อมูลจากนอกฟาร์มได้ รู้ว่าโหนดนอกฟาร์มเอาไฟจากไหน และมีแบบร่างระบบของเราเองหนึ่งชุด

## เปิดกล่อง: เครือข่าย

**30 นาที บรรยาย** · ดูไฟล์ตั้งค่า ESPHome ที่แจก คราวนี้ดูส่วนบน

![ไฟล์ YAML ของ ESPHome ส่วน esphome, wifi และ api เน้น name_add_mac_suffix, ssid และ encryption key](images/placeholder.png){ width="55%" }

หาสามอย่างจากไฟล์: **ssid** ที่บอร์ดต่อ · บรรทัด **name_add_mac_suffix** ที่ทำให้บอร์ดตั้งชื่อตัวเองไม่ซ้ำกัน · บรรทัด **api** ที่บอกว่าบอร์ดคุยกับ Home Assistant ด้วยวิธีไหน และเข้ารหัสหรือไม่ บอร์ด GoGo-IoT และบอร์ดรีเลย์มีส่วนนี้เหมือนกันทั้งคู่

> สังเกตว่าไฟล์นี้ **ไม่มีหมายเลข IP อยู่เลย** บอร์ดขอ IP จากเราเตอร์เอง แล้วประกาศชื่อตัวเองในเครือข่าย Home Assistant จึงตามหาเจอด้วยชื่อ ไม่ต้องรู้ IP นี่คือเหตุผลที่เราพิมพ์ `.local` ตอนเพิ่มบอร์ด

จากนั้นไปที่ **Settings → Devices & services → ESPHome** กดที่อุปกรณ์ จะเห็น entity ชื่อ **หมายเลข IP** บอกว่าเราเตอร์ให้ IP อะไรกับบอร์ดตัวนี้ ลองเทียบกับของทีมข้าง ๆ

> ในช่วงที่ 2 ตอนผู้สอนปิดเราเตอร์ WiFi สิ่งที่หายไปคือเส้นทางระหว่างกล่องสามใบนี้เอง

### แกนตัดสินใจสี่แกน

เลือกวิธีสื่อสารจากสี่แกน: **ระยะทาง · การใช้พลังงาน · ปริมาณข้อมูล · ค่าใช้จ่าย** ไม่มีคำตอบเดียวสำหรับทุกฟาร์ม

> **จดลงใบบันทึก** ตารางเปรียบเทียบ WiFi · ESP-NOW · LoRa/LoRaWAN · Cellular/NB-IoT · RS-485 ตามสี่แกนนี้ และเหมาะกับฟาร์มแบบไหน

### โปรโตคอล

| โปรโตคอล | หลักการ |
|----------|---------|
| **ESPHome native API** (ที่เราใช้) | บอร์ดคุยกับ Home Assistant โดยตรงในเครือข่ายเดียวกัน รับได้มากกว่าหนึ่งเครื่องพร้อมกัน นี่คือเหตุที่เครื่องกลางของผู้สอนอ่านบอร์ดของเราได้ไปพร้อมกับแล็ปท็อปของเรา |
| **MQTT** | อุปกรณ์ publish ข้อความไปที่ broker ใครสนใจก็ subscribe หัวข้อนั้น |
| **HTTP** | อุปกรณ์ยิงข้อมูลไปที่ URL ปลายทางเป็นครั้ง ๆ |

### Local-first กับ cloud

ตอบตารางนี้กับระบบของเรา เทียบกับระบบที่ Logic อยู่บนคลาวด์ เมื่ออินเทอร์เน็ตดับ

- automation รดน้ำยังทำงานหรือไม่
- ดูแดชบอร์ดจากในฟาร์มได้หรือไม่ · จากในเมืองได้หรือไม่
- ข้อมูลย้อนหลังยังถูกบันทึกหรือไม่

> ระบบของเราขาดอย่างเดียวคือการเข้าถึงจากนอกฟาร์ม เราจะเติมส่วนนั้นในกิจกรรมที่ 5

## เปิดกล่อง: พลังงาน

**20 นาที** · กล่องจ่ายไฟที่ต่ออยู่แล้วตั้งแต่ช่วงที่ 1, แผงโซลาร์เซลล์ 12V 15W, สายไฟ

> **สลับบทบาทก่อนเริ่ม**

พลังงานเป็นหนึ่งในสี่แกน โหนดที่อยู่กลางแปลงไม่มีปลั๊กให้เสียบ ระบบโซลาร์ขนาดเล็กประกอบด้วยสามส่วน คือ **แผง** ผลิตไฟ **แบตเตอรี่** เก็บไฟ และ **ตัวควบคุมการชาร์จ** อยู่ตรงกลางคอยดูแลไม่ให้แบตเตอรี่ชาร์จเกินหรือหมดเกิน แล้วจ่ายไฟให้โหลด

"กล่องจ่ายไฟ" ที่เลี้ยงบอร์ดรีเลย์และปั๊มของเรามาสองช่วง และเลี้ยงบอร์ดเซนเซอร์ตอนที่เราไม่อยู่ คือตัวควบคุมการชาร์จตัวนี้เอง เราใช้ **adapter 12V แทนแบตเตอรี่** มาตลอด วันนี้เปิดดูว่าข้างในทำอะไร แล้วเติมส่วนที่ขาดไป คือแผง

![ตัวควบคุมการชาร์จ PWM ด้านหน้า: จอ LCD สามปุ่ม ช่อง USB สองช่อง และขั้วต่อหกขั้วด้านล่าง แบ่งเป็นสามคู่ พร้อมป้าย แผง แบตเตอรี่ โหลด สองคู่หลังมีสายต่ออยู่แล้ว](images/placeholder.png){ width="55%" }

### อ่านกล่อง

ขั้วต่อด้านล่างมีสามคู่ จากซ้ายไปขวา คือ **แผงโซลาร์เซลล์** (สัญลักษณ์แผง) **แบตเตอรี่** (สัญลักษณ์แบตเตอรี่) และ **โหลด DC** (สัญลักษณ์หลอดไฟ) ไล่สายที่ต่ออยู่แล้วให้ครบ

- คู่กลาง: adapter ของเรา ทำหน้าที่แบตเตอรี่
- คู่ขวา: ไปแผงต่อสาย แล้วแยกไปบอร์ดรีเลย์และปั๊ม นี่คือโหลดของระบบ
- ช่อง USB: โหลดอีกทางหนึ่ง บอร์ด GoGo-IoT ใช้อยู่ตั้งแต่จบช่วงที่ 1
- คู่ซ้าย: ว่าง ระบบของเรายังไม่เคยผลิตไฟเองเลย

สังเกตว่าทุกอย่างของทีมเราเดินด้วยกล่องนี้กล่องเดียวมาตั้งแต่เมื่อคืน ยกเว้นแล็ปท็อป

จอแสดงแรงดันของ "แบตเตอรี่" และไอคอนต่าง ๆ อ่านค่าแรงดันและดูไอคอนแบตเตอรี่ว่าบอกเต็มหรือไม่

> จอจะแสดงราว 12 V และไอคอนแบตเตอรี่ **ไม่เต็ม** ทั้งที่ adapter จ่ายไฟได้ไม่จำกัด เพราะแบตเตอรี่ตะกั่วกรดที่เต็มจริงอยู่ที่ 12.7–13.0 V ตัวควบคุมรู้จักแบตเตอรี่จากแรงดันเท่านั้น มันไม่รู้ว่าข้างหลังคือ adapter นี่คือข้อจำกัดของ Input ทุกชนิด: เห็นเฉพาะสิ่งที่วัดได้

### ตั้งชนิดแบตเตอรี่

กดปุ่มเมนู 5 ครั้ง แล้วกดค้าง 10 วินาที จอจะแสดง `b01` ใช้ปุ่ม + และ − ดูตัวเลือก: `b01` ตะกั่วกรด · `b02` ลิเธียมไอออน · `b03` ลิเธียมไอรอนฟอสเฟต (LiFePO4) แล้วกลับมาที่ `b01`

> ตัวควบคุมตัดโหลดเมื่อแบตเตอรี่ต่ำ และหยุดชาร์จเมื่อเต็ม แต่ "ต่ำ" กับ "เต็ม" ของแบตเตอรี่แต่ละชนิดเป็นแรงดันคนละค่า ตั้งผิดชนิด แบตเตอรี่จะเสียเร็วหรือถูกตัดก่อนเวลา ถ้าใช้ถ่าน 18650 แบบเดียวกับที่อยู่ในบอร์ด GoGo-IoT ต่ออนุกรมเป็นแบตเตอรี่จริง ต้องเลือก `b02`

### ต่อแผง

ลำดับสำคัญ ตัวควบคุมต้องรู้แรงดันระบบจากแบตเตอรี่ก่อนจึงจะรับไฟจากแผงได้ถูกต้อง ของเราต่อแบตเตอรี่ (adapter) ไว้แล้ว จึงต่อแผงได้เลย

1. Hardware ต่อสายจากแผงเข้า **คู่ซ้าย** (สัญลักษณ์แผง) บวกเข้าบวก ลบเข้าลบ ห้ามให้ปลายสายสองเส้นแตะกัน
2. ดูไอคอนแผงและกระแสชาร์จบนจอ ในห้องจะได้เกือบศูนย์
3. ยกแผงไปใกล้หน้าต่างหรือโคมไฟ แล้วดูตัวเลขอีกครั้ง
4. ขณะแผงยังต่ออยู่ **ถอดปลั๊ก adapter ออกจากรางปลั๊ก 10 วินาที** ดูว่าจอดับ บอร์ดดับ หรือยังติด แล้วเสียบกลับ ในฟาร์มจริง ช่วง 10 วินาทีนั้นคือกลางคืนที่ไม่มีแบตเตอรี่ แผงอย่างเดียวเลี้ยงระบบไม่ได้

![ระบบครบสามส่วน: แผงต่อคู่ซ้าย adapter ต่อคู่กลาง แผงต่อสายและบอร์ดรีเลย์ต่อคู่ขวา บอร์ด GoGo-IoT ต่อช่อง USB](images/placeholder.png){ width="60%" }

**ถอดกลับด้านเสมอ** เมื่อเลิกใช้ระบบตอนท้ายวัน: โหลดก่อน แผงต่อมา แบตเตอรี่ท้ายสุด

> **จดลงใบบันทึก** แรงดันที่จอแสดง · ไอคอนแบตเตอรี่บอกว่าเต็มหรือไม่ · กระแสจากแผงในห้องและใกล้แสง · เกิดอะไรขึ้นตอนถอด adapter 10 วินาที

> **ถ้าบอร์ด GoGo-IoT ดับตอนถอด adapter** ค่าบนแดชบอร์ดจะเป็น unavailable และ fail-safe เซนเซอร์หายจากช่วงที่ 2 จะสั่งปิดปั๊ม ถ้าทีมสร้างไว้ นี่คือ fail-safe ทำงานจริงโดยไม่ได้นัดหมาย

**ความปลอดภัย** ห้ามให้สายบวกและลบของแผงแตะกัน แผงที่โดนแดดจ่ายกระแสตลอดเวลาแม้ไม่ได้ต่ออะไร และห้ามต่อแผงเข้าตัวควบคุมที่ยังไม่มีแบตเตอรี่

**คำถามของ Recorder** โหนดในสถานการณ์ D (แปลงห่างไกล) ใช้ระบบแบบนี้ ถ้าฟ้าครึ้มติดกันสามวัน โหนดจะดับเมื่อไร ต้องรู้ตัวเลขอะไรบ้างสามอย่างจึงจะตอบได้

## กิจกรรมที่ 5 — Dashboard

**50 นาที** · ระบบทั้งหมด และโทรศัพท์ 1–2 เครื่อง

> **สลับบทบาทก่อนเริ่ม**

สร้างแดชบอร์ดที่คนที่ไม่ได้อยู่ในห้องนี้เปิดแล้วเข้าใจทันทีว่าฟาร์มเป็นอย่างไรและกดอะไรได้

### ออกแบบก่อนสร้าง

เลือกผู้ใช้หนึ่งคน: **เจ้าของฟาร์มที่ดูจากโทรศัพท์ในเมือง** หรือ **คนงานหน้าแปลงที่ใช้แท็บเล็ต** หรือ **ผู้จัดการที่ดูหลายแปลงบนจอใหญ่**

> **จดลงใบบันทึก** ผู้ใช้ต้องรู้หรือทำอะไรบ้าง แต่ละอย่างใช้ card แบบไหน entity ตัวไหน และอยู่ตำแหน่งไหนบนจอ

ควรมีอย่างน้อยห้าอย่าง: ค่าปัจจุบันที่สำคัญที่สุด (Gauge) · แนวโน้ม 24 ชั่วโมง (History graph) · สถานะน้ำในถังจากสวิตช์ลูกลอย · ปุ่มควบคุม (Tile) · สถานะ automation

### สร้าง

1. **Settings → Dashboards → + Add dashboard → New dashboard from scratch** ตั้งชื่อตามฟาร์ม เช่น `แปลง 1`
2. เปิดแดชบอร์ดใหม่จากเมนูซ้าย กดดินสอ แล้วเพิ่ม card ตามแผน
3. **Gauge** ของความชื้นอากาศ ตั้ง **Severity** ให้สีเปลี่ยนตามค่าเปิดและค่าปิดปั๊มของทีม เพื่อให้คนที่ไม่รู้ตัวเลขก็อ่านได้
4. **History graph** ตั้ง Hours to show เป็น 24
5. **Tile** ของสวิตช์ลูกลอย ตั้งชื่อให้คนอ่านเข้าใจ เช่น `น้ำในถัง` และเปลี่ยนไอคอน
6. **Tile** ของสวิตช์ปั๊ม และ **Entities** ของ automation ทุกข้อ กดที่ชื่อ automation ดูว่ามี **Last triggered** หรือไม่
7. ย้าย card ให้สิ่งสำคัญที่สุดอยู่บนสุด กด **Done**

![แดชบอร์ดสำหรับเจ้าของฟาร์ม: เกจความชื้นอากาศสีเขียวบนสุด Tile น้ำในถัง กราฟ 24 ชั่วโมง ปุ่มปั๊ม และรายการ automation](images/placeholder.png){ width="60%" }

**ทดสอบกับคนจริง** สมาชิกเปิดแดชบอร์ดใหม่บนโทรศัพท์ โดย Driver ไม่บอกอะไร เขาบอกได้ทันทีหรือไม่ว่าอากาศแห้งหรือชื้น น้ำในถังพอหรือไม่ และหาปุ่มปั๊มเจอในกี่วินาที

- [ ] **ผู้สอนตรวจแล้ว** แดชบอร์ดมีกราฟ ปุ่มควบคุม สถานะน้ำ และสถานะ automation ครบ และใช้งานได้บนโทรศัพท์

### ส่งข้อมูลขึ้นคลาวด์

ตอนนี้แดชบอร์ดดูได้เฉพาะจาก WiFi ห้องอบรม ผู้สอนจะพาทำขั้นตอนบนจอเพื่อส่งค่าของทีมไปยังบริการคลาวด์

> **จดลงใบบันทึก** เครื่องมือคลาวด์ที่ใช้ · ที่อยู่สำหรับดูข้อมูลของทีม · ส่งค่าอะไรขึ้นไปบ้าง ทุกกี่วินาที · ส่วนที่ส่งข้อมูลอยู่ที่บอร์ดหรือที่ Home Assistant

**ทดสอบจากระยะไกล** สมาชิกคนหนึ่ง **ปิด WiFi บนโทรศัพท์** ใช้อินเทอร์เน็ตมือถือ แล้วเปิดที่อยู่คลาวด์ของทีม เห็นค่าหรือไม่ ค่าล่าสุดเมื่อกี่วินาทีที่แล้ว และสั่งปั๊มจากที่นั่นได้หรือไม่

**คำถามของ Recorder** ถ้าอินเทอร์เน็ตของสถานที่จัดอบรมดับตอนนี้ แดชบอร์ดบนคลาวด์กับแดชบอร์ดใน Home Assistant ของทีมจะเป็นอย่างไร และปั๊มยังรดน้ำเองหรือไม่

## กิจกรรมที่ 6 — Design

**45 นาที** · ใบบันทึกหน้าผืนออกแบบ ใบราคาอุปกรณ์ที่แจก โทรศัพท์สำหรับค้นราคา

> **สลับบทบาทก่อนเริ่ม** รอบนี้ Recorder เป็นคนเขียนลงผืนออกแบบ

ทีมจับบัตรสถานการณ์หนึ่งใบ แล้วออกแบบระบบให้ครบหนึ่งหน้า จากนั้นนำเสนอ **1 นาที**

| บัตร | สถานการณ์ |
|------|-----------|
| **A โรงเรือนผัก** | โรงเรือน 6 × 20 เมตร ใกล้บ้าน มีไฟบ้านและ WiFi ถึง ปลูกผักสลัด ปัญหาคือร้อนจัดช่วงบ่ายและรดน้ำไม่สม่ำเสมอเมื่อเจ้าของไม่อยู่ |
| **B สวนผลไม้ 10 ไร่** | ลำไยหรือมะม่วง แปลงยาว 400 เมตรจากบ้าน มีไฟที่หัวแปลง ต้องการรู้ความชื้นดิน 3–4 จุดกระจายทั่วสวน และสั่งวาล์วน้ำหยดเป็นโซน |
| **C ไฮโดรโปนิกส์** | โต๊ะปลูก 8 โต๊ะในโรงเรือน ต้องเฝ้าระดับน้ำ อุณหภูมิน้ำ และค่า EC/pH ปั๊มหมุนเวียนหยุดไม่ได้นานเกิน 30 นาที |
| **D แปลงห่างไกล ไม่มีไฟ** | ข้าวโพดหรือมันสำปะหลัง 20 ไร่ ห่างบ้าน 3 กิโลเมตร ไม่มีไฟบ้าน สัญญาณมือถืออ่อน ต้องการรู้ความชื้นดินและระดับน้ำในบ่อ และสั่งปั๊มโซลาร์ |

### เกณฑ์ที่ผู้สอนใช้ดู

- เซนเซอร์และ actuator ทุกชิ้นมีเหตุผลจากสเปก และมี **ราคาจริง** ระบุว่าแอนะล็อกหรือดิจิทัล
- วิธีสื่อสารและแหล่งพลังงานเลือกจากแกนทั้งสี่ ไม่ใช่ "ใช้ WiFi เพราะเราใช้ในห้อง"
- มี **fail-safe อย่างน้อยหนึ่งข้อ** และมี manual override ระบุว่าอยู่ที่ซอฟต์แวร์ บอร์ด หรือสายไฟตรง
- ระบุคนดูแลและความถี่
- งบรวมเป็นตัวเลขที่ฟาร์มแบบนั้นจ่ายจริงได้

ผืนออกแบบอยู่ใน [ใบบันทึก](record-sheet.md) หน้าสุดท้าย

## สรุปทั้งหลักสูตร

**กล่องสามใบข้ามสามช่วง** ทบทวนว่าเราเรียนอะไรเกี่ยวกับ Input, Logic และ Output ในแต่ละช่วง

1. **การสื่อสารและพลังงานคือการตัดสินใจ** จากระยะทาง พลังงาน ปริมาณข้อมูล และค่าใช้จ่าย
2. **local-first ทำงานต่อได้เมื่ออินเทอร์เน็ตดับ** คลาวด์เพิ่มการเข้าถึงจากระยะไกล ไม่ใช่ตัวแทนของ Logic ในฟาร์ม
3. **ตัวควบคุมการชาร์จก็เป็นระบบ Input → Logic → Output** วัดแรงดัน ตัดสินใจ แล้วจ่ายหรือตัดไฟ และมันก็เห็นเฉพาะสิ่งที่วัดได้
4. **แดชบอร์ดออกแบบจากผู้ใช้** สิ่งสำคัญที่สุดอยู่บนสุด อ่านได้โดยไม่ต้องรู้ตัวเลข
5. **แบบร่างระบบต้องมีราคาและเหตุผล** ทุกชิ้นตอบได้ว่าทำไมชิ้นนี้ ทำไมราคานี้ และเสียแล้วเกิดอะไร

## ไปต่ออย่างไร

ซอฟต์แวร์ที่เราใช้เปิดทั้งหมด และอุปกรณ์หาซื้อได้จากร้านค้าออนไลน์ไทย Home Assistant ก็ติดตั้งไว้บนแล็ปท็อปของเราแล้ว

| สิ่งที่ต้องมี | ตัวเลือกที่แนะนำ |
|---------------|------------------|
| เครื่องรัน Home Assistant ถาวร | Raspberry Pi 4/5 หรือ Home Assistant Green หรือคอมพิวเตอร์เก่าหนึ่งเครื่องที่เปิดทิ้งไว้ได้ แล็ปท็อปใช้เรียนได้ แต่ฟาร์มต้องการเครื่องที่ไม่ปิดฝา |
| บอร์ดเซนเซอร์ | GoGo-IoT หรือ ESP32 ทั่วไป + เซนเซอร์อุณหภูมิความชื้น + เซนเซอร์ความชื้นดินแบบ capacitive + สวิตช์ลูกลอย |
| บอร์ดรีเลย์ | โมดูลรีเลย์ ESP32 สำเร็จรูป (ค้นคำว่า ESP32 relay board) |
| ปั๊มและไฟ | ปั๊มจุ่ม 12V + adapter 12V 2A |
| พลังงานนอกฟาร์ม | แผงโซลาร์เซลล์ 12V + ตัวควบคุมการชาร์จ PWM + แบตเตอรี่ 12V ขนาดตามชั่วโมงที่ต้องอยู่ได้โดยไม่มีแดด |

![QR code ไปยังคู่มือติดตั้ง Home Assistant ที่บ้าน](images/placeholder.png){ width="25%" }

*สแกนเพื่อดูคู่มือติดตั้ง Home Assistant บนเครื่องของเราเอง*

**แหล่งเรียนรู้** home-assistant.io · esphome.io ซึ่งมีตัวอย่างไฟล์ตั้งค่าสำหรับเซนเซอร์แทบทุกตัวที่ขายในท้องตลาด · ไฟล์ตั้งค่าของบอร์ดทั้งสองในหลักสูตรนี้ ผู้สอนจะแจกในกลุ่ม

**สิ่งที่ยังไม่ได้ทำในหลักสูตรนี้ แต่ควรรู้ว่ามี**

- เขียนไฟล์ตั้งค่า ESPHome เองตั้งแต่ต้น และแฟลชบอร์ดผ่านเบราว์เซอร์
- fail-safe ในตัวบอร์ด ที่ทำงานแม้ Home Assistant ดับ (คำตอบของคำถาม Recorder ในกิจกรรมที่ 4)
- MQTT broker ของเราเอง สำหรับเชื่อมอุปกรณ์หลายยี่ห้อ
- LoRa จริง สำหรับแปลงที่ WiFi ไปไม่ถึง
- แบตเตอรี่จริงบนตัวควบคุมการชาร์จ และการคำนวณขนาดแผงกับแบตเตอรี่
